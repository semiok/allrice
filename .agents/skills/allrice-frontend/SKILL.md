# AllRice 前端开发规范

## 0. 什么时候用

任何改动用户可见界面的 PR 都使用本规范，包括插件页面。开工时读取，用 [checklist.md](checklist.md) 交回执。维护人打野3，归属 MET-214，各线共用。

本规范整理 MET-214 评论 `3538851e`，标准宽度 **1440、390 CSS px**、组件预览页方向和维护归属已获用户确认。权限、风险档位、复核、测试及发布以最新版 [AGENTS.md](../../../AGENTS.md) 为准。用户最新决定优先；冲突和依据不清的部分列在 PR“风险”，不自行定成全站规则。

## 1. 开工前固定设计基准

- 按 AGENTS.md 第0节，用户本人确认预览后，才能写对应产品界面代码。复用已确认稿时，记录版本、确认出处和文件 SHA256；需求超出原稿的部分重新给用户看。删除用户可见元素同样核对授权，不从草稿推导“纯删除免确认”。
- 同一界面由一条线负责设计；查文件和任务卡，先协调重叠，按共同基准交接。
- 用当前代码的真实组件做可打开、可点击的页面，标出代码 SHA、数据来源、版本和差异。提供页面地址，不把 HTML 源码或图片当成可交互页面。截图只用于留证。
- 用已授权真实样本或脱敏夹具，保留最长标题、摘要、文件名及多行正文。不编造线上事实，不擅自发真实 Run。
- 在产品适用范围内列出正常、空、加载/生成、错误、无权限、长文本及展开/折叠状态；覆盖1440/390 × 亮/暗。不存在的状态注明不适用及原因，不新增业务状态凑矩阵。
- 组件预览页已同意另做；交付前使用现有夹具和临时预览，记录实际入口，不声称已有全量组件目录。

## 2. 组件、样式与 DSH 边界

查组件导出、调用方和原生实现，按 AGENTS.md 写 DSH 对照。提问、工作过程、技能、子智能体等 Agent 界面优先直接复用 DSH 原生组件、命名和交互；AllRice 聊天布局的自由度不代表可以改原生执行语义或另造状态机。

查找入口：`packages/ui/src/`、`apps/web/app/chatflow/dsh-upstream/`、`apps/web/app/dsh-upstream/`。发布包未导出的能力不要自行复制或深导入；核对既有批准例外、`apps/web/app/dsh-upstream/upstream.json`、`pnpm dsh-ui:verify` 和 MET-225。必要的源码同步/例外先走现有批准与登记流程，不能把历史拷贝当成新增许可。

- 按钮、输入、下拉、搜索、焦点、文件行、标签、徽标、弹框、抽屉和外框先用已有共用组件及公开参数。找不到时先提出共用组件方案，不在页面另画一套。
- AllRice 新增颜色、字号、间距、圆角、阴影使用所属区域现有 token。查 `packages/ui/src/tokens.css`、DSH 的 `design-platform.css` 与 `ui-*-tokens.css`；管理页另遵守 [管理端设计规范](../../../docs/development/admin-design-system.md)。缺 token 先列缺口，不任意造数值或修改上游同步文件，不宣称旧硬编码已清零。
- 浮层及 portal 验证实际主题作用域：弹框、下拉、提示必须与所在区域一致；同时检查文字、边框、遮罩、焦点和禁用态。
- token 检查脚本尚待单独任务实现；目前靠代码检查和视觉证据，不能把脚本计划写成已通过的检查。

## 3. 布局与状态

标准宽度1440和390，检查中间断点；不缩放桌面截图冒充手机。保留管理端320px等已有覆盖。

开工前把标题/摘要行数、截断/换行、全文入口写入设计稿；长文件名、长单词和多项内容不能挤出边界或遮挡操作。全文入口支持触屏/键盘；不擅定全站截断行数。

状态来自接口/原生事件；加载位置统一，错误给出原因和现有下一步。状态切换不改变无关间距、滚动位置或焦点；检查早期加载→运行→结束、展开多项和历史重开，不只验静态成功态。

## 4. 文案

中文用日常表达，按钮说明动作，同一业务沿用全站已定叫法。非技术用户无需理解的工具名、内部提纲、ID、原始时区字段不直接充当用户说明；需要排障的细节保留在已有详情入口。管理页保留必要技术信息。

分隔符、数字单位、标点和空格按确认稿统一。不顺手改记忆规则、权限或业务事实；问题另交对应任务。

## 5. 交互与动效

复用原生焦点、键盘和关闭行为，检查 Tab、可见焦点、Esc、焦点恢复及 `prefers-reduced-motion`。减少动态效果时状态仍可读。

已批准的品牌面板滑出在 `apps/web/app/chatflow/brand-media/frontend-wiring.module.css` 使用 **240ms / cubic-bezier(0.2, 0.8, 0.2, 1)**（先快后慢）。它不是弹框或呼吸效果的全局参数。其他组件沿用原生参数/确认稿；全站范围和动效 token 待明确，不机械替换。

动效用连续帧或录屏核对节奏、图标与文字同步和布局稳定；静态截图不能证明“不跳”。截图比较需固定动画采样状态，不靠扩大容差掩盖变化。

## 6. 性能

首屏只加载必要内容；重预览/编辑面板沿用按需加载入口，不引入无谓请求或重复轮询。新增依赖列原因、替代项、构建体积增量；未测就注明，不编收益。核对长列表、历史恢复、面板开关后的请求和资源。

## 7. 自动验证

按 AGENTS.md 第10节定档，选受影响单测和完整页面浏览器测试，确认进入 CI 收集；不额外要求完整 M5。修复必须有能抓住原问题的行为回归，说明移除修复时哪个断言失败；不通过降低断言、加重试或扩大时限求绿。

几何先定义测量对象和预期值，例如文字可见边界、元素盒子、内边距分别量，不拿相同 CSS gap 冒充视觉等距。仓库多处几何比较使用 **±0.5 CSS px**，新同类比较沿用对应 helper/断言；原有严格零位移或更严保证继续保留，不批量放宽。

草稿的“软件渲染、零像素容差”尚未核定全局门禁/基线入口。记录浏览器版本、OS/字体、DPR、主题、数据、动画采样和工具。已有截图测试沿用锁定环境与断言；未执行的自动检查如实写明，人工对照不冒充自动门禁。不把跨平台字体差异当产品结论；全局参数和入口交规划线定，不编命令。

## 8. 设计还原检查

以同宽度/主题/数据/状态逐屏并排比较字号、图标基线、行距、边距、截断、圆角、颜色、按钮主次和过渡。执行/复核者须实际看图，不只读 CSS 或测试结果。

差异逐条写“位置—设计—实现—原因—处理”，修正或取得用户对具体差异的同意；没有差异也要注明“已逐屏比对”及证据位置。不靠改基准覆盖失败。规划线转交前再看，不像就退回；测试通过不替代视觉核对。

## 9. 合并前交付

提供一个可打开的对照页：左定稿、右实现，顶部差异清单；可切换1440/390、亮/暗和相关状态。标明设计版本、实现 SHA、未完成项和截图路径；按用户当前需求附动效证据。合并/部署是否可做只按当前授权和风险档位，不能把“设计确认”写成“批准上线”。

## 10. 部署后验收

按 AGENTS.md 的 Dev 验收要求，核对实际 Web/Worker 版本，在真实入口逐项执行需求清单并留截图；覆盖状态恢复、历史重开和关键交互，不只抽查成功页。真实 Run 仍需对应授权。记录通过、失败、未执行和原因；部署前填“待部署验收”，不能预勾。CI、冒烟、设计对照分别报告。

## 11. 验收回执

复制 [checklist.md](checklist.md) 到证据目录，填证据后打勾；不适用写理由，待做不勾。短回执链接清单。关闭自开实例/服务/进程、交还名额，写“资源已释放：……”。

## 12. 待后续工具任务

组件预览页、token/组件登记检查、页面测试覆盖检查、回执检查均另派，本次只有规范文档。脚本需区分批准例外、上游源码与 AllRice 样式；未就位前人工检查，不虚报自动拦截。落地后补入口，不复制 AGENTS.md。
