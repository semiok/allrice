# 成果与续办

## 一次复盘

按用户需要交付报告、关键图表、指标数表和复算脚本。结论紧邻证据，标明输入文件/版本、期间、单位、指标定义、异常和限制；行动表列出负责人、期限、预算、验证标准及尚未执行的状态。不同格式的数值来自同一次计算，显示舍入与原始精度可核对。

Word、Excel 和 PPT 沿用当前 `office` 的 load → change → save → reopen 流程；图表使用受管 Python 和现有中文字体。声明的输出必须真正生成并返回正式成果对象。检查负值、长标签、表格边界和可读性；结构校验通过不能冒充逐页视觉审查。以实际工具返回的成果对象 ID、checksum 和下载信息交付，不拼接虚构地址。

长类目优先使用横向柱形图，数值标签采用 `bar_label` 留白，负数标签不得压到类目文字；按当前 Office 的 `references/charts.md` 复用受管默认字体。Markdown 采用相对图片文件名并随附实际 PNG，说明同目录保存；不要把登录后才能访问的站内图片地址当作离线图片。

在原 Office 导出脚本中完成保存后重开及关键断言；后续只读核查使用 `workspace_document_read`。普通 Python 不保证包含 python-docx/python-pptx，不能因额外检查环境缺库而把已有正式成果判为生成失败。复核指标、预算、必要文件和展示后及时给出结果；仅因检查日志或措辞变化不应再制造一版文件。

## 追加变更

先确认本次变化：更正输入、调整目标/预算，还是修改展示。读取新上传源和上一版数表、脚本与需要修改的成果；不要重算无关任务，也不要覆盖原始输入。更正必须传播到所有受影响的汇总、比率、图表、结论和行动预算；保留项须按原断言复核。

对同一 Word 或 JSON/文本成果续办，`workspace.export.create` 的顶层 `parentObjectId` 使用确切上一版存储对象 ID，不能填版本 ID。输入仍指向实际授权的新来源；Office 修订的 `python.sourceObjectId` 使用实际上一版 Office 对象或准确源对象，遵守当前工具契约。`python.execute` 的 `outputs` 仅接受 path、fileName、format，不能加入 parentObjectId；重新生成的 PNG 是新的计算成果，报告中说明与旧图的对应关系，不声称它已经进入旧图的版本系列。若格式或成果系列不匹配，说明并交付新的系列。

等待工具确认真实新版本，核对父版本、来源、下载和本次更改，再说明新旧差异。失败时保留旧版并说明未交付，不把旧版下载、待执行计划或观察超时当成成功。
