# 版本交付与复核

调用 `workspace_project` 的 `deliver`，project 使用本次工具返回的完整版本，baseline 使用实际初始版本或上一版交付。不要自行拼造存储对象、成果 ID 或校验和。下面只演示引用结构，所有占位符必须由原始回执替换：

```json
{
  "action": "deliver",
  "project": {
    "projectId": "$PROJECT_ID",
    "snapshot": {
      "kind": "storage_object",
      "id": "$SNAPSHOT_ID",
      "checksum": "$SNAPSHOT_CHECKSUM"
    }
  },
  "baseline": {
    "projectId": "$PROJECT_ID",
    "snapshot": {
      "kind": "storage_object",
      "id": "$BASELINE_SNAPSHOT_ID",
      "checksum": "$BASELINE_SNAPSHOT_CHECKSUM"
    }
  }
}
```

`deliver` 返回的源码 ZIP 条目含 `sourcePackage`：`kind: source-only` 表示它只打包本次不可变项目快照中的文件，`project`、`sourceDigest` 和 `artifact` 绑定准确项目版本及 ZIP 的 objectId/versionId/checksum；`files` 是实际包内 path/sizeBytes/sha256 清单。执行目录里生成但未保存到该源码版本的文件不会自动进入本包。清单不是 README 内容正确或测试通过的证明。

交付前核对以下内容：

- 源码 ZIP、测试记录和差异来自同一项目版本；失败回执保留。交付工具生成下载文件不等于所有测试已经通过。
- 构建成果是实际执行生成并收集的文件。声明离线可用时，必须确实不依赖远端脚本、字体、接口或仅本地可见的绝对路径。
- README 说明用途、依赖、启动/测试/构建命令和限制。用户的数据默认留在输入与授权范围，不添加遥测或远端上传。
- 对每个 ZIP，逐项核对 README 和最终回复声称“已包含”的文件是否真在该包的准确清单中。明确区分本包已包含、运行构建命令后才生成、另一个确切交付物提供。脚本能恢复输入或生成成果，不等于原 ZIP 已经包含；不能把重跑后的目录清单当作已交付包清单。
- README 声称含生成文件而源码包清单缺少时，说明这个差异；在本次授权允许时保存正确说明的新版本，或选择已有且内容已核验的完整成果包。保留旧对象、说明和失败回执，不改写历史。其他工具生成的 ZIP 也需按它自己的准确包内容核对，不能借用源码包清单作证明。
- 按用户本次目标明确主交付与备选的用途，并使用各自原回执的准确对象/版本/校验值。完整成果包和需自行构建的源码包不能混称；不按文件名后缀、同名文件的创建时间或模型手写的“完整”选择主交付。
- 预览入口对应本次准确版本，访问和租期依据回执；普通用户从工作台打开，不能用管理员成功替代用户可用性。
- 数据工具保留原始字符串、前导零和异常行；明确格式与精度。浏览器展示输入采用安全文本，表格导出需考虑公式字符串，不能静默丢弃冲突数据。
- 第二版保留上一版源码和成果，说明本次修改、复用和新增验证；不要把旧测试、旧预览或旧报告冒称第二版结果。

最终回复用简短文字说明完成了什么、真实测试结果、主交付和备选各自包含什么、实际源码/成果链接和预览使用方式。存在未完成、失败或待确认项时明确列出，不能仅因为 Run 结束就宣布交付；链接有效不代表包内包含声明正确。复用同一字节的既有验证，不为说明或文件选择问题重跑已经通过的业务计算。
