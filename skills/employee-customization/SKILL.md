# 本人员工的 Workflow 维护

这是系统维护说明，不是业务 Workflow。用户需要开发、保存、更新或恢复可复用 Workflow 时，通过原生 Skill 按需加载。一次性工作照常完成；讨论、阅读文件或提供示例不等于保存授权。

## 开发完整包

- 只有创建者本人维护该员工实例的个人 Workflow；不能替另一员工、他人、部门或公司保存，也不把管理员身份当作读取私人包的资格。一个场景对应一个完整包，不叠加公司、部门、个人三层或另存共同要求。其他场景和不可变修订保留。
- 使用原生 `SKILL.md`：frontmatter 的 `name`、`description`、`whenToUse`、`metadata.displayName`、`metadata.version` 及正文按顺序的 `## 工作步骤`、`## 交付内容`、`## 执行细节`，具体格式以 `docs/development/workflow-skills.md` 为准。正文最多 262,144 UTF-8 bytes，超限拒绝、不截断；原始文件含 frontmatter 最多 8,000,000 bytes。资源最多 32 项，每项 128 KiB、合计 512 KiB，按需读取。
- 作者在本地目录编辑完整正文、资源及 `bundle.json`；受控资料用准确来源引用和可选 `sources.json` 保留来源。当前离线打包用 `scripts/workflow-skill-pack.mjs`，明确选择目标场景；它只生成完整 JSON，不保存、不发布、不执行脚本或安装依赖。checksum、作者版本和来源 URL 不授予权限，作者版本也不能代替服务端修订。

## 导入、更新与恢复确认

- 当前文件入口在本人员工详情的“本人 Workflow · 文件与修改记录”：选择完整 JSON，核对员工、场景、当前修订和正文、资源、来源、元数据差异，填写修改说明，再由本人点击“确认修改并生效”。只有准确服务端成功回执才表示已保存并生效，没有第二次发布、测试后启用或额外聊天确认步骤。
- 公开 GitHub／ZIP 来源已有服务端预览和确认合同；新的来源安装、更新界面是否可用以该环境实际发布为准，不能仅凭接口存在声称界面已经上线。预览固定所选来源及准确完整包，确认不得重新抓取并替换该输入。入口不可用时如实说明，不能改用通用 Skill 安装、旧文字方法、记忆、人设、资料或共享范围冒充保存。
- 修改文件后重新打包并预览，沿用目标场景和页面返回的准确当前内容地址。冲突后由本人重新核对，不自动覆盖；保存结果未知时沿用页面保留的原请求和参数回读同一次回执，不换 ID 重复创建。没有成功回执就说明保存结果尚未确认。
- 当前“修改记录”中的“预览恢复”按单场景展示准确历史包与当前差异，核对后由本人确认恢复；恢复追加新修订，不改写历史或其他场景。它不是旧文字整份方法恢复。来源已撤销的版本不能恢复，不能用复制字节、历史索引或换范围绕过。环境未提供该入口时，不编造替代工具。

## 原生加载、来源和结果

- 当前目录使用作者 `name`，通过原生 `skill` 或准确的 `/<name>` 调用；旧无作者字段包仍用 `/allrice-scene-<UUID>`。无需先选业务阶段。每次加载读取当前获准包；已加载正文保留在原生历史，可能被原生压缩，不因保存新版而改写。再次加载可读新版，不承诺整条对话或整个 Run 固定一个版本。
- 资源用本次加载返回的准确 `contentRef` 和相对路径调用已获权的 `workspace_skill_read`；没有该工具就如实说明，不能用新版代替旧包资源。长期资料引用必须来自当前受权读取的准确来源，临时附件和工作成果不自动成为长期资料。内容地址、hash、来源地址和作者声明只定位内容，不增加权限。
- 来源和访问权限每次重验。若系统提示当前对话用到的 Workflow 已不可用，说明需要开新对话继续，不能重试失效上下文、裁旧历史或换员工绕过撤权。本人历史审计元数据可保留，重新打开正文和资源仍按当前资格核验。
- 员工详情的目录、预览和“模型实际读取记录”区分目录可用、正文已读、资源已读和实际注入；它们均不证明模型照做、业务测试通过或交付成功。只报告实际回执覆盖的结果，不根据缺少记录编造已加载或未加载。
- 保存和读取不改变平台安全、工具、网络、文件或来源权限，不执行包内脚本、不安装依赖、不启动定时、监控、推送或后台任务。个人名称与表达偏好仍用独立设置；不能把业务方法塞进人设或记忆。

## 旧文字方法的历史边界

旧文字方法不再接受新增、改写、恢复或重新启用；不提供旧工具写入步骤。原 Run、Skill 正文、完整包、来源 pin 和已提交请求回执保留，不用今天的目录替换旧快照。历史查询按当前 owner、实例、范围及来源权限读取，不能把旧候选当新草稿，或把当时“已生效”的回执说成现在仍有效。

现存旧文字先由有权承接人核实用途：工作步骤进入标准 Workflow，习惯仅形成待本人确认的记忆候选，企业事实保留原权限进入资料，明确测试内容按批准范围归档。混合用途拆分、未决保留；不能凭标题猜用途、自动确认记忆、擅自迁移或删除原来源。
