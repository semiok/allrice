# 平台每日质检使用原生定时回执

每日固定场景质检保持原来的后台入口、北京时间规则、私有平台工作区和报告。DSH 的现有 recurring Host 负责时间；收到真实回执后，AllRice 把它交给原有质量检查队列。静态检查仍不调用模型，不创建修复或发布操作。

## 交接与历史

- 同一 Automation 保留 ID、daily/Asia-Shanghai 配置、new_each_run 模式及原 revision/CAS。平台质检使用明确的 `platform-quality-v1` consumer；普通聊天的控制 JSON、摘要与权限不变。
- 原生回执先在一个短事务中产生原 `quality_occurrence`。独立派发租期在 PostgreSQL COMMIT 时仍必须有效；回执、冻结版本、目标时间、私有范围及原业务记录必须精确对应。随后复用原恢复器、requestId、Run/Job 和报告，恢复不依赖已经结束的短交接租期。
- 派发期限始终是原目标时间加 15 分钟。忙碌、过期、暂停或配置变化形成明确的未执行记录，不补跑积压日次。已绑定的 Run 保留真实结果与原有停止入口。
- 每次启用、编辑或恢复冻结相应版本及数据库时间水位；晚到的旧回执不会被当成新规则。暂停/删除在原配置事务内阻止未派发工作，删除还要求原生任务确认删除。
- 旧计划逐个在原规则锁内迁移，不更换历史 ID。旧消费者已预留的 occurrence 沿原流程恢复。已到期但未预留的旧目标先交原消费者处理；未来目标冻结为交接下限。如果实际 Host 初始化已跨过这个目标，原历史明确保留 `QUALITY_CLOCK_HANDOFF_MISSED`，不伪造 DSH 回执。

## 权限与验收

配置仍要求真实平台管理员登录；日次执行只用原有平台私有委托，不借公司成员、普通聊天或伪造登录。准备、入队及执行继续检查当前管理员和私有配发权限，个人云端自动工作的开关不会被错误套用到平台静态质检。

必要检查包括真实隔离 PostgreSQL 的回执交接、唯一 Run/Job、未知提交回读、两层 COMMIT fence、原配置管理、撤权、历史关联和锁顺序；实际公开 Host 与 Dev 页面/报告需另行验收。SQL 合成回执测试通过不代表真实时钟或项目执行通过。保持 DSH 核心、依赖和原生执行包不变。
