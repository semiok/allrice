# MET-155 PR1：能力依赖与员工配置

日期：2026-09-26。基线：main `bb4cc68`。本批只收敛员工生产配置，不升级 DSH，不包含 Boost / Teamwork 或新的 Office 实现。

## 决策与复用

继续使用已有 Broker `allRiceToolManifest`、Skill `requiredToolRefs`、`assembleEmployeeCapabilities`、员工草稿/发布、冻结 Bundle 和运行包。DSH 引擎保持 `0.1.5-rc.3`，Web UI 来源保持 `0.1.7-rc.1`，没有新增插件加载器或第二套能力运行时。

实际缺口是 Allrice 后台无法区分手选工具与自动依赖，且开发协作、本地 MCP 的依赖在装配、预检和就绪描述中重复声明。这属于员工配置接线，不是 DSH 推理或 Skill 执行能力缺失。最小补充如下：

- 在现有 `employee-tool-catalog.ts` 集中声明工具依赖、附加能力、连接器身份、执行服务、策略动作与环境提示。基础工具能力仍取自原 manifest。
- 现有装配器解析依赖闭包；开发协作和本地 MCP 的就绪工具集合使用同一解析结果。发布与配置检查读取同一静态声明。
- 员工定义增加可选的 `capabilities.explicitToolNames`，记录手动选择或“单独保留”的工具。`toolNames` 继续表示最终有效工具集合；UI 修改工具时同步修改手选来源，服务端保存重新装配。API 调用方传入已有来源字段时，应编辑此字段表达手动增删。
- Skill 来源直接从所选 Skill 的 `requiredToolRefs` 推导，不额外保存来源图。后台显示自动装配原因，并允许单独保留依赖工具。

## 编辑与兼容语义

有效工具 = 手选工具 + 所选 Skill 所需工具 + 上述工具的传递依赖。取消 Skill 后重新计算；仅移除已没有来源的自动工具。其他 Skill 共享的工具、手选工具继续保留。依赖中的互相引用通过集合去重，不能把一次自动装配提升为永久手选。

没有 `explicitToolNames` 的历史定义按全部工具手选处理，不猜测过去的编辑意图。该字段没有 Schema 默认值，不批量回填旧数据；新保存的草稿才记录来源。已发布定义、冻结资源和 checksum 不改写。

来源仅用于编辑，不进入运行包、能力指纹或 DSH 进程配置。仅改变“单独保留”而不改变有效工具时，同一 revision 的运行包完全一致。有效工具、模型、Skill 版本真正变化时，继续遵循现有的重建规则。

能力移除后保留原连接器身份偏好及安全设置；未使用的身份模式不等于可执行权限，也不应阻止保存。仍在使用的 MCP 工具继续验证所需能力，后续手动禁止 secret/network 等设置不会被服务端保存悄悄清除。

## 各层职责

| 层                          | 继续承担的责任                                                         |
| --------------------------- | ---------------------------------------------------------------------- |
| 静态工具目录 / Skill Bundle | 声明工具、依赖、所需能力和执行服务；不保存成员实时状态                 |
| 员工后台 / 草稿装配         | 勾选、依赖来源解释、手动保留、配置检查                                 |
| 发布与冻结                  | 既有 revision / checksum / CAS、租户派驻与已选执行策略启用、旧版本回退 |
| 就绪与授权服务              | 真实账号、设备在线、目录、环境、成员偏好及当前授权                     |
| DSH / Worker / Bridge       | 沿用现有原生推理、Skill、Subagents、工具执行、任务计时与操作账本       |

开发环境继续保存并发布即生效，不新增预览门槛或开关。MCP 按需连接；设备入口为设置 → 我的电脑；环境状态在能力与环境查看。生产环境的实际关闭和禁止状态仍如实报告。共享声明没有替代执行时的资源检查。

## 验证与边界

- 契约测试覆盖共享依赖、手选保留、历史定义、互相依赖及删除最后一个 Skill。
- 真实 PostgreSQL 验证无预建 MCP 连接的发布、移除 MCP 后的保存发布，以及旧冻结快照保持不变。
- Chromium 驱动真实后台与 HTTP / PostgreSQL：选择两个共享工具的 Skill、单独保留工具、刷新、分别取消、发布、普通成员创建会话、读取所发布的冻结 Skill 资源、回退到原发布包。
- 运行包测试验证历史定义解析不补字段、编辑来源不改变运行包。已有 DSH 跨轮复用测试继续覆盖稳定配置复用和真实配置变化重建。

浏览器夹具使用隔离账号与数据库，不消耗模型额度；读取真实发布的冻结资源不等于本批重新验证 Office 或开发协作的模型任务。后两批真实业务交付验收仍按 MET-155 PR2 / PR3 推进。

员工版本回退沿用既有发布回退接口，已发布运行包及运行中的 Run 不变，无需数据库迁移。若回退本批代码，必须保留 `explicitToolNames` 的可选 Schema 声明：更早的严格 Schema 会拒绝已带此字段的新定义，不能直接降回旧 Schema。回退装配行为时可忽略来源、保留最终 `toolNames`，但不得就地修改已发布定义或 checksum。
