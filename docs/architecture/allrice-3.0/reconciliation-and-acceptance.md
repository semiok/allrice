# MET-155 PR3：对账接入同一 Skill 发布路径

日期：2026-09-27。基线：PR1 能力装配与 PR2 开发协作 Skill。

## 实施边界

`business-reconciliation` 已有冻结脚本、输入校验、整数分算法、云端 gVisor 执行和 XLSX 交付。它直接使用 PR1 的依赖装配、来源解释、发布冻结和回退，不再建设另一套对账插件配置或运行时。

本批只更新 Skill 到 1.0.1：遵循 MET-159 的成员云端自动工作设置，先调用工具，再根据平台返回决定是否等待确认。修复旧 SOP 无论实际设置如何都要求先等审批的矛盾。脚本、示例 CSV、格式契约和 Excel 导出器的字节保持不变；不借 3.0 重写业务算法或 Office 能力。

已发布员工和 Run 使用各自冻结内容。同步目录不会修改它们；管理员保存新草稿并发布后采用新 SOP，可随时回退旧发布版本。输入 ID 与 checksum、沙箱范围、产物来源和整数金额校验继续由现有程序保证。

## 三批实际收敛的内容

| 原问题                           | 本次处理                               | 保留原因                                 |

| 工具依赖散落在装配、预检和就绪处 | PR1 共用现有工具目录的静态声明及解析器 | 动态设备、账号、策略仍由实际资源服务查询 |
| 自动工具与手选工具混在一起       | PR1 记录编辑来源，展示依赖和单独保留   | 历史定义按手选处理，避免猜测删除         |
| 开发协作角色 SOP 内嵌 Worker     | PR2 读取本 Run 的冻结角色资源          | 旧包兼容提示、参数校验及错误纠正仍保留   |

未新增第二个 Agent Loop、Skill 加载器、执行引擎、计时器、审批账本或 Office 渲染器。现有开发候选、对账结果格式和各自业务校验仍是必要业务模块；并未宣称把所有业务分支消除。

## 开发与租户体验

开发端：业务流程和角色说明可随 Skill 资源发布，不必修改 Worker；声明依赖后使用同一后台、发布、冻结与回退链路。执行边界或业务算法变化仍需要代码审核和测试。

租户端：管理员选择技能即可装配所需工具；开发协作沿用现有测试、审查和下载成果；对账按已选择的工作方式自动执行或确认，交付真实 XLSX。MET-159 / MET-160 已实现的设置、排队、状态与成果界面继续复用。

本次模块化不保证模型更快或更准确。DSH 进程复用沿用此前修复，稳定配置继续复用，实际版本变化正常重建；任务物理时钟沿用 MET-153。

## 验收与回退记录

本地/CI 复用原生工具回归、对账脚本及报表测试、真实 PostgreSQL 发布和版本回退、原生助手与 DSH 复用测试。Dev 验收须记录两类真实任务：开发修改 → 同版沙箱测试 → 独立审查 → 下载；上传两份 CSV → 冻结脚本计算 → XLSX 下载并重新读取金额和来源。实际 Run、提交、CI、下载摘要及遇到的问题记录在 [MET-155](https://linear.app/metasnowsky/issue/MET-155)，未完成真实交付前不关闭工单。

无数据库迁移。代码回退仍遵循 PR1 对可选 `explicitToolNames` 字段的兼容要求。员工版本回退不改写历史 Run、输入文件、产物版本、账本或时钟。
