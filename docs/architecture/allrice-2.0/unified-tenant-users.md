# 统一租户用户与平台管理

租户侧不再区分管理员和普通成员。所有可执行任务的租户账号使用相同的工作台：使用已派驻员工，管理本人的工作方式、应用连接和 Bridge。平台管理员仍通过现有平台身份配置判定，负责员工发布与派驻、租户账号、共享环境、模型和执行策略。

## 前后台变化

- 后台「真人成员 / 成员与角色」统一为「租户账号」，移除角色选择，仅编辑授权启停并显示工作区范围。无需保留最后一名租户管理员。
- 工作台不再返回租户管理员管理入口。本地浏览器和本地 MCP 设置允许所有可执行任务的租户账号访问；服务端验证实际账号、工作区和设备所有权。
- 共享 MCP、云端浏览器、模型与员工配置仅由平台管理；旧租户管理员不能通过保留接口绕过限制。
- 旧管理员不再具有读取其他用户私有运行、替他人审批或修改他人共享资源的特殊权限。
- 本地 MCP 只能绑定给当前账号已派驻的员工；他人的设备连接不可见、不可绑定。

## 兼容和迁移

迁移 `0111_unified_tenant_users.sql` 将当前成员授权和待接受邀请中的 `admin` 转为 `member`。账号 ID、组织/工作区范围、启停状态、会话、员工派驻、私有数据与设备所有权均保留。冻结的历史执行策略不重写。

契约保留历史 `admin` 和 `viewer` 的读取兼容性，旧客户端提交 `admin` 时也只保存为 `member`。已有明确只读授权不自动提升；后台显示「历史只读授权」，省略角色的账号启停操作保持其只读属性。新租户和邀请默认使用 `member`。

## 验证重点

使用隔离 PostgreSQL 和 Chromium 验证后台账户启停、并发版本检查、普通账号个人连接管理、跨账号和跨租户拒绝、平台身份与租户角色独立、旧管理员迁移和只读兼容。现有运行、审批、MCP、浏览器和员工继承测试继续覆盖真实数据流。
