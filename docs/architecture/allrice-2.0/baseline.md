## 先给产品经理的结论

AllRice 1.0 并不是只有一个聊天页面。它已经有租户身份、Session/Run、固定执行快照、数据库队列与事件、存储、交付物版本、审批、Bridge 文件操作及受管浏览器等基础。2.0 应在这些真实入口上扩展，而不是重新建立一套相同名字但不同权威的系统。

最大的新增部分是：可以可靠恢复的统一操作账本、真正受 OS 限制的通用命令执行、工作台里的版本化审查闭环，以及受控子助手协作。类型里写着 `process.execute`、菜单里出现某个模式，或数据库状态变成 `canceled`，都不足以证明上述能力已实现。

## 冻结边界：已有 Session 可以升级，但已创建的 Run 不被改写

源码中存在两层不同事实，不能用“整个 Session 永久冻结”概括：

1. [sendChatMessage](../../../packages/database/src/workspace/service.ts) 读取当前有效员工分配；既有 Session 的下一轮输入可以使用新发布的员工版本，并记录 `session.employee.version.refresh` / `active_assignment_version_applied_on_next_turn` 审计原因。
2. [prepareEmployeeRunBinding / resolveEmployeeExecution](../../../packages/database/src/employees/employeehub.ts) 将员工定义、授权、模型、Skill 内容、用户配置和提示上下文固定到执行快照；运行时读取该快照。已入队 Run 不应被后来编辑员工、Skill 或路由的动作静默改变。
3. [freezeSessionModelSnapshot](../../../packages/database/src/providers/model-pool.ts) 还有模型策略自己的 Session 快照边界；不能推导“员工版本变了，所有模型和执行目标也跟着变”。

2.0 必须定义每种变化的生效边界：新 turn、新 Run、新 attempt，还是只能新建 Session；同一字段不可在 UI 中显示一种版本、执行时使用另一种版本。配置刷新必须同时考虑 Runtime Pool 指纹/重建与旧 Run 回放，而不是就地改变仍执行中的权限。

## 已有保护不等于待升级能力已经安全

### 文件写入：原子替换不是整个授权与比较流程的原子性证明

[writeTextFile](../../../apps/rice-bridge/src/executor.ts) 的 SHA 检查发生在临时文件写入与 `rename` 之前。该实现提供了现有的冲突检测和原子替换方式，但仅凭代码顺序，不能承诺其他本地进程在校验后修改文件、替换路径/父目录等竞争情形全部被阻止。

后续安全 PoC / Changeset PR 应把这当成**明确待验证/可能需替换实现的边界**：保留用户未提交修改、路径及软链接竞争、新建文件竞争、审查后再次修改、多个文件部分成功、原版本恢复。测试未证明前，不使用“完全防覆盖”“强事务落盘”等措辞。

### 执行与恢复：至少一次消息投递不等于副作用恰好一次

现有 Bridge 命令有服务端状态、租约和超时，但[客户端 complete 流程](../../../apps/rice-bridge/src/index.ts) 仍需把本地执行后的结果回传服务器。当前实现不是 2.0 所需的持久设备执行日志/outbox 与重连对账协议。

通用进程执行必须区分“未启动”“运行中”“本地已完成但云端未知”“已确认结果”“状态无法确定”。安全取消必须证明进程树不再继续产生副作用；仅设置数据库 `canceled`、UI 停止旋转或断开 WSS 不是验收。

### 当前循环保护：已有，但不是共享根预算和硬资源隔离

[AgentLoopGuard](../../../apps/worker/src/agent-loop-guard.ts) 默认限制事件数、工具调用数、同一工具签名重复次数和观察到的运行时间，并由[员工 Run](../../../apps/worker/src/jobs/employee-run.ts) 逐事件调用。它的计数在当前进程内；时间判断发生在 `observe` 中，不能据此证明没有新事件时仍有独立硬超时。

2.0 要补的是跨父子助手、重试与 Worker 的统一预算/停止语义，以及 OS 层超时、CPU、输出和进程数量等措施。不得删掉旧 guard 再等待新预算全部实现，也不得将“费用估算”“模型上下文压力”“累计已计费用量”混为一个数字。

### 检查点恢复不是文件恢复

[ContextCheckpoint](../../../packages/contracts/src/harness.ts) 保存摘要、覆盖到的消息、generation、配置校验和等；[employee-kernel](../../../apps/worker/src/employee-kernel.ts) 使用摘要及未覆盖的消息组装后续上下文。它不是机器快照，也不保存任意 OS 子进程或本地目录的全部状态。

因此恢复对话、恢复执行、分叉 Session、恢复文件版本必须采用不同操作类型和权限。用户看到“恢复成功”时，应知道究竟恢复了哪一层。
