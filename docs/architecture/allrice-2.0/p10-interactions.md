# P10：类型化交互与输入回执

MET-119 / B2 / S2 / R2。依赖 P03-a、P04、P06、P07；批次交付以执行总表为准。

## 对用户的变化

- 回答问题、认可计划、版本意见、动作授权分开呈现。计划认可只创建后续 Run，不批准任何命令或文件动作。
- “请 Rice 根据本批意见修订”绑定确切 Artifact、SHA 与已提交反馈。响应与后续 Run 的关联在同一事务保存；失败可以重试同一提交 ID。
- 工作时可以选“纠正当前回合”或“排队下一轮”。前者绑定原 turn/generation；已失效的回答和纠偏不会被解释成下一轮普通消息。
- 可收起的交互记录区分收到、等待步骤接收、已进入步骤、结果待核实、排队、任务完成；提供版本、输入和待批准动作深链。
- 新发布的员工配置只影响新 Run。命令进程使用 P05 独立状态卡；助手产品仍未发布。原生用量缺失不解释为零消耗。

## 权威与恢复

沿用 Message → Run/Job → conversation_followup/command，不引入新 Agent Loop。
0078 扩展既有队列，增加提交指纹和版本响应关联；同 ID 改内容冲突、同版重复认可冲突。
提交入口有同源检查和 300 KB 请求上限；重新检查真实租户、Owner、工作区、有效成员。
后续修订开始前再检查版本和成员权限；过期版本不启动模型。旧审核记录不删除。

严格纠偏的 `steer_only` 记录不能被普通 Job Worker 领取。原回合关闭后取消对应候补 Run，
包括升级前尚未答完的表单。普通 `follow_up` 保留原 FIFO。
输入领取/消费检查 Worker、turn、generation 与活跃 Job 租约。

DSH RPC 成功只证明投递，不证明采用。本适配把 AllRice inputId 与实际 native messageId 关联，
在原生 `user/message` 进入步骤后保存序号；问题回答使用 `question_resolved`，只表示答案交回工具。
传输超时使用同 ID 重查；原生记录存在但无法确认是否采用时为 unknown，不自动重放。
回合结束前做有时间上限的最后检查，防止最后一个步骤完成快于轮询。

## 固定 DSH 兼容处理

版本：`@deepseek-ai/dsh` 0.1.1-rc.2-b150a55，插件 0.1.1-rc.2。
该版本会拒绝未登记的持久化事件，且没有 downstream 插件登记 API。
`allrice-dsh-inputs.mjs` 仅扩展公开导出的 `KNOWN_SESSION_EVENT_TYPES` 中两个私有类型：
`allrice/input/request`、`allrice/input/answered`。不放宽其他未知事件的检查，不更改第三方安装目录。
效应前后调用原生 `sessions.flush`；使用实际 JSONL、inbox 与步骤事件，不伪造模型结果。
这是固定版本兼容适配，不声称上游已有正式扩展 API；上游升级需要重跑实测。

显式恢复失败不再创建空 Session 冒充恢复。默认新建只有明确不存在的日志才回退。
升级/回滚必须排空 Worker，不能让不识别私有日志的旧运行包与新包混用。
回滚保留 0078 数据和此日志读取适配，关闭工作台开关；不逆向删除响应和历史。

## 验证与边界

- 本地固定 DSH + 回环合成模型 SSE：真实下一步接收、同 ID ACK 丢失重试、改正文拒绝、JSONL 冷恢复、不额外调用模型、原生问题与答案验证。
- 实际 PostgreSQL：真实 sendChatMessage/冻结绑定/Run 队列；严格 turn、Worker 隔离、无证据不能消费、过期取消、不落入普通 Job、版本绑定、防重、旧版回执重读、启动前失效、跨 Owner 拒绝。
- 实际 Chrome + PostgreSQL：Cline 反馈、提交续跑丢 ACK 后重试，仅一个后续 Run，未产生操作授权或文件动作；旧版本与窄屏等 P07 回归。

工作台与记录入口使用 `ALLRICE_WORKBENCH_ENABLED`，默认关闭。输入幂等和失效表单修正为服务端安全修正。
不提供新的通用授权按钮、不创建任意 PTY、不开放助手产品；文件应用/恢复由 P08 单独交付。
停止仍走原取消协议；没有把“点击停止”直接标作进程已终止，也未提供一键 interrupt-adjust/fork。
B2 尚未合并/部署，不能据此声明 2.0 GA 完成。
