1. 统一登录：数据库用户名、会话与密码生命周期；统一域名不再绑定 Snow。
2. 组织和员工管理：公司、默认工作区、普通员工账号、岗位职能、批量导入、密码重置与停用。
3. AI 员工配发与人设：组织默认名单、按人批量增删、持久化个人撤回、按公司与当前员工注入上下文。
4. 全局 AI 发布：编辑 AI 本身，更新所有已配发对象；保留运行中版本快照和真实更新回执。
5. 工作动态：按公司、员工、AI 员工查看真实运行、等待、失败与交付成果。
6. 迁移和验收：旧域名、设备接口、现有身份与资料迁移，最终联合发布。

不依赖 MET-145、MET-146 或 Team 新能力。

## PR1：统一账号身份

- `allrice.bplabs.xyz` 和默认本地入口使用数据库账号登录。登录名是全局唯一、不区分大小写的英文昵称；显示名可以独立修改。已有邮箱登录兼容保留。
- 公司和工作区来自账号当前有效成员关系，不能通过域名或客户端传入的公司 ID 越权。多个历史工作区继续由已有成员关系检查。
- 普通员工与平台管理员使用同一登录入口，管理员权限继续由平台身份判定，普通租户的历史角色不会获得平台权限。
- 接受管理员指定的初始密码 `admin@321`。存储继续使用随机盐 scrypt，不把明文密码写入账号表或日志。新员工创建在 PR2 提供，现有账号批量迁移在 PR6 执行。
- 用户可以在「设置 → 账号与用量 → 修改登录密码」主动改密，不增加首次登录强制改密步骤。改密撤销所有旧登录会话。
- 登录校验、创建会话和改密在用户行锁下串行化，避免重置密码期间旧密码创建仍有效的会话。
- 旧 Snow、Drink 和平台管理入口暂时兼容。仅未迁移的账号首次通过原部署凭证登录时初始化用户名和数据库密码；已迁移账号一律使用数据库密码，重复初始化不会覆盖密码或恢复撤销的成员关系。
- 旧入口签名的用户 ID 必须与数据库会话一致。Bridge 设备接口保持原有独立凭证验证路径。
- 增量迁移为 `0113_unified_login.sql`；`0112` 留给正在并行开发的会话引用功能。

验证使用随机 PostgreSQL schema 和合成员工，无真实租户、模型调用或 Dev 修改。覆盖共用入口、跨公司隔离、平台权限独立、账号停用/撤销、用户名唯一、改密与并发登录、旧入口迁移幂等及改密接口。
