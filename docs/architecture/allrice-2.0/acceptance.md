所有 `expected` 中的短标签都是**设计断言名，不是已发布的错误码或数据库枚举**。P01 等 PR 必须明确实际 schema 映射、兼容策略和迁移；若确定性期望需改变，记录理由并同步相关契约，而不是为迎合实现悄悄改结果。

计划模式限制目标操作与外部副作用，但不禁止在授权范围保存计划工件。Run 内冻结配置不可变；同一 Session 的后续 Run 可以按生效规则采用新发布 EmployeeVersion/Skill 版本，不把 Session 误当永久配置快照。

## 2. 安全输入与复现约定

- JSON 使用固定 UTC 时间和合成 UUID；`scopes`、`artifacts`、`sources` 中的关联只用于测试材料。不能拿浏览器传来的租户 ID 当权限证明，身份须由受信请求上下文建立。
- 所有文字、金额、用户名与路径都是合成数据；`.invalid` 是占位域，不联网请求。文件内容按 UTF-8、LF、无 BOM 计算 SHA-256；金额用整数“分”，不做浮点四舍五入。
- `scopeRef` 展开相应 `scopes`，再应用该用例明确的变体。`artifactRefs` 与 `sourceRefs` 必须在顶层注册表中解析；`steps` 数组定义顺序，`expected` 为对应不可放宽的判定。每个用例都从全新状态开始，不依赖上一例遗留状态。
- `futureSemanticNotes` 仅保留延期能力的语义边界，不属于用例的 GA `steps`/`expected` 或 `candidatePrs` 实现承诺；不得因此新增启用入口或 GA 前置。A08 的 fork 即为此类预留，后续另行排期才转为真实功能用例。
- 本地路径只使用未来测试新建的隔离临时根目录。`relativePath` 和 `rootAlias` 不是本机真实路径。越界/软链接用例仅允许链接到同一次测试创建的兄弟临时目录，禁止指向用户文件或系统目录。
- 云端和浏览器验收使用隔离测试租户、受控站点、独立 Profile 与合成资料；不接入生产账户或个人 Cookie。示例中的令牌占位符不是凭证，禁止以真实密钥替换后提交。
- 设备结果或预算证据要由实际适配器/执行器获取；不能让模型复述 `expected` 充当结果。涉及拒绝时还必须观测“无落盘/无新进程/无网络副作用”，不能只断言返回错误。

## 5. P00 与后续 PR 的证据边界

从仓库根目录运行只读材料检查：

```bash
node docs/architecture/allrice-2.0/validate.mjs
```

[检查脚本](validate.mjs)仅读取文档和静态JSON，验证引用、合成内容摘要、覆盖与参考计算；不联网、不运行项目命令、不访问数据库，也不执行生产契约或证明并发/隔离正确性。

P00 可记录：Markdown 相对链接存在、JSON 可解析、必需关联完备、八契约与四任务线覆盖、合成摘要/金额计算一致。**这些是材料检查，不是功能、隔离或 GA 测试通过。** JSON 的 `validationStatus` 必须保持 `design_only_not_executed`；后续证据存于实际 PR/测试记录，不能把静态设计文件的期望字段当作实测结论。

每条真实证据至少记录：

`caseId / 候选ID / 真实PR URL / 完整SHA与基线 / 日期 / 环境与设备 / Flag与冻结配置 / 合成输入版本 / 操作及命令 / 期望与实际 / 状态与副作用观察 / 未测与阻断 / 修复回归 / 回滚与授权`

开发、自审、自测、风险判断和修复由 Codex 负责，不等待 Gemini 或另一外部模型认可；项目完成后的 Gemini 补充测试由用户另行安排。这不取消产品内高风险动作审批，也不取消未来 Boost/Teamwork 的产品内独立核验能力。完整 Boost/Teamwork、开发协作增强和正式 Handoff 属于总表 S8，不能因 A11 包含“关闭模式不得启动”的负例就宣称这些模式已实现或验收。
