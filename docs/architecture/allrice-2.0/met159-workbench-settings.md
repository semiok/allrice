# MET-159 PR5：普通成员设置与能力入口收敛

## 使用体验

沿用 MET-160 的 DSH 原生 SettingsRoot / Modal、员工会话树和文件工作台。设置统一提供「账号与用量」「已连接应用」「我的电脑」，普通成员与管理员使用同一连接界面。个人应用可登录、补充凭据、刷新、断开、重连和删除；不再要求填写工具矩阵或浏览器授权表单。电脑入口复用已有 Bridge 下载、配对与目录选择弹窗。

能力面板的「应用连接」表示员工可以按需连接应用，不要求用户先配置一个连接。具体应用是否已登录、发现失败或主动断开，以「已连接应用」中的真实记录为准。已发布员工的工具、执行策略与成员资格仍实际检查；没有把缺失环境或明确停用伪报为就绪。匿名服务无需凭据加密密钥；连接就绪查询只读取当前成员可见且未断开的连接。

本地缺项显示「连接电脑」「选择文件夹」「已暂停」或真实准备状态。缺少本地计算环境时，可从面板准备现有云端计算任务；未安装本地应用时，可让员工连接在线应用。这里只追加可编辑的任务指引，不自动发送或上传本地文件。未接入的本地服务仍需实际安装，不能把在线服务当成等价的本机环境。

能力面板保持打开检查一次、手动刷新保留卡片与展开状态。应用连接页只在连接进行中更新；稳定状态不轮询。切换设置栏目保留凭据草稿，关闭后销毁；用户或工作区变化立即关闭个人设置并清理旧内容，不跨身份保留凭据草稿。

## 复用与改动范围

- DSH UI `0.1.7-rc.1` / `46a7f68b0922371ce7144b668b90e377d8e799f4` 的 SettingsRoot 和发布包 Modal：直接使用 MET-160 已验证的适配，不新增设置框架、不修改原生源码。
- 复用 PR4 `ConnectedApps`、成员连接 API、原生 MCP 客户端与登录恢复；本 PR 只接入设置并补手动刷新。身份、凭据、断开和删除依旧由服务端验证。
- 用量、Bridge、员工派驻/继承、上传、Office 成果/版本/下载沿用既有实现。管理员高级配置页面与管理后台保留用于诊断；普通工作台不再显示这些配置表单。
- Readiness 新增 `connection_on_demand` 原因，数据库读取仍为只读事务。本 PR 无迁移、无 DSH 引擎或 Bridge 安装包升级。

## 验证与证据复用

本批定向验证使用真实 Chrome 和独立 PostgreSQL schema，无真实模型调用、无 Dev 新员工或测试成员。

- 普通成员与管理员，390px / 1440px：原生设置、账号用量、连接状态、断开/重连/删除、凭据草稿保留与焦点恢复；不请求旧管理员配置接口。
- 用户/工作区在后台刷新后变化：旧设置关闭，旧应用与凭据草稿不残留；会话内打开连接设置不覆盖聊天草稿。
- 能力面板：打开一次检查、手动刷新不闪烁；失败或错误 scope 不显示可执行；电脑配对跳转、应用设置跳转、既有文件与 Office 预览链路回归。
- PostgreSQL：普通成员可用的应用连接能力不依赖已连接私人应用；匿名连接不依赖加密密钥；他人的连接、本人已断开的连接不计入就绪；只读成员不能发起执行，查询不产生运行操作。
