# P08：精确文件变更审批、应用与恢复

MET-120 / B2 / S2 / R2。依赖 P04/P05/P06/P07/P10；批次执行、合并与 Dev 验收以执行总表为准。

## 用户流程与范围

工作台审查 Changeset → 请求应用 → 同 Session 的独立 Run 排队 → 精确动作批准 → Bridge 逐文件应用 → 持久化逐文件回执。
请求、认可计划和聊天消息都不是授权。默认没有新权限；已安装的旧 Bridge 不会领取此动作。
本切片支持已有授权目录中的 UTF-8 普通文本新建、修改、单文件删除，以及有证据的反向恢复；不创建目录树、不开 Shell、无递归删除。
需要运行项目测试时必须另行使用 P05 的受控命令及其精确审批；应用文件不隐含运行代码或安装依赖。

工作台区分提案与实际动作，展示目标设备、授权目录绑定、逐文件前后 SHA、实际动作前后文本、审批和结果。
恢复卡片展示反向内容；不会把原始正向提案作为恢复动作。拒绝、过期、取消和未知不能显示为全部成功。
一次 Artifact 版本最多申请一次应用、一次应用最多申请一次恢复；同提交 ID 可重试请求/回执，不重复产生任务。
若被拒绝、发生冲突或需再尝试，须发布、审查新的 Changeset 版本，不自动重用过去的审批。

## 权威与治理

- 0079 只新增不可变关联，仍使用既有 Message → Run/Job → Session FIFO、共享操作账本和 P04 审批。Worker 使用确定性文件动作分支，不调用模型、不另起 Agent Loop。
- 文件字节只从该 Owner/租户/工作区/Session 的不可变 Artifact 读取。浏览器不能提交动作字节、换设备或扩大授权范围。
- `local.fs.changeset` 只属于 opt-in 账本协议，不进入旧 HTTP capability 列表；新客户端显式握手 `supportsChangeset`。
- 冻结配置须有 `storage:write` 和 `local.fs.write` 工具绑定；既有员工权限解析仍要求相应的已绑定、启用原生 Skill。没有把“配置里写了工具名”当成授权。
- Tenant Policy Deny/Ask/Allow 继续生效；即使 Allow，本动作也必须单独 Ask。精确 binding 关联 Artifact SHA、完整动作 digest、Run、generation、设备/目录版本和冻结配置。
- 派发、启动、每个文件处理前和提交前重新验证权限、Job 租约、取消状态及目录绑定。拒绝/撤销/到期会结束等待，不自动改由 SaaS 执行。
- API 同源校验、登录后检查关联、4 KB 实际取消请求上限、不缓存；交互面板提供版本与待批准动作入口。

## 文件一致性与未知结果

先检查所有基线，再逐文件处理。同目录 `wx` 临时文件、fsync、再次 SHA/文件身份检查；修改使用单文件 rename，新建使用不会覆盖已存在目标的 link 插入。
拒绝目录/符号链接/硬链接、越界与敏感路径；读取及写入每份文本限 200 KB，派发载荷限 350 KB，最多 32 文件。

**不承诺多文件事务，也不承诺对同 UID 的恶意并发写入提供 OS 级原子 CAS。**
普通编辑发生在最后校验前会被阻止；不合作的进程仍可能抢在最终 rename/unlink 系统调用前写入。
因此 UI 明确要求操作期间暂停其他写入者。本能力复用受控文件写入路径，不冒充宿主机沙箱；P05 隔离执行是另一层能力。

SQLite 在每个文件副作用前后分别保存 prepared / applied 检查点。进程被强制退出后：

- 已持久化 applied：保留确认结果，不重做。
- prepared 而未确认：unknown，不能从当前内容猜测曾经成功，不重做。
- 尚无检查点：未执行；不会自动续写后面的文件。
- ACK 丢失：仅重送原回执，不重复落盘。冲突/错误 attempt 回执不作为恢复证据。

恢复只反转同一应用中有正确 path、before/after SHA 的 applied 文件，逆序执行并再次批准。
新建文件的恢复是删除那一个文件；删除文件的恢复是按原字节重建。用户后续改动导致 SHA 不匹配时拒绝覆盖/删除。
部分成功后的恢复不涉及失败、未执行或未知文件；源 Run 即使 canceled，仍可依据真实回执申请恢复已确认文件。

## 开关、发布与回滚

Web/Worker 同时设置 `ALLRICE_CHANGESET_ENABLED=1`、`ALLRICE_WORKBENCH_ENABLED=1`、`ALLRICE_RUNTIME_POLICY_ENABLED=1`、`ALLRICE_BRIDGE_OPERATION_LEDGER_ENABLED=1`，且租户规则允许本动作，才可执行。
Bridge 也需开启设备账本并使用包含本切片的新二进制。安装/打包、公证及双架构发布门禁仍归 P14；不能用旧版下载包已存在来宣称新能力已交付。

默认开关关闭。不修改现有租户授权、配对或真实目录。上线迁移为 expand；回滚前排空 Worker/Bridge 操作，保留 0079、设备检查点和 P10 日志读取适配，关闭新入口。
已被旧客户端读取不了的新 dispatch/journal 不可通过删日志降级；保留兼容执行端完成回执投递或人工核实 unknown。

## 测试证据

- 实际文件：新建/修改/删除/恢复、多文件预检、提交前权限失效、途中冲突、链接/敏感路径拒绝、恢复拒绝用户后改。
- 实际子进程 SIGKILL + SQLite：一份 applied、一份 prepared、其余 pending，冷启动恢复对应 applied/unknown/pending，不再执行。
- 实际 PostgreSQL + 真实 sendChatMessage/冻结配置/队列领取/Worker/审批 + HTTP Bridge/SQLite/文件：应用、丢 ACK、防重、恢复、跨 Owner 拒绝、审批拒绝/到期、开始前取消、途中取消/部分失败和恢复冲突。
- 实际 Chrome：批准、刷新重读落盘结果、反向恢复内容、再次批准、窄屏；身份注入仅用于测试，生产登录/Origin/请求上限另有路由单测。
- P05 专用 x64 VM：真实文件修改 → 失败测试 → 新审查版本修复 → 测试通过；命令只执行精确文件副本，宿主项目不被命令修改。此项验证两执行组件联动，不声称真实模型自动完成了开发任务。
