## PR-1：任务时限与可恢复等待

- 仅新建、服务端确认使用 Codex 订阅的员工 Run 采用新策略。模型身份仍按 Session 冻结，任务时限按每个新 Run 冻结；不回填或重置已有 Run。
- 未配置时默认 1 小时。后台提供 30 分钟 / 1 小时 / 不限制。0 是“不限制”的权威语义，不用延长一年冒充无限。多个显式作用域约束取最严格值；缺省继承不是另一个隐藏上限。
- PostgreSQL `allrice_task_clocks` 持久化活跃时间、等待时间、阶段和每次转换；根任务只有一个计时器，多个等待区间不会重复累加。兼容字段 `deadline_at` / `timeout_at` 是投影，不再各自定义任务时限。
- 仅所有活跃参与者都被审批、设备或用户问题阻塞时暂停。主 Rice 仍在工作、模型请求仍在执行、命令 dispatched/running/unknown 时继续计时。主 Rice 等子助手的事实来自 native idle 回执，不能由“有子助手”推断。
- Worker 心跳、队列维护、执行器轮询和模型准入使用同一时钟。加锁顺序统一为 root → clock → job；维护按根任务独立事务重读，不先锁一批 job 再回头锁 root。
- 审批默认有效期独立设为 1 小时；浏览器观察绑定的敏感操作仍保留 2 分钟短有效期。等候不耗任务时限，但不能延长审批、身份、目录授权、候选版本、单命令 CPU/进程/网络超时的有效期。恢复仍重新校验。
- 去掉等待子助手 RPC 的通用 5 分钟超时；它由 Worker 心跳、取消和根任务时钟监督。普通协议请求、诊断 RPC、单次模型/工具请求仍有各自保护。
- Codex 月请求次数和 Token 仅统计，API 月限额、并发和官方订阅额度保持各自语义。月路由请求次数不冒充原生模型调用次数。
- 助手明细显示活跃时间、等待时间、总历时与任务时限。

## PR-2：调用次数仅统计与无进展保护

PR-1 不撤销 16/64/80 次任务保护。PR-2 为新时钟、已验证订阅路由且已启用持久化进度记录的 Run 一并替换调用次数闸门。旧 Run / API / 未验证路由不受豁免；并发、授权、单工具超时、官方订阅额度、未知副作用禁止重放继续有效。

- 原生 DSH 中间件向 Worker 专用端口记录模型请求尝试、工具开始/完成。数据库按 Run + native Session + call ID 幂等结算，保存参数/结果哈希而非原始内容；未知完成不填零。原生请求统计不冒充官方账单或完整 Token 回执。
- 只保留最近 32 条检测事实。连续 3 次同工具、同参数、同错误，连续 8 次失败，或 12 次操作反复落入最多两种结果时，标记“疑似无进展”，并非断言模型死循环。正常状态读取、控制交互、明确的限流/超时退避不单凭重复触发。
- 暂停写入 PostgreSQL 后，在下一次模型请求前通过根任务 Ask User 呈现原因、最近操作和继续/取消。新进度问题不覆盖已存在的普通问题；所有助手共享这次决策。继续只重置检测窗口，不清空统计、工件、权限或任务已用时间，不批准任何写操作。
- 暂停仍允许已在执行的工具结束；只要任何模型/工具仍在执行，根计时器继续计时。所有计算停止后才进入等待。Worker 端口重建仍能读取暂停及决策；未知原生副作用不会自动重放，不能把端口重建测试称为完整 Worker 崩溃后自动续跑验收。
- 事件吞吐保护按 60 秒窗口计算，而不是健康长任务累计到 1 万事件就失败。助手明细展示模型请求尝试、工具调用和未完成回执数。
- Runtime Console 每轮普通/助手任务均显示该 Run 冻结的时限、来源、活跃/等待/总历时，以及原生请求尝试/工具调用/未完成回执。没有记录的旧 Run 不补零，不用月路由数冒充原生调用数。

正常轮询、审批/设备等待、退避重试不能仅因相同参数被判死循环；不能用换参数、时间戳、反复派生助手冒充进展。不增加第二个 Agent Loop，不使用额外 LLM 裁判，不自动重放未知副作用。
