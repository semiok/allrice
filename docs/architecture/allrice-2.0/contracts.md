# AllRice 2.0 八项公共契约

> P00 / MET-109：语义设计基线，不是新增 API、数据库或事件 schema。
>
> 与 [MET-105 §2B](https://linear.app/metasnowsky/issue/MET-105) 的 C1～C8 顺序一致；[总纲](../../allrice-2.0.md)规定 GA 范围，[执行总表](https://linear.app/metasnowsky/document/allrice-20-执行总表阶段依赖pr-与验收门禁-df09b0b1e681)规定实施依赖。

## 可执行边界与兼容原则

现有 [contracts](../../../packages/contracts/src/index.ts) 及 [ADR-0001](../adr-0001-v1-core-contract-authority.md) 继续有效。下列关联字段与状态是所需语义，不直接宣布同名字段已存在，也不要求机械增加新表。P01 在现有 schema 上明确映射、版本与兼容窗口；相关 P06/P24 等切片再补各自领域细节。

所有跨边界对象必须能核对可信服务端身份、organization/workspace 及适用的 owner/visibility；资源 ID 不是授权。执行/交互对象按其生命周期关联 Session、Run、源对象与版本；ExecutionTarget、StorageObject 等长期资源保留自己的归属，由具体执行建立引用，不为没有会话的资源或平台预览制造虚假 Run。Project 可以为空，但数据归属与获准工作范围不能消失。浏览器不能自报租户/actor 获得权限。

核心关联按语义分层：

| 关联                                                      | 用途与生命周期                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------ |
| Session、Run、turn、冻结配置版本                          | 区分持续协作、一轮执行、当前输入生效点；新一轮选择不热改旧 Run           |
| step、operation、attempt、lease/generation                | 区分逻辑工作、实际动作与合法重试；旧尝试迟到结果不能推进新尝试           |
| agent、parent/root、process                               | 区分助手树与 OS 进程；根预算、取消与子资源可追踪                         |
| target、device、授权工作范围、work copy                   | 精确识别在哪个获准环境作用于哪份数据；本地绝对路径不直接变成云端公开字段 |
| artifact/deliverable version、changeset、review、approval | 关联原始来源、版本化反馈、精确批准与实际写入                             |
| event identity/sequence、usage source/boundary            | 重放、防重、来源与计量范围；不把多次通知重复计费                         |

## C1. 领域职责与 GA 范围

105提供共用工作台、交互和结果表达；106拥有执行端与生命周期；107执行政策/审批/隔离/发布；108管理受控助手和根任务关系。工作台不自建任务账本、第二套审批消费状态或另一套 Agent Loop。

GA 包含基础助手 A～D，首个本地命令验证不等待完整多 Agent 系统。S0只预留关联，不等于通过108-A真实DSH PoC。Boost/Teamwork/Handoff及开发协作增强按S8处理，未发布入口必须在服务端不可启动。即使后续阶段已允许创建Agent实例，也不代表获准执行所有106工具。

验收关注：无Bridge云业务与基础助手可各自成立；未开放模式无法由按钮、自然语言或API绕过；后续范围不被误标完成。归属 P00/P01、P24～P27。

## C2. 协作模式、审查与权限分开

三种维度不能相互授予权力：

| 维度          | 示例                                 | 不能隐含的行为                                  |
| ------------- | ------------------------------------ | ----------------------------------------------- |
| 协作组织方式  | 日常、基础助手；未来Boost/Teamwork   | 不自动加工具、换模型、加预算或转移数据          |
| 工作推进/审查 | 澄清、只规划、反馈修订、认可某版计划 | 不消费动作批准，不默认允许写仓库/外部系统       |
| 动作授权      | Deny / Ask / Allow                   | Allow仍受租户强禁令、撤销、资源和执行端隔离约束 |

只规划时平台可保存获准的计划工件，但执行层必须阻止目标仓库修改与未获准外部副作用，不能仅靠提示词保证。Ask User回答、接受建议、计划认可、动作批准采用明确不同的请求类型与对象版本。

动作批准至少绑定：租户/actor、Run及动作身份、执行目标/作用域、动作与输入指纹、相关数据/文件基线、有效期与消费状态；命令还应绑定程序/参数、工作目录、有效环境/网络策略、预算和必要工具链版本。精确序列化由P01/P04落定，不传递秘密原值。

接收、执行前分别核对当前撤销与强禁令。过期、重复消费、目标变化、输入变更或旧attempt批准不得授权另一动作。产品按钮、自然语言和未来斜杠入口走同一服务端校验。归属 P01/P04/P05/P10/P26。

## C3. 工件反馈、修订与 Diff 来源

复用 Artifact 与 DeliverableVersion/StorageObject 关系：同一成果可有不可变内容版本，当前版本指针不抹掉历史证据。Review绑定操作者、租户、Session/Run、确切工件版本和锚点；文本锚点包含范围与版本依据，首版图片使用整件反馈。

评论草稿只表示正在编辑，提交批次才进入待处理；反馈的待处理、已处理、已失效必须有结果关联。生成新版本不自动“完成”旧意见。用户可提交修订意见或确认本版本，但二者均不等同文件动作批准。

Changeset定义目标/工作副本、文件列表、每个文件读取基线及拟写内容、来源operation/step和对应Review。Diff默认展示本次Changeset；如果展示分支/整个目录差异，标注含用户或其他任务修改，不能用总Diff作此次授权。

批准后文件或输入版本变化须拒绝旧批准并重建对比。批量应用记录每文件结果，不伪装全有或全无；原子替换单文件不等于原子CAS或跨文件事务。恢复也是新受控动作，检查用户后续修改，不强制覆盖。归属 P06/P07/P08/P20。

## C4. 工作范围、目标与资料出端

Workspace是企业数据空间，Project组织任务，授权目录是可执行资源集合，work copy表明原地/Git worktree/云端临时副本，Execution Target是实际执行环境；模型上下文来源和出端政策是另一条记录。

首版可只支持单目录与无项目临时任务，仍须显示真实工作范围、产物归属和目标。目录显示名或稳定指纹不等于云端可访问的文件路径。路径需规范化并在实际操作时验证边界，软链接、并发替换与程序派生进程的访问都在后续隔离测试范围内。Git worktree不等于OS沙箱。

传入模型或云端的文件/片段关联版本、来源目标、用途、授权依据及可传范围；“工具本地执行”不能宣传为“数据从未上云”。切换目标、上传输入、迁移成本与写回本地分别校验，不因Bridge离线自动授权转云。

可继续独立云步骤；依赖本地输入的步骤等待。对已发本地动作，未知结果先核实；无法证明未执行时不重新派发非幂等副作用。归属 P01/P03/P04/P05/P15/P17/P22/P23。

## C5. 步骤、助手、进程、输入与待办

业务步骤、Agent实例、工具operation和后台process分别标识。一个步骤可跨多个operation，一个助手可做多步，一个dev server不等于新助手。业务完成要核对必要依赖、交付和剩余进程；模型回复/助手idle/进程spawn成功均不单独代表任务成功。

运行中新输入在接收时绑定Session、意图、适用Run/turn或队列位置，以及防重键；区分补充当前工作、后续请求排队、请求中断后调整。状态至少表达已接收、排队、待生效、已生效或拒绝，并给出真实生效依据；消息入库不等于DSH已经采用。不能只修改输入框配置就热换当前Run模型/模式。

Ask User、动作审批、反馈修订、等待设备和unknown形成可恢复待办与对象深链。重复事件或多窗口应合并同一待办；处理中和已处理状态由后端校验。普通重复工具信息可以折叠，但待输入/审批/必须核实的事项不被隐藏。

后台进程记录归属、实际目标、租期/期限、输出、readiness、退出结果与取消确认。有限非PTY stdin绑定活跃进程与消息身份；没有TTY能力时明确转人工，不模拟已输入秘密。

开发预览要说明哪个浏览器能访问哪个目标的实际服务、端口/地址、授权访问通道及停止状态；`localhost`在不同环境不是同一地址。跨目标通道没有通过授权/隔离/可达测试时不声明可预览，更不默认开公网端口。归属 P03/P05/P09-c/P10/P13/P21～P26。

## C6. 事件、状态与 usage

扩展现有 RunEvent/SSE 兼容协议，保持持久序列和重放；新增operation/assistant/process事件按其生命周期拥有明确的关联与schema版本。P00不直接增加RunStatus枚举。旧客户端不理解新类型时按明确降级或版本拒绝处理，不能忽略后继续扩权。

必须表达的状态意义：

| 事实                     | 展示/恢复约束                                                      |
| ------------------------ | ------------------------------------------------------------------ |
| 等待用户、设备或前序输入 | 展示原因与可操作项，不当失败或成功                                 |
| 已请求取消               | 已持久接受意图；不等于本地/云端进程已停止                          |
| 执行端确认停止           | 有对应目标与attempt的进程/副作用证据；整树停止须核对子资源         |
| 结果未知                 | 网络/回执不足以确认结果；等待核实，不直接重试副作用                |
| 部分完成                 | 显示已交付部分、失败/等待部分及剩余义务                            |
| 完成/失败/已取消         | 依据适用生命周期的权威终态与实际证据，不由动画、文字或HTTP ACK推导 |

稳定事件ID/序列与attempt用于去重及处理乱序。旧attempt迟到证据可保留用于核实，不能覆写当前尝试；晚到process信息不能非法追加到已终结的旧Run事件序列，P01明确投影/关联存储方式。Transport ACK只确认相应传输事实，不充当执行成功。

usage指明来源、单位、增量或累计、统计边界、计量身份及版本。重复累计快照不相加；多个子任务按根账本汇总，不能既把子费用计入父累计又加一次。预留、已花费、结算、估算分开；缺失成本/用量显示未知，不填0。既有循环上限继续保留，跨进程根预算与硬停止另需实现。归属 P01/P03/P05/P11/P12/P15/P25/P27。

## C7. 继续、恢复、fork与文件恢复

| 动作             | 语义                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 继续Session      | 基于获准历史开始后续协作；新Run按当前发布/选择规则冻结配置                        |
| 恢复执行         | 核对租约、attempt、冻结配置、撤销和未知副作用后恢复合法工作；不是重新跑一遍整任务 |
| 刷新/重连UI      | 读取权威快照与重放事件；不产生新执行或重新消费批准                                |
| fork（后续候选） | 新的分支身份与来源关联；不继承在途进程或已消费批准，不暗示工作目录隔离            |
| 恢复文件         | 对真实当前基线作新的Changeset和授权判断；不能回滚已发送消息、已发布内容等外部动作 |

会话上下文检查点不能证明OS进程或外部副作用已恢复；单文件备份不能证明任务整体回滚。恢复任务树需要共享根状态、子资源身份和取消关系；不凭DSH native session ID重建任意权限。归属 P01/P03/P08/P10/P25；fork不新增GA前置。

## C8. 不可信预览与扩展资产

预览默认是数据渲染，不是同源执行环境。Markdown/HTML、SVG、图片、附件和登录态浏览器分别确定允许类型、协议、外链、活动内容与下载策略。不能由HTML/SVG脚本、外链图片或重定向带走任务内容/主站凭证；无法安全预览时明确降级，不能以CSS隐藏代替隔离。

活动浏览器/开发预览通过独立身份与受控通道，不继承工作台cookie；授权端口、租户、目标与有效期逐项检查，撤销即关闭可用通道。截图带来源目标与时间，过期画面不是当前成功证据。

Skill正文、资源与脚本是版本资产，加载不等于执行许可；实际工具/网络/脚本依赖继续经过106/107。Hooks、Sidecars和自定义插件自动发现执行不进入GA，未知自动执行配置不能被偷偷加载。既有自动化复用现行调度器，不另建隐藏Agent/进程常驻权威。归属 P04/P07/P14/P18/P21/P22/P23。

## 语义与代码交接

P01已将首版共享schema、状态/重放纯验证与旧协议兼容映射放入[公共运行与交互契约](p01-runtime-contracts.md)。这是后续适配器的代码契约，不表示P00全部设计或真实执行能力已完成；下述语义基线及各阶段实测要求继续有效。

[验收样例](acceptance.md)提供合成输入与预期，P00只检查样例结构、关联和自洽性。P01固定ID映射、版本兼容、事件状态和授权序列化；P02给出实际OS隔离证据；P06给出具体Review/Changeset持久化；P24验证DSH助手适配。实现可以选择更合适的私有结构，但不得降低上述语义；跨契约变更必须同步文档、相应MET和总表。
