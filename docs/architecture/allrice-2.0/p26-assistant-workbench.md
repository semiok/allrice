# P26：日常助手工作台

对应 MET-140 / MET-108，依赖 P25 的真实 DSH 治理底座。批次、PR 与验收顺序仍以 Linear 执行总表为权威；本文不是完成证明。

## 用户意图与生效边界

- 日常模式使用已有 Rice 主会话与工件工作台，不新增助手聊天产品。
- 只有已开放功能且员工明确拥有委派能力时，下一任务可选择有限助手。Boost / Teamwork 不开放，预告必须禁用并解释原因。
- `assistantPreference` 只表达 `daily` 和是否允许助手，不接收客户端预算、工具或权限。服务端生成有界配置；Worker 再校验冻结能力与当前授权。
- 输入框只配置下一项普通任务，不改变活动 Run、审批、审查反馈或问题回答。旧客户端不带该字段，仍走原单 Agent 路径。
- “本次不使用助手”被保存成该任务的硬约束。根用户文本开头明确独立的“不使用助手”等指令也能收紧此约束；附件、引用、历史及模型输出不参与解析。自然语言不能自行提高权限或开启尚未发布的模式。
- 请求幂等摘要包含选择。相同输入 ID 的不同选择必须冲突，不能复用旧收据悄悄修改任务。

## 展示与操作

- 读取 PostgreSQL 中实际的根/父/子 Run、原生 Session、消息、结果、预算和停止确认；不由工具标题、动画或浏览器内存推算成功。
- 主聊天显示真实助手数与摘要，展开查看分工、结果来源、失败、耗用及工件；需要处理的异常/审批不能仅存在于默认折叠内容里。
- 区分消息已接受、已落盘、结果收到、父模型已采用；“请求停止”和“执行端确认停止”分开。部分失败不能被显示成全部成功。
- 停止单助手与取消整项任务是不同操作。整树取消经 P25 durable tombstone 关闭后续准入；迟到消息不能唤醒任务。
- 关闭新功能只禁止新准入，不能抹去历史、隐藏待处理事项或阻断取消。刷新/切换会话时丢弃过期请求，恢复权威状态。
- 所有新写接口校验同源、用户/租户/工作区/会话所有权、严格输入与请求 ID；不把用户提供的 child ID 当作归属证明。

## 验收要求（实施后追加结果，不用本文代替）

契约与展示测试之外，必须通过真实数据库与原生 DSH 验证：无需 Bridge 的至少两个真实并行只读/分析子任务；简单/串行任务不乱拆；用户禁用、权限收回、预算不足；消息重复/迟到与刷新恢复；部分失败与带来源的结果归集；单助手取消和整树取消。最终固定候选版本的联合验收归 P27。
