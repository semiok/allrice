# MET-159 PR3：Bridge 配对即用

新安装配对、已有配对设备升级后，独立浏览器、文件/Diff、已有本地沙箱和项目预览默认进入准备流程。普通成员不需要先在 Mac 启用、再到网页授权。显式关闭的设置继续保留；暂停连接会持久化，重新打开或升级应用不会自行恢复。

## 复用范围

沿用现有 Bridge 配对、目录选择器、持久凭证、操作账本、原生 Chromium 启动器、网络代理、项目预览转发、固定容器工具链、DSH 工具入口及具体动作审批。协议仍为 v2，新增可选环境报告；没有另造 Shell、浏览器驱动或权限存储。

- 独立浏览器：实际启动并观察空白页，完成关闭检查后回报准备结果。服务端为配对成员自动建立公共 HTTPS 使用关系；既有站点范围和显式撤销记录不会被覆盖。
- 本地计算：复用已安装的 `allrice-b2` 沙箱。自动恢复该专用 VM，必要时下载固定摘要的 Node 镜像，再验证架构、镜像和运行时隔离。文件与浏览器不等待 VM 准备。
- 无本地运行环境：命令工具回报未执行，并向员工提供现有 `cloud.process.execute` 的承接路径。仅适用于不依赖本机进程的计算；本地输入须由当前任务选择，结果沿用交付成果和 Diff。不会把本地服务或项目预览伪报为云端等价完成。
- 项目预览：浏览器和本地计算都准备好后可用，沿用当前任务启动的服务和已有预览授权链路。
- 退出与更新：按实际浏览器、命令和后台服务是否结束判断，不再因为浏览器开关开启而禁止升级。未确认浏览器关闭时，不返回已安全暂停。
- 界面：Mac 状态和工作台显示准备中、可用、已暂停或实际缺项；Mac 可重试准备，缺少 Chrome 时可打开官方下载页。

## 兼容与用户选择

旧客户端仍能使用原有精确站点授权，不会因心跳在线获得新公共浏览器能力。新公共授权只有新客户端持续报告准备完成时可执行；旧版本回连、准备失败、暂停、离线、撤销都会阻止相应后续执行。心跳不改用户角色、员工权限或配额。普通成员可以管理自己设备的浏览器授权；不能操作他人设备。

已有配对、目录、执行日志和凭证路径不迁移。新配对重新建立自己的默认偏好。历史显式关闭、撤销继续有效。默认浏览器不持久保存登录资料；需要长期保存的精确站点授权继续沿用现有路径。
