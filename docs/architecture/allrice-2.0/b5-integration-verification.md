## 集成测试实际发现并修正的问题

1. **审批期间导航提前结束**：点击需等待其实际导航信号，不能依赖固定短延时推测请求已经发起；等待批准时父操作维持心跳，拒绝或关闭后的迟到批准不能重新发送。
2. **审批正文与实际正文不一致**：Playwright 返回缓存 Buffer。直接清零借用的 Buffer 会将真实 POST 变为空字节。审批摘要与预览 relay 各持有自己的副本，只清零自己的副本。回归同时核对摘要、长度及实际接收原文，不能仅检查成功状态或写入次数。
3. **工件存储配额锁反序**：八个新增容量入口使用同一组织/工作区配额锁，先取配额锁再进行权限检查和写入；保留 pending + ready 容量计算、租户隔离和组织范围上传兼容性。并发两份单独能放下、合计超限的工件必须只有一个成功。
4. **浏览器状态与父操作心跳锁反序**：从服务器已保存、同租户/所有者的不可变绑定解析目标，按 root → operations → controls/browser 取锁并复核。四个真实 PostgreSQL 并发握手覆盖状态查询、投影、审批请求与审批决定，不通过重试或削弱短租约掩盖死锁。
5. **历史 Run 打开预览后面板未刷新**：服务变更通知对应 Run 的浏览器工作台重新读取，避免只能刷新整页才看到待启动预览；不伪造设备启动 ACK。
6. **测试时间与环境依赖**：观察时间和到期时间采用同一测试时钟采样，避免偶发 60,001 毫秒超限；数据库测试只允许明确的本地独立库或 CI 独立库。生产时效限制不放宽。

失败报告保留；后续通过报告不能把先前失败、跳过或未覆盖场景改写为通过。

## 证据分层

- **单元与真实 PostgreSQL**：契约、权限、账本、状态机及并发。CI 不具备真实 macOS / Keychain / VM 时，这些原生门禁明确跳过，不能计入已通过数量。
- **真实隔离 Chrome UI + Next + PostgreSQL**：验证工作台、管理页、历史刷新和审批展现。合成会话签发不是密码登录；合成服务数据不是实际设备执行。
- **原生执行链**：HTTP 权威、数据库、设备 SQLite、实际 VM 服务和实际独立 Chrome 联测。检查批准前零副作用、批准后精确正文、拒绝后零写入、断连/停止后的进程与容器清理。
- **实际 App 包**：从最终源码分别构建 Intel / Apple Silicon 包，绑定 ZIP、Core、Host、Launcher、Playwright runtime 摘要。候选包不能代替最终 main 包；独立 SEA 探针不能冒充 GUI 配对测试。
- **实际 Dev 发布**：既有 Snow 账号登录、至少两段既有历史、Bridge 打开/手动刷新一致、两架构鉴权下载返回实际 200 和正确全量字节摘要，再核服务身份与数据保护摘要。

各层测试不能互相替代。没有调用计费模型的测试不得称为真实模型端到端验收；这些测试也不证明所有第三方站点、MCP Server 或项目均兼容。
