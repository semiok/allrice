# P13 / B4：Keychain 非交互排查与凭证一致性候选

2026-09-09。基线 `642d8f335fd66bc0c9ac260e0e5d626c8ad04cf4`，候选分支 `codex/b4-keychain-diagnostics`。本补丁仍属于 B4，不进入 B5；未合并、未部署、未替换当前 `0.4.0-dev.1` 下载包。上线前必须补目标 Mac 的原生实测。

## 证据与不能下的结论

9 月 8 日最终 Intel / M5 原生菜单和配对测试通过，但新配对均使用私有文件回退。之前对随机合成设备的 Keychain 复现返回 security 退出码 36，并报告 `User interaction is not allowed.`。这只能证明当时的启动会话不允许交互，不能推断解锁后从 Finder 正常启动一定成功或失败，也不能把文件回退说成 Keychain 成功。

Apple 将 [errSecInteractionNotAllowed](https://developer.apple.com/documentation/security/errsecinteractionnotallowed) 定义为不允许与 Security Server 交互。本补丁不解锁钥匙串、不修改 ACL/TCC、不获取个人密码、不通过设置 Always Allow 或更换默认钥匙串来让测试通过。

## 本次有界修正

- 所有 `security` 调用设置 5 秒 timeout、64 KiB 输出上限，等待实际子进程结束后再返回；超时只终止本次创建的 `security` 子进程，不触碰系统钥匙串服务。不是只用 Promise.race 放弃等待、留下迟到写入者。
- 只对已核对的退出码与文本组合分类：交互不允许、条目不存在、超时、不可用。stderr、argv、token 和原异常 cause 不进入 UI、日志或诊断。输出超限不能误报为超时。UI 解释是最近一次访问/保存记录，不宣称每次打开状态窗都会探测或修复 Keychain。
- CLI 只有配置文件确实不存在才进入首次配对；已有配置的解析错误、凭证缺失/暂不可读不再消耗新的配对码、覆盖身份。
- 新配对使用配置文件旁的独立 `0700` 凭证目录，每个设备一份 `0600` 来源记录。Keychain 来源记录不保存明文 token，并校验已保存 token 摘要；文件来源只读取本设备记录，不让之后可读的陈旧 Keychain 项覆盖它。Keychain 来源暂不可用时拒绝启动，不复活陈旧 legacy token。
- 已有设备凭证不隐式轮换或自动切换存储源。新设备的写入不能在配置提交失败时污染旧设备。显式迁移仍是待设计/验收事项，不借此引入跨 Keychain 与文件系统的假事务回滚。
- 旧的 `config.json.token` 只读兼容限于落盘配置中的同一 deviceId。读取不触发迁移、修复权限、删除或写入。非本人、非 `0600`、软链接/硬链接、非普通文件或过大文件均拒绝使用；不能先读取不安全文件，再仅在 UI 上警告。
- 新文件先在私有目录内以独占临时文件写入、同步，再原子替换。拒绝不安全的原目标，不自动 chmod 父目录，不以失败清理删除旧凭证或他人替换的文件。这些检查不宣称防御拥有同 UID 任意进程控制权的攻击者。
- 远端确认撤销后，本机清理的成功/部分失败单独返回；不能因 Keychain 暂不可删而用已失效 token 重试远端撤销，也不能把部分清理说成所有本机凭证均已删除。清理失败保留待核实提示，不绕过系统权限。

## 验证边界

不依赖桌面的验证包含：隔离文件与 mock Keychain 的来源/身份/失败路径；使用真实 Node 测试子进程验证 5 秒超时和输出超限确实结束进程；真实桌面 Core 子进程读取合成设备文件、状态/诊断输出及安全退出；Intel / ARM Swift 类型检查。这些都不等于真实 Keychain 成功保存。

所有测试只使用临时目录、合成 token 与自有子进程；系统 `security` 不作为模拟测试的执行目标。模拟端口只存在于测试文件，不添加生产环境 override。

## 下一次实机门禁

1. Mac 解锁后以普通 Finder 启动独立候选 App，不沿用 SSH/自动化受限启动作为成功路径的替代。
2. 只使用随机合成账号和隔离配置；确认实际 Keychain 写入、读取、正常退出及再次打开均成功。检查文件中没有回退 token，诊断中没有秘密。
3. 分别核对 Intel 和 M5；其中一台通过不能替代另一台。保留用户拒绝授权、锁屏或受限会话的负向路径。
4. 验证已有私有文件配对仍能使用；不自动迁移、不强迫重新配对。显式旧凭证迁移尚未实现时必须保留未验标记。
5. 验证撤销的远端结果与本地清理结果分别准确，失败不删除日志或宣称成功。
6. 固定候选版本通过后才提交发布判断、重建对应版本的 Bridge 包及更新 Dev 下载；不拿当前已发布旧 ZIP 当补丁的实测证据。

## 已知保留限制与回滚

撤销成功响应中的 `serverRevoked`、`cleanupComplete`、`configDeleted` 分别表达远端撤销、本机完整清理和配置删除结果，`ok: true` 不等于本机全部清理完成。桌面 `credentialCleanupPending` 目前只保留在当前 Core 进程内，重启不恢复，也没有新增清理重试入口；重新配对后提示明确指向此前操作的旧凭证，不误称新设备已经撤销。完整原生 UI 的部分清理路径仍需实机验证。

当前仍调用 `security add-generic-password -w token`，token 在该子进程 argv 中的既有风险没有被这次错误脱敏解决。原生 Security API 替换需独立审查及双架构实测，不用交互式 shell 拼接或变更系统权限临时绕过。

Keychain 实际成功、显式凭证迁移、正式签名/公证/升级回退均不能在本轮非交互测试中签字。新设备来源记录是新的本地格式：不要把它删除后强制退回旧读取器；旧二进制不理解新的文件来源记录。候选尚未发布时可保留源码而继续运行现有版本；未来发布后的回滚必须保留新格式读取兼容，不能让旧 fallback 再次成为权威。
