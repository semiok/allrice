## 合并前修复

独立审查发现 `executeEmployeeRun` 先按当前 router 选择做额度准入，再复用同 run/attempt 已持久化的路由。
当前选择与历史路线不同时，可能错误地用订阅准入跳过实际 API 路线的未知费用门禁，反向也可能误拒订阅。

现在先恢复持久路由对应的精确 frozen target/connection/credential，再按实际连接做唯一准入并保留 Provider 治理检查。
新增七项真实 PostgreSQL/生产 Worker 回归覆盖双向重放、未知 Token、kill switch、未发布连接、身份错配。
未调用外部模型或读取真实凭据；router/adapter 为受控替身，不冒充真实 provider 实测。

沿用现有派发前失败收尾：被拒的持久路由记为 failed，实际 Token/费用为已知零，计入一次失败尝试；旧未知费用回执保持原值。
这不是把已经派发但未知的用量清零，也未增加另一套状态机或迁移。
