# MET-159 PR4：员工代办应用连接

## 用户行为

已发布员工包含 `cloud.mcp.call` 时，普通成员可以让员工连接一个支持 HTTP MCP 的应用。员工提交服务名称、公开 HTTPS 地址，Worker 使用 DSH 原生客户端发现真实工具。匿名服务可以直接使用；私有服务提示用户打开「已连接应用」，通过应用登录或专用凭据表单完成接入。聊天输入和模型工具参数不接收密钥。

完成登录且发现成功后，系统通过既有原生问题回答机制唤醒原任务。同一任务可以立即调用新应用，无需提权、重新发布员工或重开会话。用户主动取消、断开或删除后，不会被员工后台自动重新连接。普通成员可在 `/workspace/mcp` 查看状态、登录、断开、恢复和删除；原本地 MCP 高级管理保留给管理员。PR5 再将此组件接入 MET-160 的统一 Settings，不另写设置框架。

## 复用与适配

- 原生包：`@deepseek-ai/dsh-mcp-client@0.1.5-rc.3`，源码 `a4c74a91e06b00fe0b0937bde982170c526cc842`。先完成未补丁发布包的匿名发现、真实 HTTP 调用闭环；无模型调用。
- 原生发现、工具名、schema、ToolRuntime 执行及输出继续由 DSH 负责。官方 MCP SDK 处理 OAuth 元数据、动态注册、PKCE、回调换码与刷新；Allrice 只提供加密的持久化端口。补丁只增加 HTTP fetch/authProvider 注入、关闭重连。
- 复用 connector binding、discovery lease、employee binding、运行操作账本、typed User Questions 和持久化等待。没有第二套 Agent 主循环、凭据系统或等待调度器。
- Migration `0107` 增加成员归属、认证状态、断开/删除标记及原任务连接请求。已有共享 SDK 连接保持兼容；新成员连接才使用 DSH 原生工具名。
- 新工具在每次操作提案时从当前数据库取真实定义并冻结到操作；不修改历史 Run 快照。仍使用已发布员工能力、当前成员身份和现有具体动作审批。成员撤权、连接断开、重新连接和凭据变更均使旧审批失效。

## 验证与实际边界

本地数据库采用独立随机 schema，HTTP MCP/OAuth 服务、用户和模型端点均为可控测试夹具。没有创建 Dev 测试员工，没有使用真实模型配额。

- 原生客户端：匿名、Bearer、真实 HTTP 执行、执行前撤权、丢失写响应不重试。
- 数据库：当前任务接入并调用、他人私有连接隔离、共享连接按成员断开、删除清除个人凭据、旧审批不得复活。
- OAuth：官方 SDK 完成发现、注册、PKCE、单次且绑定当前用户的回调、换码和刷新；密钥不进入输出。
- 原任务等待：连接成功只提交一次原生 typed answer；真实 DSH 子进程释放后恢复既有任务，不重放连接操作。
- 浏览器：真实 Chrome 验证连接、登录、断开、删除及状态刷新保留现有页面，不在稳定状态持续轮询。
- HTTP：普通成员访问、跨站请求拒绝、消息限长、服务端回调地址、拒绝任意执行/授权字段和隐藏底层凭据错误。

第三方服务仍需实际提供可访问的 HTTP MCP 地址。OAuth 服务需要支持官方 SDK 所支持的注册/认证方式；需要固定厂商客户端登记的服务仍有相应接入工作，可按服务支持情况使用专用 Token 表单。未提供真实第三方账号的服务，不宣称已完成其账号验收。MCP 不保证返回账号邮箱，界面如实显示服务、个人/共享归属和连接状态，不捏造账号身份。Bridge 本地服务安装与多格式传输不属于本 PR。

Dev 部署必须基于当时正在运行的 MET-159/MET-160 集成版本叠加，保留现有 Bridge 下载和 Office 服务。迁移不删旧字段；新托管连接启用后按前向修复处理。发布 SHA、CI 和部署验证结果在工单与 Dev release metadata 中记录；本 PR 不关闭 MET-159。
