# AllRice V1 core contracts

This document explains the executable schemas in `@allrice/contracts`. The package is authoritative; examples here cannot override code.

## IDs, tenancy and time

- Entity IDs are RFC 4122 UUIDs generated by a trusted server or PostgreSQL, never accepted as proof of authorization.
- Timestamps are ISO 8601 UTC/offset values at API/event boundaries and `timestamptz` in PostgreSQL.
- Business resources carry `organizationId`, optional `workspaceId`/`projectId`, optional `ownerId`, `visibility`, timestamps and an optimistic version.
- `private` means owner-only even for organization administrators. `workspace` and `organization` still require active Membership.
- Archive is a reversible state; delete/retention is defined per resource. Callers cannot silently treat archive as hard deletion.

## Request and execution authorization

`RequestContext` is constructed from a validated server session. Browser tenant, role and owner fields are ignored. Authorization follows this order:

1. require a human user actor for a browser request;
2. deny organization mismatch;
3. deny private content unless the actor is its owner;
4. require active Membership for the resource workspace;
5. apply role/action rules or an explicit policy grant;
6. emit an AuditEvent for sensitive allow and every deny.

`admin` manages tenant resources but does not inherit access to another user's private Chat, Memory or files.

`ExecutionContext` freezes the delegating actor, organization/workspace, Run, Job and PolicySnapshot. Worker authorization rejects expired snapshots, tenant mismatch, private-owner mismatch and absent grants. A Worker identity alone grants nothing.

## Queue state machine

```text
queued -> claimed -> running -> succeeded
   |         |          |----> retry_wait -> queued
   |         |          |----> failed
   |         |          |----> canceled
   |         |---------> dead_letter
   |--------> canceled

claimed/running -- expired lease --> queued
retry_wait -- attempts exhausted --> dead_letter
```

- Claim uses a database transaction and a unique lease token.
- Heartbeat may extend only the matching, unexpired lease.
- Recovery to `queued` requires lease expiry; ordinary callers cannot force it.
- `(organization_id, idempotency_key)` is unique.
- Retry uses capped exponential backoff. Terminal states never transition.
- Payloads carry `schemaVersion`; Workers reject versions outside the declared rolling-upgrade window.
- Irreversible external effects require their own provider idempotency key or a recorded compensation/approval boundary.

## Run, Event and SSE

- Run freezes PolicySnapshot, EmployeeVersion and DSH-native Skill snapshots before execution.
- RunEvent uses a UUID event ID plus a zero-based, gap-free sequence unique within the Run.
- A terminal event (`run.succeeded`, `run.failed`, `run.canceled`) forbids later events.
- Persistence commits the Run state and event in one transaction.
- SSE IDs are `<run_uuid>:<sequence>`. `Last-Event-ID` replays only later authorized events.
- Invalid cursors return `CURSOR_INVALID`; another Run/tenant returns not-found/forbidden without disclosing existence; cursors older than the retained window return `CURSOR_EXPIRED` and require a Run snapshot refresh.
- Heartbeat events keep intermediaries alive but do not change Run state.

## DSH-native Skills

`AllRiceSkillProvider` exposes only the enabled Skills bound to the frozen
employee Run. Tenant users cannot install or modify Skills.

Worker verifies checksums and required Tool references before initializing the
tenant-isolated DSH runtime. PostgreSQL snapshots are authoritative; DSH
provider caches are disposable.

## Storage

Object keys have the canonical form:

```text
organizations/<org>/workspaces/<workspace>/owners/<owner>/<category>/<object>
```

All segments are validated UUIDs or allowlisted categories. API values never expose host paths. Metadata is authoritative for ownership, checksum, MIME, size, retention, deletion and immutability. Local-mount and S3-compatible adapters implement the same `StoragePort`.

Signed access binds object, subject, operation, expiry and nonce. Authorization happens before signing and again when an application proxy serves the request. Deleted/expired objects cannot be signed.

## API and migration compatibility

- HTTP is namespaced under `/api/v1`; errors use the canonical envelope and stable codes.
- Contract schema version 1 is the only supported V1 payload version.
- Web and Worker rolling upgrades support versions listed by `CompatibilityPolicy`; adding a version must precede producing it.
- Database migrations are ordered, forward-only in production and must use expand/migrate/contract for destructive changes.
- A rollback means deploying the previous compatible image; down migrations are development/test aids, not the production recovery strategy.
- Old Job/Event/Artifact data remains readable for the documented compatibility window or is migrated before contract removal.

## External integration boundary

AllRice remains authoritative and independently runnable. Reviewed external
systems may integrate through versioned APIs, signed short-lived tokens, events
or explicit connectors. Shared database tables, migration history, ORM models,
credentials and runtime directories are forbidden.
