# 第二批租户验收缺陷修复（2026-10-01）

本次修复来自 Dev 租户视角的真实验收，沿用当前固定的 DSH 引擎、原生 Office 指南、Python 库和检查器。

## 提交与排队

首条消息已提交，但 Worker 尚未创建或领取 native runtime 时，原准入只看到空闲 runtime，第二条消息会立即执行并报 `CONVERSATION_BUSY`。现在准入在已有 Session 锁下检查已接受且尚未结束的 Run，启动窗口中的追加消息也进入已有的持久队列。

首轮在 native runtime 建立前失败或取消，调度器仍可领取一个 FIFO 后继；其它后继保持排队。消耗或拒绝补充资料消息时，同步结束其临时 Run 的权威任务时钟。

并发准入原本包含已领取的当前 Run，却仍按“新增一个 Run”检查，实际三个名额会拒绝第三个。现在只排除与公司、工作区和员工身份匹配的当前 Run，排队消息不占执行名额；并发上限本身保留。

## Office 修改与交付

验收中的前两次 Excel 修改失败来自模型脚本调用不支持的 `RowDimension.to_tree` / `NamedStyle.to_tree`。Office 1.3.2 仅补充局部修改的接入说明：复用原生 load/change/save/reopen，检查所改数据、公式和格式，避免序列化所有库内部对象。上游资源和检查器未修改。

用户重新上传历史文件后，上传对象没有版本信息。现在允许显式选择同一 Session 的历史成果作为父版本，但必须通过原有权限验证且字节校验值相同；来源仍登记为实际上传对象。不同文件、跨用户或跨公司引用不能附着到旧版。

本轮某类文件的最后一次实际导出失败，即使模型最终回复正常结束，Run 仍标记 `DOCUMENT_DELIVERY_INCOMPLETE`。模型自行修正并收到成功导出回执后才解除该状态，历史下载不冒充新文件。

## 原生模型恢复与状态

长资料继续任务的日志包含明确的 provider 失败结束回执、持久结算 ACK，以及 DSH 的下一次重试。原接线因之前已有部分模型输出而阻断新请求。固定版本 DSH 对失败回复记录 attempt，不提交正常 assistant message，也不执行其中的工具调用；重试由原生 agent loop 决定。

现在明确的可重试失败结束回执获得持久 ACK 后，允许 DSH 使用新的 call ID 继续。缺少结束回执、缺少 ACK 或未知执行结果仍保持原状态；不重放工具和已发生的外部写操作。用量未知仍按未知统计。

`llm/retry` / `llm/retry-started` 接入现有工作过程，显示“正在重新连接模型”；后续文字或思考事件到达后结束该状态。过滤 provider 消息、原始参数和私有推理。已结束为失败的流不会显示“恢复响应”。

## 验证范围

- 针对性单元验证：原生准入、等待结束回执、重连展示、文件交付回执、Skill bundle 完整性。
- 独立 PostgreSQL 验证：启动前排队、失败后 FIFO 推进、重新上传文件版本链与来源、越权和不同字节拒绝、补充消息时钟、并发名额。
- 全仓构建、类型检查、格式和 lint；完整普通测试首次有一条 5 秒超时，单独复验 36 项全部通过。
- 合并后通过 Dev 租户页面复验，具体 Run、下载文件和部署 SHA 记录在本机验收报告中。

慢响应样本的 native 日志包含 `fetch failed` 和 `terminated` 后的重试，不能把这次九分钟等待仅归因于上下文大小。网络和上游时延不承诺由此次代码修复消除。CSV 输入扩展、自动压缩实测和全面容量测试不计为此次已完成项。
