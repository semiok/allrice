# MET164 PR6a：文件调查与原字节整理

用户可在已选 Bridge 文件夹内查找文件、按原字节查重、比较两个子目录，然后审查复制、移动或重命名的清单。文件整理复用现有 Changeset 成果、应用请求、精确审批、Run、Worker 与 SQLite journal；不是另一套队列，也不把二进制文件假装成空文本删除。

`local.fs.list` 的可选 `survey` 执行只读调查。文件名、扩展名、大小与时间用于筛选；调查最多2000项、24层和128000000哈希字节。重复组按内容与大小识别，目录比较保留缺哈希、未完成或跳过的未知项。版本来自原生调查，不与 PR3 `local.file.inspect` 的版本混用。普通列目录和旧文本 Changeset 保留原契约；旧客户端不会领取调查与二进制整理任务。

整理提案由 `workspace.export.create` 的 `kind:changeset`、`format:json` 发布。`operations` 保存源路径、目标路径、copy/move/rename、调查的 checksum/version/sizeBytes 与 `expectedDestination:null`；服务端绑定真实目录授权和不可变成果。目标父目录必须已有，每次最多32项、单文件9000000字节、总计128000000字节。不覆盖目标，不支持永久删除、交叉路径、循环移动或跨目录授权。

固定 macOS FileGuardian 以 openat、原文件身份与原字节 CAS 检查源，拒绝符号链接、敏感及依赖缓存路径。复制先写独占暂存、fsync，再原子 create-only 提交并读回目标；移动只有在目标确认之后才隔离、复核并删除原源。跨卷走原字节复制，而非假定 rename 跨卷可用。批次逐项执行，不承诺批量原子性。

既有 prepared checkpoint 在副作用之前落盘。源变更在所有源的预检查或原生提交检查中报冲突；发生未知效果时停止余项，保留已确认项、原文件与相关恢复位置，不自动重做。服务端核对每份回执的顺序、数量、路径、源 checksum、目标、操作、大小、阶段与终态；不能把缺项、pending、unknown 或目标不符的报告登记为成功。恢复只对已确认移动/重命名生成反向计划，使用回执中的实际目标版本，仍要求原位置为空；复制件保留。

Bridge 只在嵌入构建的 FileGuardian 哈希、单一CPU架构、签名、文件类型、owner与权限均相符时报告调查/整理能力。目录授权、普通员工冻结配置、设备就绪、当前 lease 和撤销检查仍在原接入链上；撤销、stdin EOF、监督器退出、取消或30秒原生上限终止实际子进程。原目录选择并非操作系统沙箱，不能声称同 UID 的外部进程无法改文件。

PR6a 包含调查与整理。ZIP 字节解析独立留给 PR6b 的受控传输与成果接入；PR7 的 PDF/图片以及 PR9 的目录触发不在本次提案契约内。Windows 暂缓。原生 Intel/M5 与真实跨卷证据、服务端数据库和正式包的 Dev 验收分别记录，原生单元通过不代替普通员工交付。
