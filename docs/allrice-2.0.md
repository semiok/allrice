## 1. 产品定位

AllRice 2.0 是企业 AI 员工工作台：员工通过网页向 Rice 交付任务，Rice 在同一个 Session 中使用已授权的云端或本地环境完成工作，并通过工件、Diff、审批和执行证据交付结果。Bridge 是可选的本地执行端；不安装 Bridge 的租户仍有完整的云端业务闭环。

学习 Antigravity 的远程执行与成果协作体验，采纳 Cline 的审批、Diff、MCP 生命周期和可恢复修改设计研究；运行时仍基于 AllRice 的租户治理与 DSH Harness。独立产品定位不变。

用户应能回答：Rice 正在做什么、在哪里做、用了什么资料、哪些动作需要我处理、成果是否真的可用、停止或掉线后发生了什么。普通员工通过网页和图形化 Bridge 即可工作，不以自己维护终端窗口为前提。

## 3. 2.0 GA 与后续边界

**GA：Rice 在同一 Session 中安全地使用获准的本地或云端环境完成真实任务，交付可审查、可追溯、可继续迭代的成果；具备可用的客户端、浏览器和基础并行助手体验。**

四条任务线必须分别实际验收：

1. 本地开发：网页授权 → 计划/成果反馈 → 精确 Diff → 写入 → 测试/修复 → 受控开发服务实际可达预览 → 交付；验证取消、掉线、文件冲突与未知结果。
2. 无 Bridge 云业务：合成输入 → 澄清 → 云端清洗对账 → 与确定性参考结果核对 → 下载并重开文件 → 临时环境销毁后仍可访问；人工审核规则/经验后下一任务实际采用新版本。
3. 浏览器工作：本地独立 Profile 与云端受管浏览器分别验证真实操作、权限、上传下载、登录隔离、人工接管与撤销。
4. 基础助手：无 Bridge 时至少两个受控助手完成分工、汇总证据和工件；任务树、预算、部分失败、取消、恢复、产物冲突和不可用模式拦截可验证。

横向门禁还包括 Apple Silicon 与 Intel 对应客户端的实际安装/使用/更新回滚、旧 Bridge/Session 兼容、租户隔离、真实用量与冻结配置。平台、证书、服务或场景未测时标未验证，不能拿另一平台或另一条任务线代签。

不进入本次 GA 的完整能力：Boost、Teamwork、正式员工 Handoff、开发协作增强、自动批量经验晋升、Hooks/Sidecars/插件自动执行、任意交互式 PTY、通用公网隧道、完整 VCS 管理、会话 fork 产品功能与浏览器 Push。少量语义预留不等于实现承诺；基础助手完成也不等于整个 MET-108 可关闭。

## 4. 关键术语与责任

| 名词                 | 产品含义与不可混淆的边界                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------- |
| 租户 Workspace       | 企业数据归属与成员权限空间，不是电脑目录                                                    |
| Project              | 组织任务与资源的上下文；不能作为目录访问授权                                                |
| Session              | 连续多轮协作的会话；下一轮可按现行规则采用新发布配置，不代表热改已入队 Run                  |
| Run / attempt        | 一轮执行及其执行尝试；冻结配置与授权依据，恢复时核对租约和副作用；不是每个工具都新建 Run    |
| 逻辑步骤             | 任务拆解中的可追踪工作单元；可关联多个操作或助手                                            |
| Operation / 工具调用 | 一次有目标、输入和授权依据的动作；领取、实际执行与结果确认分别记录                          |
| Agent 实例           | 执行角色与上下文主体；同一个助手可做多个步骤                                                |
| 后台进程             | 在实际目标存活的操作系统进程；已启动不等于任务成功                                          |
| Artifact / 工件      | 独立交付结果；复用现有 Artifact、DeliverableVersion 与 StoragePort 的关联，不另建孤立成果库 |
| Changeset / Review   | 精确版本的文件修改集 / 对工件或计划的审查；满意、提交修改意见与执行授权是不同动作           |
| Execution Target     | 动作的实际执行位置；与模型 Provider、资料出端路径、Project 和工作副本分开                   |
| Bridge               | 执行获准本地动作并回报证据的设备端；不是另一套租户 Agent Loop                               |
| Skill / Memory       | 版本化任务方法和资源 / 有来源与作用域的持久知识；不替代工具权限与执行隔离                   |
| Handoff              | 未来跨员工任务移交；不是开发时 Codex 与其他模型的协作安排                                   |

ChatFlow 负责工作台与会话控制表达，Runtime Console 按租户提供运维可观测性；Worker 协调持久任务与运行恢复，DSH 承担模型/工具循环，Tool Broker 及执行端共同执行授权与隔离。`@allrice/contracts` 是跨边界可执行类型的权威；PostgreSQL 是业务状态权威；StoragePort 承载内容；SSE/WSS 是传输，不是另一套任务账本。

## 5. Bridge 可选与端云工作范围

| 设备/授权状态           | 本地行为                                         | 云端行为                                                     |
| ----------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| 未配对或无可用 Bridge   | 不能访问本机资源                                 | 独立获准云能力正常可用；需要本地资料时说明配对或受控上传     |
| 已配对但离线            | 不发新本地动作；已发动作可能仍在运行，结果待核实 | 独立云步骤继续；依赖本地输入的步骤等待，不静默搬运资料或重跑 |
| 在线但未选工作区/缺能力 | 连接可标绿色“Bridge 在线”；具体缺失另列          | 不把连接状态误当文件/命令权限；云端按自身授权继续            |
| 在线且目标权限有效      | 在指定目录、环境和预算内执行                     | 可以与本地协作；按步骤选址，不强制全部本地或全部云端         |
| 撤销或停用              | 拒绝新动作；取消请求与执行端停止确认区分         | 不转云绕过禁令；独立有效的其他云动作另行判断                 |

真正修改用户电脑文件、控制本机进程、使用本机工具或仅该环境可达的服务必须在目标设备执行。云端副本不代表原文件已修改。账号、政策、审批、任务协调、必要审计与获准持久交付属于 SaaS 基础责任。

转云需要明确的输入版本、数据传输/用途授权、目标能力和预算；本地动作结果未知时先核实，避免重复副作用。若只完成云产物、尚待本地落盘，显示部分完成与下一步，不宣称原地交付成功。关闭网页、设备断联、机器休眠与撤销授权不等价。

## 6. 实施、测试与交付责任

Codex在已确认范围与授权内独立负责技术选择（含高风险改动）、实现、自审、自测、修复回归和阶段技术验收；不设置 Gemini 或其他外部模型的前置确认。项目完成后由用户另行安排 Gemini 补充测试。

每个 PR 绑定范围、完整 SHA、风险依据、环境、实际结果、未测项和回滚办法。有可审内容即可 Draft，范围完成并通过适用验证后提交 Ready，不等整阶段完成。合并、部署与生产启用按实际授权分开处理。此次只提交 P00，既不合并也不部署。

研发分工不改变产品中的业务审批或独立核验要求。越权、数据丢失、重复副作用、核心验收失败、关键安全证据缺失仍阻断交付；构建或类型检查不代替真实功能测试。
