# MET-159 PR1：租户后台员工派驻

租户管理新增首个入口「AI 员工团队」。管理员选择工作区和已发布员工后可直接派驻，查看实际已派驻版本的技能、工具和当前可执行成员数；可撤回、设为默认或更新到新的发布版本。备注可选，操作自动记录真实管理员及目标租户。

## 复用与范围

复用平台员工目录、冻结发布包、`materializePlatformEmployeeRevision`、个人 assignment 和已有聊天/执行绑定；没有新目录或新权限框架。只读成员仍受原有入队角色检查约束，不提升成员身份。

`0106_tenant_employee_default.sql` 在现有派驻表上增加工作区默认标记，并依据已有个人默认分配回填一个默认员工；不改 assignment ID、会话或成果归属。后续新成员继承由 PR2 承接。

管理写入在同一事务核验管理员会话、目标工作区、发布版本和派驻快照，复用员工锁并按工作区串行化。重复派驻、撤回和设默认不重复创建版本/分配/管理审计。旧快照不能重新激活刚撤回的员工。

撤回使现有分配失效，保留历史。已纳入平台派驻的工作区在读取时不再自动创建 Rice 或激活旧个人分配；空花名册返回 `employees: []`，兼容字段 `employee` 为 null。明确创建新会话、继续执行旧会话仍需有效分配。尚未迁入平台派驻的旧工作区保留既有初始化路径。

## 与 MET-160 并行

基线为 #106 的 `9caac80`，独立分支 `codex/met159-employee-deployment`。本 PR 不修改 ChatFlow 侧栏、选择器、标签或前端 Workspace 类型。`employees[].id` 仍为个人 assignment ID，`employeeId` 仍为工作区员工 ID；已有字段含义不变。

双方共用 `packages/database/src/workspace/service.ts`：本 PR 为无员工时独立解析 `workspaceId`；MET-160 增加会话侧栏状态时，查询应使用这个 `workspaceId`，不要再解引用可能为空的 `assignment.workspaceId`。合并时保留双方查询与会话字段；Dev 部署以当时实际已部署 SHA 为基线，禁止覆盖对方已部署增量。

## 验证

- 独立 PostgreSQL schema：普通成员获得准确发布包及技能，真实创建会话并冻结执行快照；无模型请求。
- 并发重复派驻、版本不匹配、跨租户目标及失效管理员会话。
- 默认切换、默认员工撤回、最后员工撤回、历史读取和旧 assignment 不得绕过撤回。
- 只读角色不能入队；不会为了派驻创建管理员的目标租户成员关系。
- Chrome → 实际 HTTP handler → 独立 PostgreSQL：空备注派驻、设默认、撤回、刷新及 390px 窄屏。
- 回归现有员工发布、Skill 冻结、租户管理和旧员工会话兼容。

迁移是向后兼容的增量列及索引。回退使用上一份应用发布，保留已发生的派驻/撤回事实与历史数据，不删除列或恢复旧授权。

PR2–PR5 的持续继承、云端默认权限、Bridge 自动准备、员工代办连接与工作台收敛尚未交付；不能据此关闭整个 MET-159。
