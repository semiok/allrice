入口：Runtime Console → **租户管理**（`/runtime-console?view=tenants`）。平台管理员明确选择租户/工作区后，可查看现有成员、修改角色和启停成员授权，并填写修改原因。保存后重新读取数据库；切换租户时清空旧数据/表单，未保存表单需确认放弃。

## 真实权限与数据路径

- 复用 `allrice_organizations/workspaces/memberships/users/sessions/audit_events`，不新增权限事实源，不需要数据库迁移。
- 平台管理员复用服务端 `ALLRICE_PLATFORM_ADMIN_EMAILS` 的身份判定，并核对有效账号、真实会话及登录租户/工作区。租户 `role=admin` 不等于平台管理员；Runtime Console 事件入口也统一校验。
- 管理操作者保持自己的身份和登录上下文，目标租户/工作区是独立参数。不会创建管理员在 Snow 的临时 membership，也不会冒用 Snow 身份。
- `GET /api/v1/admin/tenants`：游标分页读取租户与工作区。
- `GET /api/v1/admin/tenants/:organizationId?workspaceId=...`：游标分页读取成员；选定工作区时也明确显示适用的组织级授权。
- `PATCH /api/v1/admin/tenants/:organizationId/members/:membershipId`：严格结构化输入、同源 JSON、8 KB 请求上限、成员归属/范围校验、数据库版本冲突检查、事务内审计。
- 授权范围不可在此次修改中偷偷切换；修改组织级成员会影响全部工作区，界面保存前明确告知。停用某条授权不等于禁用整个账号，其他有效授权仍可能允许访问。
- 同租户成员变更锁定组织行，保护最后一位有效管理员；并发修改返回冲突而非覆盖。审计保留实际操作者、目标成员、前后值、原因及设备权限未变的记录。
- 登录 bootstrap 只初始化新用户/新租户，不覆盖已有名称、角色或启停状态，不复活已删除成员关系或已停用账号。既有会话的后续请求重新读取当前授权。
- 请求结果未确认时不自动重发写操作；界面提示刷新核对。

## 验证

新增三层回归，无需真实模型或设备：

1. 服务端权限和 HTTP 单测：匿名/非平台管理员拒绝、目标参数独立、跨站拒绝、输入上限、并发冲突、错误脱敏。
2. 独立 PostgreSQL：角色修改与审计、重新登录保留配置、停用/删除关系不复活、过期/撤销会话与停用账号、归档工作区、跨租户/工作区拒绝、并发修改/最后管理员保护、首次初始化并发幂等。
3. Chromium → 实际 HTTP handler → 独立 PostgreSQL：保存并刷新、重新登录后角色持久化、无冒用 membership、跨租户表单切换、390 px 窄屏、跨站及租户管理员请求拒绝、503 写入失败后的手动核对。

CI 的 `tenant-workbench-browser` 增加临时 PostgreSQL 服务并显式执行新增集成用例；普通单元测试跳过依赖数据库/浏览器的集成套件，不能把跳过计为通过。
