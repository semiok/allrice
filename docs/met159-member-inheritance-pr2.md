# MET-159 PR2：成员持续继承与云端能力默认可用

后来加入的普通成员直接获得工作区已派驻员工的准确发布版本、默认员工及相应云端能力。无需重新发布员工、逐人授权浏览器或提升为管理员；成员修改的备注改为可选。

## 复用与行为

复用工作区派驻、成员关系、个人 assignment、冻结运行包、运行策略与既有云端授权表。`synchronizeTenantEmployeeAccess` 是发布、接受邀请、成员修改和平台环境恢复共用的同步入口，不增加表或新权限体系。现有成员会在 Worker 启动后的环境准备中补齐。

- 邀请加入、组织级或工作区级成员资格按实际作用域继承；只读成员不获得执行分配，不改变成员身份。
- 成员降为只读、移除、员工撤回或归档后，旧会话及执行绑定不能继续新调用。重新激活成员沿用原 assignment ID；历史会话与已有冻结运行快照保留。
- 发布新版本同步当前成员与会话的下一轮版本；后台准备不重新发布、不新增员工版本。已有个人默认选择保留，新成员使用工作区默认。
- 发布可先完成，环境稍后恢复时自动准备使用关系；不因暂时没有云端后端而要求再次发布。
- 已有明确暂停的运行策略、禁用或撤销的资源授权、撤销的执行目标不会被自动准备恢复。只增加已派驻工具缺少的策略规则。

## 实际环境与默认访问

Worker 启动及每分钟复用现有 `CloudRunnerBackend.preflight` 和云端浏览器启动/观察链路。计算核验现有 gVisor 镜像、运行时与 watchdog；浏览器实际启动独立 Chromium 和现有固定地址代理。数据库保存实际报告并更新现有执行目标；超过 120 秒没有新报告的目标不再算可用。Readiness GET 只读状态，不创建授权或做探测。

已派驻 `cloud.process.execute` 或 `browser.workspace` 的员工对应成员自动获得现有类型的使用授权。云端浏览器新增 `public_https` 配置，允许公网 HTTPS 站点及跨站浏览，无需逐个登记网站；继续复用地址解析、私网拦截、隔离浏览器、具体写操作审批和个人账号归属。旧的明确来源白名单仍按原方式执行，摘要保持兼容；本地 Bridge 不接受这个云端配置，留给 PR3。

已有日常助手沿用 DSH subagent、现有冻结助手配置及当前权限检查，没有实现 Team、Boost 或第二套助手。移除成员或撤回员工后，助手后续权限核验也会拒绝。

本批仅面向现有同一云端执行后端；报告不提供多 Worker 资源池调度。执行开关被明确关闭时记录暂停/不可用，不伪装就绪。
