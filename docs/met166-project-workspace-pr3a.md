# MET166 PR3a：项目源码版本

`workspace.project` 经现有 DSH 原生工具适配器和 ToolBroker 保存、读取项目源码。模型传入源码数据或有读取权限的上传对象，不能传入宿主目录、租户身份、Shell 或执行位置。

每次保存完整源码、锁文件原始字节和来源引用，沿用私有 StorageObject / DeliverableVersion。新表只绑定当前任务的项目版本。`apply` 比较当前版本与完整 `before` 文本，源码版本和绑定在同一事务提交；重复调用返回原版本，冲突不会覆盖已保存的新版本。保存失败也不推进绑定。

| 操作                       | 行为                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| `open`                     | 从文件列表新建，或从确切快照恢复；返回项目与快照引用。                 |
| `list` / `read` / `search` | 读取指定版本，文本分页，搜索按字面匹配。                               |
| `apply`                    | 用 `expectedHead` 及完整 before/after 修改，保留未修改的源码和锁文件。 |

跨任务必须重新 `open` 指定的历史快照；跨会话恢复创建新的版本系列并记录来源，不修改旧会话的版本。每次操作检查普通员工身份、当前成员关系、冻结工具/能力、读取授权、任务截止及确切 Worker 租约。上传和恢复都检查实际字节、校验值和相对路径，拒绝路径穿越、大小写/NFC 碰撞、父子冲突和过期来源。

当前限额为 64 个文件、单文件 200,000 字节、源码总计 256,000 字节、快照 JSON 512,000 字节。文本操作只接受有效 UTF-8；二进制上传可保留并参与校验，但不能当文本编辑。依赖目录不属于源码。源码检查点可以通过原有文件下载接口读取，不进入业务交付成果列表或业务成果计数。

本 PR 只保存源码，不运行构建、测试、依赖安装或持续服务，也不会把容器写入自动认定为源码版本。PR3b 接入已冻结快照的本地执行，PR3c 接入同一安装器的云端执行；PR4 验证编辑、构建、测试、修复及正式交付，PR5 提供持续预览。

验证包括真实隔离 PostgreSQL 的保存、上传来源、版本冲突、幂等、权限及存储失败回滚，以及固定 DSH 子进程的原生工具参数往返。Dev 的普通账号跨 Run 恢复、下载及隔离验收另存于交付记录。
