# MET-151 PR-3：指定租户的环境、连接器与分层额度

基于 PR-2 #79（`14864dc`）提交独立审查。**本阶段不合并 main、不部署 Dev/Prod、不改变真实 Snow 的角色、500 万月额度、设备配置或服务端开关。** 不消费真实模型额度，不通过 SSH 操作 Intel/M5。PR-4 的真实租户执行与交付验收仍需单独完成，MET-151 尚不能关闭。

## 管理入口

Runtime Console → 租户管理 → 选择租户、具体工作区 → 环境与连接器 / 分层额度 → 选择实际使用者。

1. 使用真实平台管理员登录，不需临时加入 Snow 工作区；Snow 保持普通成员。
2. 环境页展示该使用者的 Bridge、已由本人选择的目录标签、平台云端目标及沙箱/浏览器授权。角色、员工版本、动作策略、部署开关、设备、工作区、沙箱、连接器等前置条件并列显示；旧租户能力卡仍保持原来的首个指引投影。
3. 后台可颁发固定 gVisor / 无网络云沙箱授权、限定 Origin 的云浏览器授权，以及指定设备的独立浏览器平台授权。目标来自实际租户注册表，不能输入任意 Runner、宿主命令或镜像。变更必须填写原因。
4. 所有者本人仍需在前台配对/选目录，在 Bridge 端启用沙箱、独立浏览器或本地 MCP。管理员不能替他生成配对凭证、改变本地开关、选目录、获取个人 Chrome Cookie。本地 MCP 只可引用该所有者已有目录授权和设备端凭证引用。
5. 云 MCP 复用原加密凭证、发现、工具授权及确切员工版本绑定；本地 MCP 复用原来源清单、摘要、目录代次与原生 opt-in。平台颁发人与资源实际所有者分别记录，运行期仍按真正执行者检查。
6. 撤销在执行开关关闭时仍可进行。浏览器停止与本地 Profile 清理显示为“已请求/待设备确认”，不把数据库撤销伪装成物理停止。云端配置不要求安装 Bridge；本地离线不会自动转云、上传或重放未知副作用。
7. 平台环境授权目前没有到期时间，撤销状态与设备离线独立。单次任务审批单独显示有效期、待批/已批/拒绝/撤销/过期，仅查询所选使用者未结束任务中未消费的审批（最近 100 条，超出明确提示）。过期只作只读诊断，不禁用整项能力、不改原记录、不续期或重放；处理责任仍在对应任务审批链路。

### MCP 授权范围不能误读

云 MCP 连接和工具是**工作区服务配置**。员工版本绑定影响本工作区被分配该确切版本的使用者，并不是仅给当前下拉框选中用户开通；页面明确显示此影响范围。运行期仍检查该调用人的有效分配、确切版本和逐次审批。本地 MCP 额外限定实际设备所有者，绝不借用平台管理员设备身份。

这一版仍使用原有 Bearer/设备凭证能力，不增加 OAuth、任意主机 stdio、个人浏览器接管或服务器开关自助修改。

## 额度口径与编辑边界

- 使用原 `allrice_model_usage_ledger` / `allrice_subscription_usage_budget_reviews`，不新建账本、不改历史 Run。
- 组织月总额度、租户资源限额、所选用户限额可编辑；其他员工/Provider 限额继续由原运行准入执行，不借此次管理 UI 放开。
- 明确区分平台默认、平台对象覆盖和租户对象覆盖；用户/租户对象可移除覆盖恢复继承。组织表编辑只改月 Token 和调用次数，不更改原美分限制。
- 总量为输入+输出，缓存是输入子集，不减掉、不重复相加；缓存用量缺失显示未知。真实已记录用量、未知笔数和管理员风险预留分列。
- 组织表统计所有工作区。现有资源准入按当前工作区统计用户/租户资源用量；同租户用户设置会作用于其各工作区，**并非把工作区累计伪称为全组织用户累计**。
- 官方 Codex 窗口不由 Token 推算，此页明确标记没有查询官方窗口。本次不接 API 计费、不调整供应商预算、不恢复 136,000 成功警告。
- 每次额度修改带预期版本，在事务中对比、写入原表并记录前后值与真实管理员。提高用户限额不能绕过组织总额度、未知用量处理和原运行安全边界。

## 接口与权限

| 指定租户路径                                                     | 作用                                              |
| ---------------------------------------------------------------- | ------------------------------------------------- |
| `GET/PUT /api/v1/admin/tenants/:organizationId/quotas`           | 指定工作区/使用者的分层额度、CAS 修改与审计       |
| `GET/PUT /api/v1/admin/tenants/:organizationId/environments`     | 设备/云端目标/前置条件；沙箱与浏览器授权和撤销    |
| `GET/POST/PATCH /api/v1/admin/tenants/:organizationId/mcp`       | 云 MCP 配置、发现、工具与员工绑定，凭证仅加密保存 |
| `GET/POST/PATCH /api/v1/admin/tenants/:organizationId/local-mcp` | 指定所有者设备上的 MCP 配置与授权，不触发原生开关 |

新的管理目标是独立参数，不伪造 `RequestContext.actor`、membership 或执行主体。原管理员接口和真实执行权限检查继续保留；服务端管理选项仅由可信处理器构造，每次事务重新校验真实平台管理员会话、活动组织/工作区及使用者。

写请求要求同源、JSON 大小限制、明确原因。MCP 修改复查连接/工具版本，员工绑定保留原版本 CAS；拒绝过期页面覆盖。跨租户、其他设备所有者、已撤销/过期的管理员会话均拒绝。错误不回显密钥；切换租户/使用者不复用旧数据，未保存修改提示、保存中禁止切换、失败不自动重发。

## 迁移与回退

`0100_tenant_scoped_resource_quotas.sql` 保留所有原额度行和值，将资源额度唯一键从 `(scope_type,scope_id)` 拆为“组织+对象”的唯一键及 NULL 组织的平台对象唯一键；准入查询同时修正为优先本组织覆盖、再平台覆盖。否则同一账号加入两个组织时，一个组织的额度修改会影响另一个组织。

部署时先排空并停止旧管理服务/Worker 的新请求，再执行迁移，最后启动匹配的服务端/页面和 Worker；在所有读取方更新前不开放跨组织额度覆盖写入。此提交仍未执行真实环境迁移。不要只更新前端或让旧的无组织过滤读取与新覆盖写入并存。

回退管理 UI/路由时保留组织隔离的额度读取修复和迁移，不删除账本或既有设置。如果已经产生同一用户跨组织的多条配置，**不能直接恢复旧的全局唯一键或旧版不区分组织的查询**；必须明确核对数据并规划兼容回退，不做自动删行去重。回退权限配置走显式撤销/重新授权；不要恢复旧 Run 的冻结授权或重放在途操作。
