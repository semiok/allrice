# 管理后台设计规范

管理后台采用固定深色主题，规范仅作用于 `AdminShell` 内，不改变员工工作台或登录页的外观。组织管理作为首个完整样板，其他模块按各自 PR 逐步调整布局。

## 色彩与层次

所有后台新组件使用 `apps/web/components/admin/admin-ui.module.css` 中的 `--admin-*` 变量。页面底色、侧栏、浮层依次为炭灰 `#181b20`、深灰 `#14171b`、较亮深灰 `#22262d`；选中填充为 `#2a3039`。正文为柔和白 `#edf0f4`，辅助文字为 `#a0a9b7`。成功、待处理、错误分别使用低饱和绿、黄、红，并配合明确的文字标签。

## 字体与间距

| 用途                       | 字号 | 字重              |
| -------------------------- | ---- | ----------------- |
| 页面标题                   | 22px | 500               |
| 正文、表单、按钮、分区标题 | 14px | 400；分区标题 500 |
| 描述、账号、状态、表头     | 12px | 400               |

间距使用 4、8、12、16、24、32px。页面内容左右通常留 28px；窄屏留 16px。表格单元格左右留 12px。选中背景覆盖的内容必须保留左右内边距，不能改变选中前后的文字位置。支持 320px 窄屏，优先换行或堆叠内容。

## 共用控件

- `AdminShell` 提供后台导航、当前页面标识与深色变量作用域；原有 `view` URL 参数继续使用。
- `AdminButton` 提供主操作、次操作、轻操作、危险操作与图标操作。每组仅一个主操作。常规按钮高 34px、圆角 7px，图标 16px；触屏交互目标扩大至 44px。
- `AdminDialog` 使用原生模态对话框，提供焦点限制、Esc 关闭和焦点恢复。提交期间阻止关闭，错误显示在所属表单内。浮层背景保持不透明。
- `AdminMenu` 收纳每行的低频操作；支持点击外部与 Esc 收起，操作本身保留明确名称。
- `AdminStatus` 使用 12px 状态文字与同色圆点，状态必须来自接口事实，不通过颜色代替文字。

表单、搜索、列表、空状态和加载状态必须保留原有后端语义、权限及并发版本检查。刷新不改变当前公司，批量操作必须明确选择范围，密码不进入展示日志或截图。改动完成后在 Dev 验证真实页面，同时通过隔离数据的浏览器测试核对写入流程。

## 组织管理样板

公司选择与编辑集中在页头，下方使用「员工账号、公司 AI 员工、应用与电脑、用量」四个页签。表格常显员工身份、岗位与状态，低频的编辑、密码重置和启停操作放入行菜单。创建、导入、编辑和配发使用共用模态框。

批量配发入口分别标明已选员工、当前筛选结果和全公司；重新查找时清空选中范围。AI 员工的添加、移除、跟随默认和全员自动配发即时保存，提交结果来自接口，不能使用无写入行为的确认按钮。历史工作区选择必须作用于实际请求，不能同时出现两个不同步的选择器。

资源表单未保存时，切换公司、页签或后台导航需要确认放弃；正在提交时禁止切换。窄屏将员工表格和配发表格改成分行布局，保留完整的公司名称、账号、状态及所有操作。

## AI 员工编辑样板

统一页头使用 22px 标题；员工目录支持名称 / Key 搜索与真实发布状态筛选，选中项保留 12px 内边距。编辑区使用 14px 员工名称、12px 版本与状态，配置页签横向滚动，窄屏目录和编辑区上下排列。新建草稿使用共用弹框，说明复制来源；发布与草稿测试仍使用现有版本和权限检查。刷新、切换员工、离开后台模块和关闭页面时保护未保存的配置，提交期间锁定编辑控件。

## 公司看板样板

公司与员工 / AI / 岗位 / 时间筛选集中在页头，概况、工作记录、交付成果、规矩与范本使用四个页签。真实计数使用 22px 数字与 12px 标签，点击计数进入相应工作列表；统计口径、缺失用量和未确认费用必须保留。窄屏表格转换为有字段标签的分行记录。工作与成果使用共用宽弹框，保留焦点限制、恢复和版本固定预览；页签切换不卸载列表与编辑状态。

## 平台设置样板

版本与能力、模型与用量、应用连接、运行技术详情、员工反馈采用相同页头、字号和左右边距。模型与应用表单使用 34px 控件，保存与刷新统一共用按钮；Provider、授权状态、未知用量和修订冲突来自现有事实源。能力说明和组件详情保持如实展示，组件弹框沿用共用焦点、滚动与关闭行为。反馈列表选中背景保留内边距；窄屏表单与主从详情上下排列。

运行过程沿用按时间排列的阶段：准备使用蓝色、工具使用青色、上下文整理使用紫色，颜色由共用 `--admin-process-*` 变量提供。连续的上下文占用与整理记录归在同一阶段，准备项、其他工具及不同 Run 保持原有顺序；仅有占用记录时不宣称已执行整理。上下文整理阶段默认展开，可向下展开或收起全部原始记录，轮询刷新保留用户的展开选择。

节点使用对应操作的图标；每条明细保留标题、脱敏摘要、原始状态及时间。正文 14px、状态和时间 12px，状态显示中文标签，原始值保留在 `data-state` 与提示中。成功、执行中、失败独立使用绿、蓝、红状态，历史开始记录显示「已开始」。阶段完成依赖真实结束事件，摘要已更新或结果已精简不代表仍在运行的整理已完成。窄屏将标题、状态与时间换行，保持内边距与完整明细。
