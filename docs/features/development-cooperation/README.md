## 用户结果与范围

多个助手能围绕同一真实开发任务分工，提交可追溯的修改，运行针对该版本的测试并独立审查，最终由主 Rice 核验和交付。不是新增若干角色按钮，也不是让子助手同时写用户目录。

只复用现有日常模式、DSH、父子 Run、根预算、Tool Broker、Changeset、精确审批和三栏工作台。不实现 Boost、Teamwork、长期自治调度或新的 Agent Loop；不调整模型、订阅计量、Snow 月额度或 Prod。

## 已核对的基线

- `apps/worker/src/harness/dsh/assistant-controller.ts` 已接通有限只读工具、助手报告、受控本地命令提案。它并未允许子助手任意文件读写或导出 Changeset；不能只放宽 `supportedChildTools` 就声称协作编程完成。
- `packages/database/src/assistant-runtime.ts` 是父子身份、租约、消息、预算及产物归属的权威入口。`artifactNamespace` 区分助手输出，不等于用户工作目录或物理沙箱。
- `packages/database/src/local-command-service.ts` 已将子助手来源绑定到操作账本和精确命令审批。每个命令有自己的 `local_copy` 操作身份；命令成功不能证明测试了刚生成的某份修改。
- `packages/database/src/changeset-service.ts` 已具备主 Rice 提案的版本、审批、实际基线检查和有证据的恢复。复用其写入链，不另建“助手直接写入”接口。
- MET-151 已验证基础助手报告交付和后台配置；这不是 MET-144 的真实协作项目验收。

## X01-A：归属、版本及合并基础（本 PR）

1. 将开发分工关联到已有 root / parent / child、组织 / 工作区 / 使用者、执行目标和具体工作副本。文件范围必须明确；“分工”不授予工具或资料出端权限。
2. 冻结每个修改提案的读取基线、来源助手、文件范围和内容版本。复用现有 Artifact / DeliverableVersion / StorageObject，不复制第二份成果账本。
3. 在持久事务中处理父子 / 同级争用、重复请求、同路径以及目录前缀冲突。重启后继续承认已有归属；不能用内存锁、先查后写或用户界面禁用来替代并发保护。
4. 明确隔离副本与最终写入目标。不同副本可并行提出方案，但进入同一交付目标必须串行审查、合并及核对基线。同一文件的新用户修改必须保留。
5. 合并得到新版本，不继承旧版本的批准或测试通过结论。后续测试必须绑定合并后的实际输入版本，不能在未修改的原目录跑测试后给新代码打“通过”。

这一 PR 的门禁是契约、持久化与冲突 / 权限 / 幂等 / 冷恢复回归；它不单独宣称完整协作体验上线。

### 已实现的内部接口与数据

`createAssistantRuntime().development` 复用原根事务锁、真实父子 Run、Worker 租约、当前权限和取消状态：

- `initialize`：从同租户、同 owner、同 Session、主 Rice 发布的真实 Changeset 版本建立候选主线。文件正文仍来自已有不可变 StorageObject；实际读取并校验对象 SHA 与每个文件 SHA。
- `assign`：父助手仅可分配给自己或直接子助手，冻结当前主线版本、执行目标、副本引用和 **明确文件清单**。不是目录通配授权。非根助手再委派或给自己分工时，必须落在上级已授予且未关闭的文件清单内，换副本 ID 也不能扩大范围。相同副本内父子 / 同级的同路径、前缀、大小写和 Unicode 规范化冲突串行拒绝；同一请求重试不重复分配。
- `propose`：只接受归属助手发布的真实 Changeset 版本；文件必须在清单内、目标和副本必须匹配，before 必须与分工时的候选版本一致。登记的是修改提案，不是完成写盘的证据。
- `merge`：仅主 Rice 采用提案。根事务串行检查 expected head，重新验证来源、当前权限、当前文件基线和合并内容。输出必须是已有 Artifact 系列中的新后继版本；拒绝过期提案、重复采用和内容夹带。返回 `verification: unverified`，不创建审批、命令或测试成功记录。

候选主线是**有限文件集的 Changeset**，不是完整仓库快照。初始版本可以是主 Rice 已有修改提案，也可用 before/after 相同的文件表达待修改基线；新文件的 before 为 null。单份最多 32 个文本文件，沿用现有工件 512 KB 读取限制，一次最多采用 16 个提案。合并保留原始文件 before，累积新的 after，最终落盘仍须匹配真实文件。

`0101_development_cooperation.sql` 新增五张元数据表：`allrice_development_heads`、`allrice_development_assignments`、`allrice_development_proposals`、`allrice_development_merges`、`allrice_development_merge_sources`。引用现有 DeliverableVersion，不新增正文或费用账本。数据库触发器保护分工、版本来源和合并记录不可改写；主线推进必须对应合并记录。合并采用后关闭该分工的**提案登记**，后续修改需新分工；这不表示进程已停止。

本 PR 无新 HTTP 接口、模型工具、前端入口、环境开关或执行权限；现有助手开启也不会自动开启协作编程。`workspace.export.create` / `assistant.delegate` 必须已在真实权限链中获得授权，缺少生产授权 hook 时默认拒绝。没有改 DSH Agent Loop 或根预算。

### 冲突与恢复的准确边界

归属与串行采用限于**同一 root 的候选主线**，不是跨任务全局文件锁，更不是文件系统沙箱。不同 workCopy ID 只是服务端内部副本引用；本 PR 不创建副本、不证明物理隔离，也不凭引用执行。X01-B 必须把它绑定到真实受控副本的创建、输入版本和 Runner 回执，不能将这些字段开放为模型自报权限。

不同副本可提出同文件的两个方案，但不能在一次合并中静默选一个；先采用一个后，另一个必须核对新基线或重新生成。不同 root 和用户编辑的实际冲突继续由原 Changeset 精确审批、实际路径检查和逐文件 SHA 校验处理。本 PR 未增强跨任务物理写入互斥，不将单文件替换声称为多文件原子事务。

候选工件先通过原发布路径保存，再进入根事务验证采用，避免倒置存储配额锁顺序。保存成功但未采用的工件保留为候选；若候选内容不符，修正版可在同一 Artifact 系列后继发布并重试，必须重新按仍有效的主线计算内容，不继承失败候选内容、批准或测试结果。版本祖先检查最多 64 层，超出需另行处理，不绕过校验。

重建 Runtime 后从 PostgreSQL 读取既有分工和幂等请求；不存在内存锁重置或 TTL 自动释放。取消、未知状态、旧租约的助手不得补交提案；已完成助手的既有提案可由主 Rice 采用，但仍须当前授权。取消/未知分工不自动重新派发。断网时仅处理已授权且已存储的候选材料，不访问本地设备、不自动上传或改派云端。

## 权威、数据及安全边界

PostgreSQL 保存业务状态和归属，现有存储服务保存版本化内容。每次读取、提案、测试、合并和写回继续核对组织、工作区、真实 owner、根关系、当前权限、租约、期限及取消状态。浏览器或模型不能自报 agent / device / grant 获得授权。

Git worktree 不等于 OS 沙箱，文件清单不代替真实路径与软链接边界检查。持久文件归属也不证明物理文件未变；Runner 最终还须核对输入摘要、真实路径和执行授权。子助手不能通过生成脚本、MCP 或“测试命令”绕开隔离。

Bridge 在线且目录获准才使用本地材料。离线时本地依赖明确等待；没有单独的资料出端授权，不上传代码/凭证，不把未知本地动作改派云端。云端独立授权材料可使用已有云沙箱；不同目标的执行证据不混用。

## 失败、恢复与发布

各 PR 独立列出代码、测试和部署状态，迁移采用兼容增量并说明回退范围。未经本单真实验收不关闭工单，不自动部署 Prod；145 / 146 不作为依赖，也不借本单提前开启。
