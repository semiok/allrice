## 用户结果与范围

多个助手能围绕同一真实开发任务分工，提交可追溯的修改，运行针对该版本的测试并独立审查，最终由主 Rice 核验和交付。不是新增若干角色按钮，也不是让子助手同时写用户目录。

只复用现有日常模式、DSH、父子 Run、根预算、Tool Broker、Changeset、精确审批和三栏工作台。不实现 Boost、Teamwork、长期自治调度或新的 Agent Loop；不调整模型、订阅计量、Snow 月额度或 Prod。

## 开工时核对的基线（实现增量见 B1 / B2）

- `apps/worker/src/harness/dsh/assistant-controller.ts` 已接通有限只读工具、助手报告、受控本地命令提案。它并未允许子助手任意文件读写或导出 Changeset；不能只放宽 `supportedChildTools` 就声称协作编程完成。

- `packages/database/src/changeset-service.ts` 已具备主 Rice 提案的版本、审批、实际基线检查和有证据的恢复。复用其写入链，不另建“助手直接写入”接口。
- MET-151 已验证基础助手报告交付和后台配置；这不是 MET-144 的真实协作项目验收。

## X01-A：归属、版本及合并基础（PR #83）

1. 将开发分工关联到已有 root / parent / child、组织 / 工作区 / 使用者、执行目标和具体工作副本。文件范围必须明确；“分工”不授予工具或资料出端权限。
2. 冻结每个修改提案的读取基线、来源助手、文件范围和内容版本。复用现有 Artifact / DeliverableVersion / StorageObject，不复制第二份成果账本。
3. 在持久事务中处理父子 / 同级争用、重复请求、同路径以及目录前缀冲突。重启后继续承认已有归属；不能用内存锁、先查后写或用户界面禁用来替代并发保护。
4. 明确隔离副本与最终写入目标。不同副本可并行提出方案，但进入同一交付目标必须串行审查、合并及核对基线。同一文件的新用户修改必须保留。
5. 合并得到新版本，不继承旧版本的批准或测试通过结论。后续测试必须绑定合并后的实际输入版本，不能在未修改的原目录跑测试后给新代码打“通过”。

这一 PR 的门禁是契约、持久化与冲突 / 权限 / 幂等 / 冷恢复回归；它不单独宣称完整协作体验上线。

### 已实现的内部接口与数据

`createAssistantRuntime().development` 复用原根事务锁、真实父子 Run、Worker 租约、当前权限和取消状态：

- `initialize`：从同租户、同 owner、同 Session、主 Rice 发布的真实 Changeset 版本建立候选主线。文件正文仍来自已有不可变 StorageObject；实际读取并校验对象 SHA 与每个文件 SHA。
- `assign`：父助手仅可分配给自己或直接子助手，冻结当前主线版本、执行目标、副本引用和 **明确文件清单**。不是目录通配授权。非根助手再委派或给自己分工时，必须落在上级已授予且未关闭的文件清单内，换副本 ID 也不能扩大范围。相同副本内父子 / 同级的同路径、前缀、大小写和 Unicode 规范化冲突串行拒绝；同一请求重试不重复分配。
- `propose`：只接受归属助手发布的真实 Changeset 版本；文件必须在清单内、目标和副本必须匹配，before 必须与分工时的候选版本一致。登记的是修改提案，不是完成写盘的证据。
- `merge`：仅主 Rice 采用提案。根事务串行检查 expected head，重新验证来源、当前权限、当前文件基线和合并内容。输出必须是已有 Artifact 系列中的新后继版本；拒绝过期提案、重复采用和内容夹带。返回 `verification: unverified`，不创建审批、命令或测试成功记录。

候选主线是**有限文件集的 Changeset**，不是完整仓库快照。初始版本可以是主 Rice 已有修改提案，也可用 before/after 相同的文件表达待修改基线；新文件的 before 为 null。单份最多 32 个文本文件，沿用现有工件 512 KB 读取限制，一次最多采用 16 个提案。合并保留原始文件 before，累积新的 after，最终落盘仍须匹配真实文件。

`0101_development_cooperation.sql` 新增五张元数据表：`allrice_development_heads`、`allrice_development_assignments`、`allrice_development_proposals`、`allrice_development_merges`、`allrice_development_merge_sources`。引用现有 DeliverableVersion，不新增正文或费用账本。数据库触发器保护分工、版本来源和合并记录不可改写；主线推进必须对应合并记录。合并采用后关闭该分工的**提案登记**，后续修改需新分工；这不表示进程已停止。

X01-A 无新 HTTP 接口、模型工具、前端入口、环境开关或执行权限；现有助手开启也不会自动开启协作编程。`workspace.export.create` / `assistant.delegate` 必须已在真实权限链中获得授权，缺少生产授权 hook 时默认拒绝。没有改 DSH Agent Loop 或根预算。B2 新增工具见下节，不覆盖 A 当时的验证边界。

### 冲突与恢复的准确边界

归属与串行采用限于**同一 root 的候选主线**，不是跨任务全局文件锁，更不是文件系统沙箱。不同 workCopy ID 只是服务端内部副本引用；本 PR 不创建副本、不证明物理隔离，也不凭引用执行。X01-B 必须把它绑定到真实受控副本的创建、输入版本和 Runner 回执，不能将这些字段开放为模型自报权限。

不同副本可提出同文件的两个方案，但不能在一次合并中静默选一个；先采用一个后，另一个必须核对新基线或重新生成。不同 root 和用户编辑的实际冲突继续由原 Changeset 精确审批、实际路径检查和逐文件 SHA 校验处理。本 PR 未增强跨任务物理写入互斥，不将单文件替换声称为多文件原子事务。

候选工件先通过原发布路径保存，再进入根事务验证采用，避免倒置存储配额锁顺序。保存成功但未采用的工件保留为候选；若候选内容不符，修正版可在同一 Artifact 系列后继发布并重试，必须重新按仍有效的主线计算内容，不继承失败候选内容、批准或测试结果。版本祖先检查最多 64 层，超出需另行处理，不绕过校验。

重建 Runtime 后从 PostgreSQL 读取既有分工和幂等请求；不存在内存锁重置或 TTL 自动释放。取消、未知状态、旧租约的助手不得补交提案；已完成助手的既有提案可由主 Rice 采用，但仍须当前授权。取消/未知分工不自动重新派发。断网时仅处理已授权且已存储的候选材料，不访问本地设备、不自动上传或改派云端。

### 迁移与回退

迁移仅新增表、索引和对应触发器，不回填、更新或删除旧业务记录。隔离数据库验证覆盖已有助手历史的 0100 → 0101 增量迁移和连接池重开。本次不迁移 Dev / Prod。

### X01-B1：候选版本沙箱验证（PR #84）

源代码核对发现原 Local Runner 只能复制原目录，不能测试尚未落盘的提案，因此将涉及 Bridge 协议的装载/回执作为独立 PR。**本 PR 是真实执行能力，不是完整多助手闭环，也不把 X01-B 宣告完成。**

- 主 Rice 的现有 `local.process.execute` 新增可选 `candidate:{artifactId,checksum}`。只接收引用，不允许模型指定正文、设备、授权或执行证据。Worker 通过原 StoragePort 读取同租户、同 owner、同 Session 的不可变 Changeset；每份对象/文件 SHA 和实际目标授权重新核对。
- `files` 是原目录的准确 before 清单及其余验证依赖。每个修改/删除文件必须有对应基线；新增文件必须原本不存在。Bridge 保留原路径、软链接、敏感文件、单文件 200 KB、合计 256 KiB 的读取限制，并检查大小写/NFC/前缀冲突。在内存生成完整 after 清单，只把它放入原 Linux 隔离容器；**不先落盘到用户目录，也没有任意宿主 Shell**。最终副本仍限制 64 个文件和 256 KiB。
- 当前只支持前台 Node/npm 验证命令；不与依赖安装、诊断、后台服务组合。不扩展命令时限、网络、CPU、内存或权限。项目需安装依赖的候选验证不在本小节的能力声明内。
- 新版 Bridge 报告 `changeset_candidate`，领取操作时明确发送 `supportsChangesetCandidate`。旧设备/旧领取请求不能领到这种任务，不回退测试旧文件。原普通命令协议不变。
- 精确批准绑定候选内容、命令、输入文件和环境。审批卡片复用既有 Cline Diff，显示候选摘要和可核对的前后文本。新版本发布后旧任务显示过期，停止新的派发/续租；旧批准不会迁移。修正后需新操作及新批准。
- 运行回执增加 `candidate:{artifactId,checksum,inputDigest}`；inputDigest 为按路径排序的完整隔离副本 `[path,sha256]` 数组的 SHA-256。还保留真实退出码、原因和输出。服务端拒绝缺少版本、版本/输入摘要不符、非零退出伪报成功或声称宿主写入的回执。执行前拒绝允许只记录失败原因，不凭空生成进程证据。
- 容器创建时持久标签绑定精确候选/输入和命令。冷恢复需标签匹配，不运行新命令、不读取变化后的宿主重新推算回执。取消/未知仍沿用原账本。后继版本不会改写旧回执。
- 沿用原 PostgreSQL 操作、审批和回执表，无新增迁移。候选正文进入现有不可变 operation payload；保留 512 KB 总封包上限，候选命令超过 480 KB 提前拒绝，为绑定字段留空间。无新全局开关、后台角色或租户授权变更。

B1 当时尚不允许子助手提交 candidate：它缺少受控发布与物理副本归属绑定，不能用父 Rice 身份替代。下节 X01-B2 接入真实分工、子助手发布/测试、独立审查和主 Rice 采用；不以模型自报或 B1 主 Rice 命令成功代替这些步骤。X01-C 再做获准 Dev 的真实项目闭环。

验证分层：契约/路径单测、独立 PostgreSQL 的精确审批/租户/旧客户端/版本变更/冷读取/回执防错配、前端预览测试，以及本机 `allrice-b2` 专用 Linux VM 的实际候选失败→修正版成功→冷恢复。VM 只操作测试新建的临时项目与带本次 attempt 标签的容器；数据库设备是合成夹具，二者不冒充已完成真实租户网页→M5 链路。

### X01-B2：原生子助手开发闭环（本 PR）

新增显式授权的 `assistant.development` 原生协调工具（`storage:write`）。必须在 Rice 已发布版本、当前策略和 Run 冻结工具中获准，子助手只能获得父级工具子集；不自动更新任何租户发布版本或开关。它不是通用 Shell / 文件写入工具，也不取代 `local.process.execute` 的精确批准。

1. 主 Rice 用现有 Changeset 工件 `initialize` 建立主线，通过 `assistant.delegate.development` 指定 edit / test / review 任务。分工、子 Run、首次消息、启动预算在**同一事务**提交；失败一起回滚，不能留占位助手。编辑只授予明确文件清单，副本 ID 由服务端生成。
2. 编辑助手 `inspect` 读取自己文件范围的基线，用 `publish` 提交修改；服务端计算 SHA、重新核对 before / 路径 / 目标，沿用原存储配额和不可变工件发布。来源是实际子 Run，不伪装主 Rice。修正需显式引用前一提案版本；发布不修改用户目录。已保存提案可作为 `assistant.report` 的真实引用。
3. 主 Rice `merge` 重新计算提案组合，生成完整候选主线并返回 `unverified`。候选保留原目录 before，累积全部 after；不是对原目录做直接修改。不同助手的增量提案不会被错当成完整测试输入。
4. 测试助手获得**该主线 ID + SHA** 的 test 分工，使用原 `local.process.execute` 提案、网页审批和 B1 Runner。新建、批准、派发、续租均检查真实助手归属、当前分工和主线。物理副本仍以 operation ID 隔离；命令回执绑定候选 ID、SHA、完整输入摘要、镜像、退出码和停止原因。旧客户端不领取候选任务。
5. 另一个审查助手 `inspect` 当前完整候选和最多 8 次同版本测试的实际输出（每路最多 4,000 字符，截断明确标记），`review` 引用真实终态命令。accept 必须有相同版本的成功回执。审查者不能是主 Rice、累计修改的任何作者或该命令的测试者；角色名称不作为身份依据。它是**可追溯的模型审查意见，不是正确性的绝对保证**。revise 不会被另一个 accept 静默覆盖，必须修正版本并重测、重审。
6. 主 Rice `deliver` 重新核对当前版本、成功测试和独立审查，将交付记录保存到工件工作台。普通助手口头报告不能代替这道门禁；已初始化开发任务缺少当前有效交付时，根任务不能标为 completed。最终写回原目录仍是另外的 Changeset 请求、用户审批和实际文件 SHA 检查。

界面沿用原三栏工作台、Cline Diff、审批和日志，不新增模式按钮。子助手副本明确显示“提案、未写入本地”，不提供直接应用按钮。独立审查 / 主 Rice 交付以 JSON 工件记录精确候选、真实命令和助手来源；本 PR 不另做专门的审查仪表盘。旧版本的失败、拒绝和执行事实保留，不迁移给新版本。

数据：`0102_development_verification.sql` 仅新增 `allrice_development_verifiers`、`allrice_development_reviews`、`allrice_development_deliveries` 三张关联表及不可变更新保护；不复制文件正文、审批、执行或用量账本。工件继续使用原 Artifact / DeliverableVersion / StorageObject。开发协调调用的完整参数摘要绑定原计量请求 ID，重试不能偷换命令；真正命令执行仍遵循原不可盲目重放规则。新增内部 evidence 权限检查只允许读取已完成助手的既有来源，不能恢复它的模型或工具执行；取消、失败、未知、旧租约和权限撤销仍拒绝。

## 权威、数据及安全边界

PostgreSQL 保存业务状态和归属，现有存储服务保存版本化内容。每次读取、提案、测试、合并和写回继续核对组织、工作区、真实 owner、根关系、当前权限、租约、期限及取消状态。浏览器或模型不能自报 agent / device / grant 获得授权。

Git worktree 不等于 OS 沙箱，文件清单不代替真实路径与软链接边界检查。持久文件归属也不证明物理文件未变；Runner 最终还须核对输入摘要、真实路径和执行授权。子助手不能通过生成脚本、MCP 或“测试命令”绕开隔离。

Bridge 在线且目录获准才使用本地材料。离线时本地依赖明确等待；没有单独的资料出端授权，不上传代码/凭证，不把未知本地动作改派云端。云端独立授权材料可使用已有云沙箱；不同目标的执行证据不混用。
