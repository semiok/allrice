# 个人技能（MET187 PR1–PR4）

普通员工可在聊天中上传一份独立 `SKILL.md` 或包含技能与资源的 ZIP，明确说“请安装我上传的 SKILL.md”或“请安装我上传的 ZIP 里的技能，给当前 AI 员工使用”。服务器保存原始文件和解析结果，绑定本人当前 AI 员工，后续任务可通过 DSH 原生 `skill` 工具采用。通用员工与定制小白使用同一机制。

设置 → 我的技能展示来源、固定版本、绑定的员工和启用状态，可停用、重新启用或卸载。员工详情不增加技能编辑器。格式检查与真实业务验证分开；安装成功不会被标成“业务验证通过”。

独立 SKILL.md 必须是有效 UTF-8，最大 256 KiB，有 DSH 支持的名称、说明和正文。个人库最多 32 个已安装技能、128 个保留安装记录，每个实例最多启用 8 个；还受现有运行快照 64 项、8 MB 总量限制。读取、评价、翻译、临时使用及引用中的安装指令不构成长期安装授权。当前消息必须恰有一份技能附件；不会根据模型提交的任意正文安装。

也可发送一个公开 GitHub 链接，明确要求安装其中的技能。更新和回退复用同一份个人库，采用下面的固定版本确认流程。同名平台技能或不同内容的个人技能不会被覆盖。保留原始文件，包括解析器没有采用的前置信息；不会自动安装依赖或在 Worker 宿主运行文件中的代码。

## 公开 GitHub 来源

支持 `https://github.com/owner/repository`、`tree/<ref>/<directory>` 与 `blob/<ref>/<path>/SKILL.md`。例如“请安装这个技能：\nhttps://github.com/owner/repository/tree/main/weekly”。当前直接消息必须只有一个明确的来源链接；引用、翻译、评价、临时使用和安装另一份附件的指令均不授权链接安装。私有仓库、其他域名、凭据、查询参数及 URL 片段不接受，不借用平台或用户的 GitHub 授权。

先解析唯一分支/标签/提交与目录，再固定完整 commit/tree SHA。分支名包含斜杠且与目录有歧义时，要求提供固定提交链接，不猜测。只通过公开 GitHub API 和固定提交文件地址读取；拒绝重定向、不完整目录树、链接/子模块、LFS 指针、路径冲突、大小超限及字节校验失败。一次读取最多 60 秒。来源内容仍交给既有 DSH 原生解析器；目录中的模板 `SKILL.md` 保留为资源，不作为额外候选。

发现与导入沿用同一 ZIP 候选选择、配额、私有不可变存储和绑定事务。一个可用技能安装，多个候选等待用户下一条直接消息选择；不会整个仓库自动启用。GitHub commit/tree、原路径、原字节校验和、资源清单与来源链接一起保留。丢失存储确认后重试读取已固定提交，分支移动不会替换待选包；已存妥的包直接回读，不再次联网。后续任务读取私有固定副本，不依赖远端仓库继续可用。

“我的技能”展示仓库、固定提交链接和许可来源。许可缺失显示“未提供”，GitHub 返回的许可仅标为“GitHub 标注”，不推断兼容或业务效果。安装仍不授予额外执行权限，公开来源代码也不会在宿主执行。支持的是现有文件/大小边界内的技能目录，不保证任意大型仓库或外部依赖兼容。

## ZIP、候选与固定资源

ZIP 不超过 8 MB，沿用 Bridge 已有的有界归档读写组件（共享 `@allrice/file-archives`，固定解码器版本），不新增解码算法。拒绝加密、链接、越界/重复路径、CRC 错误及超出展开限制的包。只把准确名为 `SKILL.md` 的文件交给原生解析器，每包最多 8 个候选。候选只引用所在目录的 `references/`、`assets/`、`scripts/`；每项最多 128 KiB、资源合计 512 KiB。明确引用却缺失的资源会显示不兼容，不能启用。

一个可用候选直接安装；多候选列出名称和说明后结束本轮，不自动选第一个。用户下一条消息明确选择名称或准确路径后才安装，例如“我选 weekly，请安装到当前员工”。原生工具保留 `importId + candidatePath`；同一 Run 的问题回答不能替代新的直接用户指令。用户可以说“刚才那个 ZIP 先不装了”。候选 24 小时过期；同会话导入新包使旧待选包失效。

未启用的候选不会进入员工快照。取消、过期或被替换的未引用私有副本在后续本人导入/取消操作时有界回收，只有实际删除字节后才释放存储配额；已被版本引用的不可变对象不能清理。重复上传相同包和绑定其他本人实例复用已保留副本。存储或提交结果未知时不宣称安装回滚，重试仍按原消息与来源回读。

安装版本保存原始 ZIP 的私有副本和资源清单，不依赖原附件永久存在。正文与包资源分别校验；运行快照固定版本和包校验和，不包含整包字节。`workspace.skill.read` 在实际读取前后复核所属用户、当前实例、版本、epoch 与资源 checksum。文件模板走现有成果工具，不增加模板管理体系。

可兼容的无额外依赖 Node/Python 脚本可使用已有 `cloud.process.execute` 的 `frozenScript:{skill,path}`，读取 Run 固定的 `scripts/*.js`、`*.mjs` 或 `*.py` 原字节。调用方不传 `language`，服务器按已验证资源确定运行时，再由原有云端授权、输入传输、执行预算与成果机制处理。安装不授予执行/联网权限；此入口不运行安装钩子，也不承诺任意依赖包均兼容。缺依赖、运行错误和输出检查仍按实际结果报告。普通内联 Python 的本地优先规则保持原样。

## 版本更新、回退与其他员工绑定

个人库按公司和本人保存一份当前版本，已绑定员工共同使用这一版本；不额外建立逐员工版本管理系统。设置 → 我的技能标明“个人库当前版本”，展开历史可查看来源、版本与回退指令。当前工作区的绑定列表不代表全部工作区。

在聊天中说“请将 weekly 更新为我上传的 SKILL.md”，或给出唯一公开 GitHub 来源。原生 `workspace_personal_skill_version` 先 inspect 读取准确 installationId/revision，再 update 复用既有解析、ZIP、固定 GitHub 和私有配额链路。新包必须包含一个名称与目标相同且格式有效的候选；有重复同名候选时不猜测。上传文件没有在线版本源，需要新上传；GitHub 的移动分支只用于读取这一次候选，确认和使用不再跟随分支。

更新或“请将 weekly 回退到 v1”先产生待确认预览，不立即生效。预览包括固定来源、基线版本/revision、所有工作区的绑定（包括停用项），以及确认文字。用户在同会话下一条直接消息中确认完整范围后才能提交；引用、泛泛“好”、同 Run 的询问、模型布尔参数均不代替确认。一个技能在同会话只保留最新待确认候选，不能把“刚才展示的版本”套用到较早来源。候选 24 小时过期。

提交在同一事务内重新检查全部范围、来源和当前权限。绑定变化、归档、撤权或版本竞态拒绝旧确认；不会部分应用。版本变更不增删绑定、不改变 enabled 或 epoch。在途 Run 继续读取原版本；后续独立任务使用库当前版本。停用后重新启用仍遵循原有 epoch 撤权规则，旧 Run 不复活。回退仅移动当前指针，不删除后来的版本、资源或成果；保留版本上限为 32。

若要给另一个本人 AI 员工使用已有库技能，在那个员工聊天中明确说“请把技能 weekly 绑定给你”。先 inspect，bind 带准确当前 versionId/revision；服务端检查当前实例、数量、平台同名冲突及撤销时间，旧消息不能通过刷新 revision 重新启用。原包与历史版本复用，不上传重复副本。

回执记录该次操作实际应用的版本；后续再次更新不能改写旧回执。原安装请求重入保持既有请求 ID，并分别返回原保存结果与当前库状态。存储或提交结果未知时先回读，不能重复分配版本。待确认包引用保护私有字节；取消/替换/过期后只有未被任何历史版本引用的副本可沿用现有清理链路回收。确认前实际校验包字节，文件丢失或损坏时保留旧当前版本。

## 原生复用与权限

- 导入使用固定版本 `@deepseek-ai/dsh-skill-filesystem` 的公开 `FileSystemSkillProvider`，只扫描一次性私有目录，关闭默认根和 watcher。运行使用现有 AllRice Provider 与 DSH 原生加载器，无第二套技能引擎，无 DSH 核心改动。
- 个人记录以公司和本人为归属，启用绑定到当前实例。附件、用户直接原话、当前配发、运行租约及授权在保存事务中重新检查；其他员工及后台目录不读取个人正文。
- 普通能力权限计算完成后再加入个人技能。安装不会增加文件、命令、联网等权限，不伪造平台审核标记。组合快照重新计算完整摘要，同时固定安装、版本、实例及绑定 epoch，损坏的个人快照不能降级为旧权限推导。历史读取核对独立索引与原生来源标记，显式 null 或缺失索引不能绕过；模型调用只检查精简来源，不反复读取全部历史技能正文。
- 原生加载前通过内部 RPC 检查固定身份和当前权限；已有内容 generation 检查覆盖每次模型调用、重试、压缩及历史引用。停用/卸载使旧绑定 epoch 失效，重新启用也不会复活旧 Run 的权限。新的任务丢弃失效 generation 的上下文。普通版本更新与撤权区分，在途固定版本不会被悄悄替换。
- 安装意图按用户消息、附件和实例固定身份，换一个工具调用 ID 也不会重复执行。请求回执在同一事务保存；撤销后旧消息不能重新启用，新的明确安装请求必须晚于最近撤销。即使实例归档或配发撤回，本人仍能在设置卸载个人安装。不确定的提交结果保持未知，不自动重放写操作。

## 核心回归

`personal-skill-intent.test.ts` 使用真实验收原话检查多句、文件名引号、标点、临时使用与长期安装边界。`personal-skills.integration.test.ts` 使用独立 PostgreSQL schema 和合成账号，覆盖真实附件/Broker/原生解析、跨账号隔离、冻结、重复写入、撤权、旧历史、平台同名与配发撤回。

`allrice-model-errors-native.test.mjs` 以真实固定 DSH 运行时和 loopback 模型传输验证原生加载、斜杠、再绑定及撤权后的模型/压缩边界。`workbench-layout.browser.test.ts` 验证桌面和手机“我的技能”交互。Dev 验收另行记录真实用户模型任务和准确加载收据，不能用上述确定性测试替代。

PR2 增加同一隔离 PostgreSQL 链路的 ZIP 选择、取消、配额/物理字节回收、重复副本复用、私有资源和脚本冻结验证；`composer-isolation.browser.test.ts` 覆盖真实上传控件的桌面/手机 ZIP 请求；原生 Broker 往返检查覆盖安装参数联合类型与固定 Python 脚本。历史平台脚本与 Bridge 归档回归一并保留。

PR3 使用公开 HTTP 夹具验证固定提交、错误来源、限流/超时、资源边界和不携带授权；真实 Broker/原生解析/独立 PostgreSQL 测试覆盖多候选、分支移动、未知存储写入结果、无联网重用和来源授权混淆。原生 schema 往返与桌面/手机来源展示均纳入提交前检查。Dev 另行使用真实公开来源与普通隔离账号，核对实际冻结版本及新会话采用，不把模拟网络测试当成实际交付。

PR4 的隔离数据库回归覆盖原始文件更新/回退、新旧 Run 固定版本、多工作区和停用绑定、并发归档、旧撤销消息、同名平台冲突、旧请求 ID 与回执、连续候选确认、GitHub 来源移动、缺失历史包及权限隔离。原生 schema 往返和桌面/手机版本历史在提交前验证。
