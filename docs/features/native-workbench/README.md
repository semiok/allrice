## MET-198：桌面统一工作台

会话标题栏只显示会话名；右侧为金色文件、紫色经验，以及仅在当前员工有已注册业务包时出现的蓝色工作流入口。入口使用统一尺寸与线宽，只有当前展开的对应模块有选中底色；文件、文档或开始页切换后按真实标签更新。工作台关闭时显示展开按钮，打开后由工作台自身提供分栏、全屏及收起控件，避免重复按钮。

全局「自动化任务」保留在左侧，使用简洁的图标与文字导航。当前会话存在生效定时任务时才显示顶部时钟：单项打开既有任务详情，多项先显示当前会话的任务列表，再进入同一详情组件，均复用右侧工作台，不另开弹窗。侧栏空闲会话可显示定时标记，原生活动状态优先，归档会话不补时钟。

桌面主对话正文、用户消息、输入文字及提示文案默认 14px，输入框增加柔和的多层阴影；IME、发送、排队、停止和既有可见性行为继续使用原逻辑。文件与经验不是另一份上传库或记忆引擎。本轮不重做手机导航或另做移动产品；既有员工组织会话的方式保留。

DSH `0.2.1-rc.2` 的公开 `DockLayout` 和现有已登记的原生 store 继续管理标签、分栏、浮动、全屏、恢复和关闭。宿主通过原本已有的 `openContent.replaceTab` 让开始页卡片替换自身；一栏内存在开始页（即使在后台）就不显示加号，否则加号打开开始页。唯一停靠的开始页不可关闭；关闭最后内容收起，再打开由原生规则补开始页。不另造布局状态机；会话行时钟只通过来源账本登记的宿主槽接入。历史成果审查、自动化任务详情继续使用各自真实接口。

文件使用紧凑两行列表和既有 DSH 文件类型图标。普通文件列表只展示各系列最新文件，不显示 v1、v2，详情不再提供版本下拉或跳转最新版。内部对象、历史记录及不可变引用仍完整保留，不把已引用内容改成新版；从历史消息打开的文件仍对应当时的固定对象。列表不暴露原会话信息。上传按钮以白底描边样式放在搜索框右侧，不重复显示「工作区文件」标题；范围箭头保留右侧内边距。

每行常驻「可见范围」齿轮及三点菜单。三点菜单按「引用文件、设为参考资料、下载」排列，无法引用的文件不显示引用操作，不显示「仅文件」文案；参考资料页移除单独的「公司范本」「历史资料」快捷按钮，已有资料及其他既有入口保留。详情直接展示刷新、可用的引用、设为参考资料、可见范围图标和下载。权限编辑未改变参考状态时只保存权限，不重新固定参考版本；成果保存继续使用当前打开版本的原保存接口。上传采用既有拖放区及紧凑范围设置。交付卡片点击即可预览，菜单保留预览、下载，移除冗余主「打开」及「保存到电脑 / 打开」。

模块及布局图标统一为 20px、1.75px 实际线宽和 32px 点击区域，内外收起控件复用同一图标；开始页卡片及终端入口统一使用右箭头。自动化详情「规则 / 任务运行记录」使用文字下划线页签，移除顶部「打开原会话」，执行记录的实际结果跳转保留。以上交互更新跟踪 MET-211，复用当前固定 DSH 原生组件和现有接口，不另建移动版布局。

文件按“全部可见、本次对话、我的文件、部门共享、公司共享”筛选，文件类型为全部、交付成果、参考资料。“我的文件”按所有者筛选，自己共享后的文件仍在其中。个人/指定多个部门/公司范围由服务端当前身份和内容维护级别决定；全公司无需勾选部门。上传默认私人，公司维护权限不能读取别人的私人文件，也不能把别人的共享文件收为自己私人文件。只更改文件及其交付版本序列的策略，不更改原始聊天或其他附件的权限。

文件授权基线使用 `0201_workbench_file_policies.sql`，部署前按既有 `pnpm db:migrate` 流程执行。本次紧凑列表与真实终端扩展不新增 SQL migration。旧文件不做推测性回填，显式调整后才建立文件策略，并收窄旧存储可见性及撤销旧签名。列表、预览、原字节下载、版本、引用和修改均重新核对当前权限；预览与下载在 IO 后再次核对。新的文件历史投影不返回原始私人会话/Run/所有者信息。

长期参考复用现有 Knowledge 不可变快照和处理队列；文件原对象和参考源之间只增加授权绑定及长期参考指针。“引用文件”只加入本次输入，不自动加入长期参考库。任何新快照的读取和已冻结的引用都复核原文件的当前权限，收窄共享后旧快照不能成为旁路。复制者的快照采用原文件所有者作为私人权限的保守后备；不认识新绑定的旧 reader 会拒绝共享接收者，而不会因复制者身份获得永久访问。存储复制不持有外层数据库事务；提交设置时再次核对权限、预期版本和请求幂等回执。处理失败或尚未处理不等同于检索可用；现有 50 MiB 参考处理边界不扩大到一般文件存储。

经验页通过已有员工详情读取生效内容，按员工、个人/部门/公司/平台及文字搜索查看；积累、验证、采用和来源复用现有经验面板。纠正/撤回只准备真实聊天草稿，仍由当前员工及既有服务端授权处理，不在浏览器伪造生效状态。工作流嵌入已有品牌内容工作台，其事务、包校验、品牌/稿件/回执和实际会话跳转保持原有服务。

新增数量来自权限内的文件/经验/业务包版本身份；只在完成工作、文件操作或窗口回到前台时读轻量身份投影，不为角标轮询预览。已读标记属于本浏览器的显示偏好，按用户、组织、工作区及必要的员工隔离；点击一个模块不清除其他模块。首次成功读取作为基线，失败/拒绝不当成“空列表已读”，不宣称跨设备通知同步。

### Bridge 人类终端

当前授权恢复、默认 Shell 与输入延迟修复跟踪：[MET-207](https://linear.app/metasnowsky/issue/MET-207)。

「新建终端」只出现在加号打开的开始页，不增加固定顶部图标。入口直接使用原生接口返回的电脑默认 Shell，不展示 zsh/bash 选择菜单，也不改变已有标签的 Shell。网页按在线设备实际声明的 `humanTerminalVersion: 1 | 2` 放行，而不是仅比较版本号。未连接、离线或旧 Bridge 通过现有「我的电脑」设置引导，不向旧客户端发送新终端帧。多个电脑或目录可明确选择，恢复的标签固定原设备与授权目录，不静默换机器。

浏览器完整加载固定 DSH `0.2.1-rc.2` 的 `ClientTerminals`、`RemoteStream` 与 `TerminalBody`，包括原生 xterm、FitAddon、输入排序、ACK、屏幕快照和恢复逻辑；Bridge 完整使用同版 `TerminalController` 与 `LocalSubprocessRuntime` 管理真实 PTY。资产版本与 SHA-256 登记于 WebUI 来源账本，同源加载器只集中承担模块注册及用户作用域 Storage 适配，不重写终端模拟器或命令输入表单。

网页通过校验 cookie、Origin 和真实登录会话的 WebSocket 接入既有 Bridge WSS。服务端绑定组织、工作区、本人、会话、设备、授权目录版本及指纹；Bridge 再核对本地授权目录与当前服务端权限，不接受浏览器传入任意本机路径或 owner。顶栏一行显示设备、授权初始目录与连接状态，当前 shell 位置由终端提示符展示。授权目录只选择初始 cwd，**不构成 OS 文件系统沙箱**：这是本机用户权限下的人类 shell，独立于员工的沙箱和审批执行。

该入口不创建 Agent 或 Run，不调用模型，也不把输入输出自动加入模型历史或交付成果。Tab、Ctrl+C 等按原字节传给原生 PTY；流信用与原生 ACK 保留背压。断线只重建输出/保留连接，不自动重放输入或其他可能产生副作用的命令。Bridge 生命周期内刷新复连同一身份；进程已消失时明确要求新建，不偷偷分配替代 shell。

折叠、切标签、切会话及暂时 WSS 断线仅分离视图，后台 PTY 按原生保留规则继续运行；不是跨 Bridge 重启的进程恢复。显式关闭标签保存原生持久清理意图并结束对应进程范围，失败仍显示可重试状态。确定的撤权、登录失效、授权目录/设备变化和 Bridge 退出会进入原生清理；退出未确认完成时保持 `stopping`，不宣称已停止。权限服务暂不可用或证据 `unknown` 不当作撤权强杀：超过已确认授权期限后停止控制输入、保留 PTY，等待重新核实。原生无人保留回收也不把 busy、stopped 或 unknown 当作可安全回收的 idle。

Bridge `0.6.0-dev.60` 将临时授权查询失败报告为 `terminal/unavailable` 与 `HUMAN_TERMINAL_AUTHORIZATION_UNAVAILABLE` 的组合。网页只将这一准确组合视为可恢复断开：清空旧连接世代、使在途调用失败，然后沿用现有退避重连；新连接通过完整授权后，由原生 `RemoteStream` 恢复原进程的输出。界面显示「正在重新验证终端授权」，不把它解释为电脑未连接。输入和创建、关闭等变更请求不自动重放；关闭失败仍需用户明确重试。真正撤权和其他终止原因继续保持结束状态，不通过重试绕过授权。网页恢复修复兼容已有客户端，不新增接口或依赖。

Bridge `0.6.0-dev.61` 将有效授权租约内的周期复核移出按键及输出的等待路径，避免每次公网复核都增加一次回显往返。仍沿用原有 500 ms 复核间隔与 5 s 有效期，同一目标最多一个在途检查；首次授权、租约到期和显式维护复核继续等待真实结果。撤销结果立即失效并进入原生清理，unknown 和在途请求不能延长有效期。本地设备、目录版本及指纹继续逐次核对。

macOS x64 与 arm64 的 SEA/App 分别携带固定的 `.terminal-runtime` 副资源；构建从锁定依赖闭包生成逐文件大小与 SHA-256 manifest，并把预期 manifest 固定进 SEA。加载及最终打包校验平台、架构、清单与实际字节，不信任可替换的磁盘清单或任意运行时路径；发布不能只替换 Core 而遗漏副资源。这是终端 Host 的独立资源，不是另造员工执行内核。

## MET-186：大文件预览与聊天输入性能

文本读取接口继续按原有不可变文件和租户权限读取；AllRice 在展示层再按最多 200 行、16,000 个字符分窗，格式化 JSON 后也执行同一限制，防止单行 JSON 展开成整份高亮 DOM。上一页/下一页替换当前内容，跨读取页时仅保留页地址并重新读取，下载仍返回完整原文件，复制按钮明确标为「复制本页」。分页错误保留当前内容，可再次点击原方向重试，切换文件时取消旧读取。

草稿由独立 store 持有，只有输入栏订阅文本变化；发送、附件建会话和导航检查同步读取最新草稿，页面仅订阅草稿是否为空。工作台、文档预览和聊天记录以稳定属性和 React memo 隔离其余更新，关闭状态的输入菜单使用稳定回调，避免无意义状态更新累积。输入框在本地布局效果中测量高度，避免一次按键重复强制布局。隐藏或切走文本预览时移除正文节点，保留标签、页码及未保存审查状态，重新打开恢复阅读位置。小文档继续使用原有 DSH 展示组件，不改 DSH 包、核心或文件授权。

浏览器回归覆盖大 JSON（格式化与单行）、字符完整性与超长 Unicode 行、前后翻页、隐藏恢复、中文输入/组合输入与上传菜单；生产 React 模式另验快速输入。真实 Dev 使用隔离账号与合成大文件验证，不需要调用模型或改动反馈租户的数据。

### 先检查官方插件的结果

检查官方 `ui-sidebar` / `ui-workspace` 的 manifest、README、公开导出和插件装配。ui-workspace 的 `client` 发布文件通过 `window.__ModuleLoader__` 注册插件，仅导出 apply / inject；发布包未包含其声明的 src 通配路径对应源码。插件安装需要既定 Loader / Slot 和 Session / Workspace 服务，缺少直接面向员工分组的配置。

随后在独立 Chromium 页面中运行官方**原样 WorkspaceBrowser** 及原生 store，投影一个“财务员工”分组与“财务核对”会话（不是生产员工）。浏览器无 JS 错误，会话正常显示；分组菜单实际出现“重命名 / 删除工作区”，轨态没有员工头像。源码确认 WorkspaceBrowser 对所有非空工作区固定提供这两种管理动作，没有隐藏 / 替换员工头部或定制轨态的公开配置。这次验证是原生视图的适配对照，不声称已将完整 DSH Loader 后端部署进 Allrice。

因此员工树复用官方源码组件；不把员工撤回假扮为删除工作区，不仅取样式后另写全部组件。插件已有的目录新建、fork、pin / archive 等后端动作不以空处理函数开放给用户。必要补充是员工头像和详情、显式员工新建、键盘可达性、作用域隔离的显示偏好，以及不展示尚无接线的菜单。原始来源校验和适配补丁记在 `apps/web/app/dsh-upstream/upstream.json`、`scripts/dsh-ui-patches/`。

### 业务行为

会话始终留在真实 employeeAssignmentId 下；撤回员工的可见历史使用冻结名称展示独立分组。单员工直接新建，多员工选择器由现有 DshDialog 承载；显式选择优先于 URL / 默认员工，失效目标不换人。草稿与附件切换沿用会话请求世代处理，未发送内容有明确提示。偏好按组织、工作区及当前用户隔离。

## PR4：来源校验、同步与退役

`pnpm dsh-ui:verify` 校验当前 22 份原生文件/摘录、补丁、已安装包与固定版本、PDF 资产，并用实际浏览器打包器验证公开导出。CI 在 Worker 分发校验之外执行此命令；两者不能互相代替。加 `--source <官方仓库>` 时会从账本固定 SHA 读取原文，重放补丁并比较结果，原生摘录及其依赖常量发生变化会明确报错。

更新步骤（在独立分支操作）：

1. 先按复用清单检查新官方插件是否已补齐本仓适配缺口，能直接使用时删除对应源码适配。查看官方 changelog、公开导出、依赖/React 支持和版本差异；引擎与 UI 分开升级。
2. 固定目标 tag 的完整 SHA；更新 Web 的官方包、必要 packageExtensions 和上游依赖版本，执行 `pnpm install`。不盲目提升 Worker 图。
3. 执行 `pnpm dsh-ui:sync --source <官方仓库> --commit <完整SHA> --version <精确版本>`。命令先重放全部补丁并核对来源、导出和安装版本，全部通过才写目标文件及账本；补丁冲突或摘录变化须先对照原生接口修正，不能忽略错误。人工改动补丁时同步登记 patchSha256。
4. 执行 `pnpm dsh-ui:verify --source <官方仓库>`、`pnpm dsh:verify`、格式/lint/类型/Web 构建，以及现有工作台/输入归属和租户后台 Chromium 用例。预览相关更新复核既有真实 Office 文件，不能以图标或字节存在代替预览。
5. 用独立 Dev 预览核对现有员工、会话与文件；保留未合并的其他工单部署。确认后按正常发布流程推广。回退应整体恢复该次 Web 提交、锁文件、源码、补丁与账本，再 frozen install/build；无需回滚任务或文件数据。

已用 `46a7f68b0922371ce7144b668b90e377d8e799f4` / `0.1.7-rc.1` 执行 verify → sync → verify 演练，原生目标文件没有产生差异。该演练证明当前固定基线可重建，不保证未来版本的补丁一定无冲突。移除了旧扁平会话列表、会话头像轨、员工冒充账号及重复工作台标题的残留样式；保留业务审查、已有 Markdown 和 Office 服务。
