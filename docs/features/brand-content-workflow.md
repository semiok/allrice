# 品牌内容运营 Workflow（MET194）

在已配发员工下创建私有定制实例，以同一实例的个人文字流程和不可变 Workflow 包组成内容工作方法。共享模板、其他实例和真实公司配发不随安装改变。执行流程 Tab 仍只展示文字流程与可执行 Workflow 两类；业务操作从“内容工作台”进入。

## 执行边界

五个官方模板分别处理选题、成稿、退回修订、发布交接、发布复盘。WorkflowDefinition 及对应 method.md 原文件存于原有 Storage，登记时检查文件、定义、方法版本与摘要，当前指针绑定准确实例及可选场景。运行代码由 AllRice 仓库的领域工具实现，不从企业资料执行任意 JavaScript，也不依赖 TNAlpha 运行环境。

每次点击工作台启动一段已有 EmployeeRun/Workflow DAG，固定包、品牌资料、选题或稿件版本。现有 DSH 执行模型节点，领域工具校验并保存输出。普通聊天不会因为相似名称自动进入业务 Workflow。候选采纳、准确图文审稿和发布回执由真人操作；阶段间不保留一个持续等待的模型进程。

包升级只改变后续新任务。已持久启动的任务沿用原来的准确包；当前身份、配发、实例、来源或绑定失效时仍拒绝继续。安全的幂等步骤可由新 Job 租约接管，原成功步骤与业务回执保持；非幂等未知副作用转人工处理。

## 业务记录与文件

品牌资料按版本保存，选题引用生成时的资料版本及事实编号。候选按品牌、上下文、平台及规范化标题去重；采纳请求带批次修订与准确选题 ID。成稿复用原有正式成果链，文档续版和业务 bundle 在同一事务提交；CAS 或当前授权失败时一起回滚。

人工退回绑定准确 bundle，修订读取完整原稿与反馈，保留旧文档及父版本。每张图片独立记录文件、校验值和来源；改图不重写正文，但需重新确认新的图文组合。支持用户上传的 PNG/JPEG/WebP；已有图片工具的结果只有真实操作回执才能作为生成图片登记。

## 排期与发布

先保存准确已批准图文的发布计划，再显式开启到点提醒。提醒复用现有 AllRice 统一 Automation 与 Native once 调度，固定当前计划和流程包；原生调度未就绪时拒绝登记，不另起 cron 或备用时钟。时钟、持久触发与恢复由统一调度负责，内容流程只校验业务范围并投递提醒。

到点消费者重新检查当前身份、准确计划修订、审批图文、私有原会话与冻结包，然后在同一事务提交一次真实站内提醒消息、唯一 occurrence 回执和计划状态。该确定性消息没有模型 Run，也不消耗模型调用；未知事务提交通过原唯一键与事实回执核对。改期或取消只停止该计划原有的专用提醒。通用调度编辑接口不能改变专用业务绑定。

“提醒已登记”“提醒已送达原会话”和“已有发布回执”是不同事实。页面重读真实消息编号后才提供查看提醒；刷新或重新打开原会话可读取消息。站内提醒不表示向外部平台发帖，发布记录仅保存真人提供的真实链接、发布者和实际时间，不声称已独立验证外部平台。

## 发布反馈与经验

1. 在内容工作台的“反馈与经验”录入真实发布链接、发布时间、采样时间、数据来源和局限。已有本系统稿件应选择其发布回执；外部已发布样本会单独标注，不会伪造本系统的发布记录。指标留空表示未知，`0` 表示确实观测为零。来源说明由录入者提供，保存不代表平台已独立核验链接。
2. 选择相同品牌资料版本、相同平台的样本，点击复盘。代码固定样本版本、区分已知和未知指标，只有分母非零且数据已知时才计算点赞/阅读比。DSH 生成摘要、建议、适用范围与局限；结果必须准确引用本次样本，单次观测不能证明因果或转化收益。
3. 复盘完成后点击“提交为经验候选”，核对来源并填写理由，再人工确认或拒绝。候选复用现有 Memory 和经验审核，关联真实完成的 Run、助手消息及原文摘录。确认不会覆盖正式方法。
4. 下一轮选题、成稿或修订只加载同一组织、工作区、用户、员工实例、品牌、活动和平台下有效的已确认经验。任务固定经验版本与摘要，模型注明实际采用的经验和理由，随选题批次或稿件版本保存，可在工作台查看；加载过但没有采用的经验不算实际引用。
5. 已确认经验可撤回。新任务不再加载，正在恢复的旧任务在下一次模型调用和保存前重新检查。历史模型上下文及会话引用也检查来源有效性，切换品牌或普通聊天不能带入旧品牌私有经验。

反馈快照、复盘与引用记录不可原地修改。相同来源及采样时间的重复提交返回同一记录；相同键下不同数据会报冲突。新的观测使用新的采样时间，旧观测保留供核对。失效来源、并发审稿冲突及失败任务保留原记录，不自动重跑模型或冒充已保存。

反馈专用附件删除或到期后，工作台提示并隐藏相关反馈、复盘、经验及引用理由，其他有效资料仍可使用。单条读取、审批和已固定输入仍拒绝失效来源；品牌资料、稿件、发布回执及完整性检查继续遵循原有严格校验。正常撤回的经验仍显示撤回状态，归档会话中的历史记录仍可只读查看。

## 模板复用、升级与恢复

在同一个员工实例中增加品牌或活动资料即可复用模板，不复制平台代码或常驻 Agent。另一企业只安装通用流程定义与方法，重新录入授权资料，不复制原企业的品牌对象、经验、文件或凭证。跨企业、跨工作区、跨用户及其他私有实例访问均重新校验归属。

企业方法和 Workflow 使用现有流程版本管理：保存新的方法版本、登记匹配该方法的不可变流程包、验证后启用准确修订。文字方法改变而可执行包尚未同步时，界面保留待同步状态。回退选择仍有效的旧包修订并更新员工引用；旧版本、输入快照、稿件和 Run 证据不删除。不要编辑已登记的包字节，也不要把新版本绑定冒充旧 Run 的执行版本。

每次人工操作使用稳定请求 ID；失败或断连后先刷新读回真实业务记录，再重试同一操作。恢复只接管安全的幂等节点，已成功保存的步骤不重复提交。撤回经验、删除来源或停用员工后，恢复会拒绝继续使用已失效输入，需要核对后从有效资料启动新任务。

## 成本与验证

模型用量沿用原 Run 账本。按 Run 区分选题、成稿、一次修订和复盘的实际模型、输入/输出 token、报告费用及耗时；人工采纳、审稿、经验确认和代码校验单独记录。来源未提供的成本保持未知，不以零代替，也不从公开互动量推断收益百分比。本业务不写入旧 Workflow 合成的零费用及成功率评估。

契约和纯测覆盖固定版本、路由、输出事实与内部发布组合；隔离 PostgreSQL 覆盖权限、真实文件父版本、事务回滚、包升级、步骤崩溃接管、提醒幂等、反馈快照及经验撤回。组件浏览器检查覆盖不同账号/实例、草稿保留、错误后同键重试、未知指标和实际状态。上线验收另外记录实际 Dev 版本、普通账号真实模型阶段、网页文件读取与下载、历史与隔离证据。公开样本可用于功能验收；公司真实业务数据和正式审稿决定由业务方后续录入。
