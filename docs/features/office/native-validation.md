## 实测发现并补充的接入缺口

- 原生文档操作不经过原有固定编辑枚举。Allrice 使用现有 gVisor 执行生命周期，补齐文件输入、原生 Python 环境和产物接回；上游检查脚本在沙箱内实际执行。
- 原生 openpyxl 不计算公式；继续复用已有 LibreOffice 求值和缓存回填，保留公式表达式、条件格式与图表。
- 续改时发现既有渲染容器积累 114 个僵尸进程、触及 128 的进程上限，导致 LibreOffice 加载失败。去除打印 DPI 的对照没有解决问题；原因是子进程回收，而非文档数据。已在两个 Compose 配置启用 Docker 自带 `init`，Dev 容器以同一镜像加 `--init` 重建。修复后原文件不变即可预览，六次不命中缓存的转换均为两页、公式结果正确，残留僵尸进程为零。没有增加自有进程回收器或改写文档内容。
