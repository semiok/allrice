## 验收推动补齐的接入

- 上传 API 和浏览器选择器接受三种原生 Office 类型，兼容浏览器仅提供通用 MIME 的情况。
- 文件列表接入同一个 DSH 原生循环；模型实际接口包含 `includeStructure`、结构化 `office` 和原文件编辑，不再只支持旧 `content`。
- Word 标题层级同时接受数字与字符串；原生工具复用共享契约，把错误字段返回给模型纠正。固定 DSH 子进程测试验证嵌套参数往返与错误反馈。
- 三个文件并发生成时，排队和转换共用一个 40 秒期限；不再因两秒队列等待把正常批次中的后续文档报为不可检查。真实三格式并发渲染已纳入 Compose CI。
- 新开发环境在启动原生 DSH 子进程前构建共享契约；Worker 崩溃恢复烟测仅重启被测 Worker，避免重启渲染依赖耗尽原有任务时限。

前两轮发现的漏接和 Word 参数失败保留在会话中；最终成功 Run 是修复后的独立验收，不能将失败轮次算作成功。

## 运行与交付边界

渲染使用固定的 LibreOffice/UNO/Poppler 容器和 Noto CJK 字体；最终镜像为 `sha256:099caaa43f836ff6bcd2690ddaaafe6671b8dc2c44a6cad1fdeac16fb4109b8e`。转换子进程禁止 IP socket、禁止宏与外部文档更新，采用临时工作目录。没有新增数据库迁移、文件库、DSH Shell 执行权限或租户端安装要求。

样本验收不代表任意 Office 文件均能无损编辑。当前保留式编辑支持正文/表格/幻灯片文字与指定单元格；公式检查支持普通和共享公式，数组/溢出公式、外链、宏不在检查范围。预览最多展示前八页，LibreOffice 与 Microsoft Office 排版可能不同；数值求值不替代业务核对。旧 PDF/文本读取、冻结员工版本及业务对账链路由回归测试保留。
