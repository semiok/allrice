# 员工分层内容与工作场景

MET179 PR2 提供内容存储、校验、启用及读取 API。工作场景是执行要求、文字流程和已有来源的索引，不是权限层级或另一套运行器。个人内容绑定稳定员工实例；公司、部门内容绑定已有租户员工身份。平台来源仍是实例当前配发版本的不可变平台发布，展示其行为要求和安全边界；完整系统提示词继续由原运行包管理。

## 修改与读取

`POST /api/v1/employee-content` 支持 `save_draft`、`validate`、`activate`，共用 `EmployeeContentMutationSchema`。每次带 `setId`、`workspaceId`、归属、目标、`requestId` 和 `expectedRevision`；校验和启用另带准确的候选版本 ID、摘要。个人／部门／公司维护权限在事务内重新读取，不能借此配发员工、授权工具或修改模型。

草稿可以原子保存 `textEdits` 和索引。`draft_text` 引用必须对应本次编辑，服务端将其转成带摘要的不可变来源。保存草稿不会改变生效内容。校验成功后，启用仍会检查当前身份、来源状态、版本和继承依赖；任一条件变化则拒绝，原来的生效指针保持不变。相同请求返回原回执；同一标识不同请求、并发旧版本返回冲突。

`GET /api/v1/employee-content/:id?workspaceId=...` 返回草稿或生效内容及重新鉴权的来源。普通共享读者只能看到生效版本；当前维护人可查看候选。`GET /api/v1/employee-instances/:id/content?workspaceId=...` 返回平台、公司、当前部门、个人的有效组合。当前用户失去身份、配发或来源权限后，历史请求不能恢复这些权限；失效来源不返回正文。

## 来源与继承

- 执行要求、文字流程复用 `allrice_company_assets` 的独立 kind 和不可变 revisions。旧公司规则／范本接口明确排除这两类内容，发布个人文本不会使它变成公司范本或全局规则。
- Knowledge、Workflow 只引用已有发布及已启用的员工 binding，不新建能力或授予读取权限。共享 Knowledge 需匹配的公司／工作区 ACL；仅个人或员工 ACL 不能扩大成公司共享。本切片读取的是来源描述，文件和连接器的实际检索继续走原执行权限；文件级、连接器级引用暂不提升为共享层，MET180 再接分层资料。
- 经验引用只接受当前已确认、未失效的已有记忆版本，遵守原私有／工作区边界；本切片不将经验提升为公司／部门资料，不增加自动沉淀。
- 上层引用自动保留；相同来源与版本去重，同一来源的不同版本冲突，同一场景 ID 的不同名称／适用条件冲突。主动声明的未解决冲突阻止启用。任意自然语言的语义一致性标记为 `not_proven`，不能把结构校验当成业务正确性验收。

新索引使用 `allrice_employee_content_sets/revisions/requests`，不复制原始文件。事务原子更新文本发布、候选、生效指针、审计和原回执。平台发布／撤权沿用现有 assignment/deployment 锁，不另取反序 employee 行锁；遗留租户目标的首次平台配发竞态返回冲突重试。

本切片不改变正在运行的任务或历史快照。实际 DSH 装配在 MET179 PR3，聊天定制在 MET181，共用前台／后台详情在 MET182，自动经验沉淀在 MET183。

## 核心回归

`employee-content.integration.test.ts` 使用隔离 PostgreSQL 和真实 HTTP handler：多场景保存与启用、来源权限、原回执重放、CAS 并发、失效保留旧版、上下层冲突、共享草稿隐藏、旧接口拒绝、发布与撤权锁序、登录与配发撤销。`employee-content.test.ts` 验证输入和内容预算。CI 纳入现有租户数据库检查步骤；无新测试服务或模型任务。

## 工作场景的运行时采用（MET179 PR3b2）

两类员工共用同一场景目录。Run 冻结已发布的名称、适用条件和精确来源引用；共同要求先加载，场景正文仅在原生 `skill` 工具选中后读取。用户明确选择优先，匹配不明确时使用既有问询工具，一般任务允许不选择场景。重复的公司/部门/个人引用按精确版本去重。

读取会在当前任务身份、执行租期和资料权限检查后提交 `content_scene_state.reads`，再返回正文。原生斜杠探查、丢失响应只保留读取依赖；匹配的成功工具结果才写单场景 `adopted`，事件 `allrice/scene-adopted` 表示原生加载成功，并不等于业务任务已经正确交付。工作过程中的对应工具卡显示场景名称与现有成功/失败状态。

多个场景并发采用冲突会停止继续派发。撤权或显式纠错通过既有 content generation 阻止后续根任务/助手派发、压缩、恢复和旧答案导入。恢复从公开 Session 自有原始事件补核对采用回执，不把 fork 继承记录冒充子助手新采用。场景任务按 Run 隔离原生线程；普通可见会话历史保持原有授权检查，无场景旧任务的配置摘要不变。

Knowledge/Workflow 引用仍是已有资源目录，读取文件和执行流程沿用原工具与权限。新建、修改及启用场景的聊天交互、完整详情面板分别在后续 MET181/182 交付。

## 历史恢复

维护者通过 `GET /api/v1/employee-content/:id/history?beforeRevision=` 查看同一内容集合的历史索引及纠正状态，响应不包含来源正文。正文仍走现有详情接口的当前权限检查。

现有内容写入入口接受 `operation: restore_draft` 和 `sourceRevisionId`，其余归属、目标、请求 ID、预期修订和变更说明字段与保存草稿一致。恢复生成新候选版本并保存 `restoredFromRevisionId`；必须再次校验、启用，才影响之后的新任务。外部集合版本、已显式纠正作废的旧发布不能恢复；来源撤回或权限变化不能通过恢复绕过。旧 Run、旧发布、旧文件不被重写。

## 公司共同要求的完整测试（MET181 PR4d4b）

公司共同要求候选通过既有聊天保存、原生测试、Ask User 确认及内容事务启用。`sharedTarget` 保持公司发布对象；新增可选 `executionView` 只用于公司共同要求测试，明确公司基础或一个准确部门。旧个人、公司单场景和部门测试不增加默认字段，既有冻结摘要保持不变。

服务端在既有组织内容事务锁下枚举当前启用的部门共享层，用同一内容装配器生成公司基础及各部门组合。个人层不进入共享测试。覆盖键是 `executionView + sceneId`，摘要同时绑定候选、来源、模型版本、范围及全部视图；同名场景的证明不能跨部门替代。共享组合和完整场景覆盖分别最多 32 项，空视图仍参与摘要，来源无效、样例不支持或超限时整个计划无效。

排队、执行、结果读取、重试和启用都核对当前依赖。启用事务复用本事务已锁定的完整视图，逐项核对证明和模型，避免为每项证明重新装配全部部门；不跨请求缓存。新增部门共享层或修改已有层后，原证明与确认不能继续使用。

`workspace.employee.method.inspect(view=candidate)` 返回最多 32 条测试索引及 `nextBeforeTestId`。用 `beforeTestId` 查询后续页；游标必须属于当前用户、实例、集合及同一候选，SQL 原生时间戳和 ID 排序避免亚毫秒丢项。存储状态只是发现入口，启用以重新校验的实际断言为准。公司共同要求确认题在 `detail` 中保留完整视图与场景，沿用既有原生问答及准确内容校验。

## 员工详情与个人设置（MET182 / MET201）

`GET /api/v1/employee-instances/:id/content?workspaceId=...` 通过 `EmployeeDetailsSchema` 返回 `profile` 和原有 `content`，在同一只读 repeatable-read 事务中重新核对当前用户、实例、配发、人设及有效内容。人设使用该实例当前配发版本的 manifest 和个人覆盖，不拼接可能过期的工作区列表；通用实例同样显示已保存的个人表达偏好。响应禁止缓存，不返回技能、模型或凭证配置。

前台入口固定所点实例，不在目标失效后回退到当前会话的其他员工。通用与定制实例共用紧凑详情：名字、使命、工作方式和表达偏好归为低调的人设区，不重复角色、简介及人设来源版本；工作场景与四维内容另成一区。场景直接列出，选中项与右侧内容相连；通用内容始终可选，切换场景保留当前维度。执行要求、执行流程、参考资料和经验按完整固定引用匹配来源；草稿层和未选场景不进入当前展示。历史配发的行为准则和安全边界仍显示，但不冒称平台来源。

来源标记继续采用服务端每条来源的 `ownership` 和 `canMaintain`，以紧邻标题的文字标明个人或继承归属，不依赖颜色表达权限。资料只打开已引用的准确 revision，通过原预览／下载路由重新鉴权；首次读取、刷新或翻页失败清除旧预览。经验列出实际已引用的条目及现有经验面板，不把候选视为已采用经验。

本人可维护的定制实例提供一个「编辑」入口，复用创建员工的同一表单，维护名字、后台同款十色头像、使命、工作方式和表达偏好。创建默认科技蓝和通用人设；编辑先通过原实例 GET 读取 raw profile，保留未展示的描述、角色、头像类型等字段，再走原 PATCH 和 `expectedRevision`。同一提交保留稳定 requestId；取消不保存，失败保留输入，冲突需重新读取，撤权后清除旧私有内容。更新成功才刷新详情及工作区显示，不修改平台模板、共享发布、旧 Run 或冻结快照。通用实例及组织共享视图不获得定制编辑入口。

定制实例的「AI 新增」和有维护权限的个人条目「AI 调整」仅准备准确员工的主聊天草稿，不自动发送、创建 Run 或直接改内容。复用既有草稿组合、DSH 原生 Broker 与内容事务；新请求放在草稿开头以满足已有明确修改意图校验，原草稿文字、附件和引用仍保留。提示词要求保留公司、部门、平台及未提及的个人内容；经验调整沿用原有验证和采用语义。共享、撤权和不可用来源不显示此类操作。

MET201 只有前端与文档变更，无迁移、模型配置、运行包、Bridge 或 DSH 核心变动。定向回归与隔离普通账号实际 Dev 验收覆盖创建/编辑真实持久化、刷新重登、权限拒绝、场景与四维切换及仅准备草稿。

回归覆盖同名不同实例、通用表达偏好、模板及私有人设来源、当前与候选分离、撤配／跨账号拒绝、迟到响应、版本预览及翻页失权、1440px/390px 页面与无维护写请求。组织管理与后台目录复用在 MET182 PR2/PR3 继续接入。

### 执行流程分类展示（MET194 前置）

共用只读详情在「执行流程」中分别展示「文字流程」与「可执行 Workflow」：前者说明 AI 参考的工作方法，后者说明由程序执行的固定业务流程。两组均保留用途说明、实际内容或各自空状态；条目显示名称、正文、维护权限及真实已有的文件版本。正文直接展示，页面不提供步骤查看、运行示例或启用操作。

分类沿用已有 `procedure`/`workflow` 来源类型、精确引用与当前场景筛选；无效来源仍不显示原标题和正文。此变更只调整前台、组织与后台复用组件的呈现，不创建 Workflow、不改变员工绑定、执行权限或数据接口。MET194 的原生内容运营 Workflow 及其员工配置另按该票实施。

## 组织管理只读目录（MET182 PR2）

组织管理保留原账号、配发、用量与应用页面，在横向导航增加「AI 员工与工作沉淀」。按部门／未分部门及真人员工查询实际实例，当前可用通用／定制、停用、归档和配发待建立实例分别计数；分页统计覆盖整个筛选范围。读取不会补建实例或恢复配发。人员调部门后按当前归属重新读取共享层。

平台管理员保持真实登录身份，通过独立的 `OrganizationSharedReader` 获取指定公司、当前人员部门的共享只读投影。它不生成租户成员身份，不冒用被查看员工，不改变普通内容权限。公司／部门只读来源仍校验精确版本、digest、发布状态、引用范围和资料可用性；所有维护标记为只读。原生内容合并器和员工详情组件同时供前后台使用。

组织详情明确展示「已配发基础人设与公司／部门共享内容」。实际配发的不可变版本是基础人设来源，不读取他人的个人名称、简介、人设、表达偏好、场景、引用、经验、候选和历史正文。资料与场景数量仅来自当前共享发布；资料数量表示引用数，不等于每份资料均可读取。自动经验沉淀在 MET183 之前明确未启用。

后台预览、翻页、源文本和下载使用实例范围内的独立 GET 入口，每次重新检查管理员会话、目标公司／人员／实例状态和仍然生效的共享资料版本；文件读取完成后再次核验。私人、未引用和已撤回的版本不因知道 revision ID 而可读。普通租户预览与维护接口保持原权限。无新数据库表、调教入口或发布机制。

## AI 员工后台目录与历史（MET182 PR3）

AI 员工管理按“模板与发布 / 员工实例 / 模板历史”查看；模板编辑、测试和发布继续使用原流程。切换目录前检查忙碌状态和未保存草稿。小白从已配发员工创建定制实例，与通用实例共用来源和配发结构，不按名称推断模板类型。

实例视图复用组织管理的目录与只读详情。`kind=general|custom` 和 `sourceTemplate=<模板 UUID>|legacy` 在数据库中共同作用于真人列表、统计、实例分页和待建立配发；`legacy` 表示没有平台发布来源的历史租户版本，返回来源类型仍为 `tenant_version`。筛选不授予读取个人内容的权限。

平台管理员通过 `GET /api/v1/admin/platform-employees/history-directory` 发现包含归档模板的历史目录；`/:employeeId/revisions?before=` 分页读取元数据，`/:employeeId/revisions/:revisionId` 读取准确的已保存定义与运行包。所有读取重新验证管理员会话，使用只读事务，不改变草稿、配发或发布状态，不用当前技能目录补写历史快照。未生成发布包的版本如实标明。

模板 Workflow 指向实例中真实生效的执行流程；Knowledge 保留平台公共资料库，并提供实际实例引用的查看入口。平台编译器对不支持的 Workflow/Knowledge 模板绑定仍拒绝。经验沉淀展示当前未启用状态和个人可见边界，共享详情只返回合法共享内容，不提供虚构调度、开关或私有经验统计。自动整理由 MET183 实施。

回归沿用组织目录数据库和管理后台浏览器检查：组合筛选、旧来源、归档状态、历史分页、冻结技能、撤销管理员权限、共享内容隔离、桌面/手机和草稿切换保护。
