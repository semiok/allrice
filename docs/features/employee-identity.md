# 员工运行身份

员工名称取自「基础」中的名称，角色、使命和行为取自「人设」。发布时将名称明确写入 IDENTITY.md，与 SOUL.md、工作规则一起冻结为运行包；平台通用规则不应重复指定某一员工的姓名。

历史 Rice 模板曾把 `You are Rice, the default AI employee in AllRice.` 写入平台规则，复制为 Office 等员工后造成身份冲突。新建或保存草稿会把这句已知的开头替换为使用 IDENTITY.md 中身份的通用说明，完整保留后续规则和其他自定义提示词。读取、回放与校验已发布版本不做此转换，也不修改旧运行快照。

已发布员工需要保存、发布新版本后生效。现有会话在下一轮采用有效分配中的新版本；历史回复保留原文。Office 的专门角色与使命属于员工配置，不能仅根据员工名猜测或在运行时硬编码。

## 稳定身份与实例生命周期

模板一旦向任何公司配发，员工 Key 就固定。名称、简介、人设可保存为新版本；发布仍更新原配发和原实例，保留公司/部门内容关联、个人配置、创建来源以及历史 Run 的冻结版本。草稿保存和实际物化都检查 Key，旧草稿不能绕过限制。

实例归档通过 `POST /api/v1/employee-instances/:id/lifecycle`，传 `workspaceId`、`expectedRevision`、`requestId` 和 `operation: archive`。恢复使用同一入口及 `operation: restore`、`sourceRevision`。恢复生成新的修订并记录来源，不修改旧修订；当前配发必须有效。重复请求返回原回执，冲突修订拒绝写入。该入口不改变实例归属、访问权限或共享模板。

归档后不再出现在可工作列表，已有会话与成果保持只读可查看。`GET /api/v1/employee-instances?view=history` 提供本人历史实例（含撤回配发），使用 `beforeId` 分页；单个实例 GET 和 `/:id/history?beforeRevision=` 可读取本人历史。所有历史入口复核当前公司成员身份，不授予执行或维护权限。详情页面的展示整合在 MET182，聊天调整入口在 MET181。

归档、公司撤回配发、移除个人配发和平台停用都调用已有任务取消事务，写入取消请求及已有子代理树截止记录。恢复或重新配发只允许新任务，不清除旧任务取消记录；模板正常升级和个人普通修改不取消正在执行的旧任务。
