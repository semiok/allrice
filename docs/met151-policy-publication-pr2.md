# MET-151 PR-2：能力目录、执行策略与 Rice 发布

本阶段叠加在 PR-1（PR #78，`9cc7a0a`）上，独立提交审查。只完成后台配置与发布路径，不包含环境授权、额度管理和真实 Snow 执行验收。没有部署 Dev/Prod，也没有改变 Snow 角色、额度、设备授权或平台执行开关。

## 管理路径

1. 「租户管理」选择租户和具体工作区，再打开「执行策略」。全组织范围不允许编辑工作区策略。
2. 显示当前策略版本、执行/仅规划模式、每个动作的设置与实际策略判定。未配置默认拒绝；命令、Changeset、MCP 和浏览器写动作即使选 Allow，仍须原有精确审批。
3. 核对前后值，填写原因后保存。数据库版本比较和事务审计阻止过期页面覆盖别人刚改的策略；平台管理员不需要也不会自动获得目标租户 membership。
4. 「配置能力与 Rice 发布」携带工作区范围进入现有 AI 员工页面。工具选项和编译检查从 `allRiceToolManifest` 派生；标签不是另一套注册表。
5. 「技能」可查看已有 Skill 的来源、版本、内容、审核状态和依赖。内容按文本呈现，不执行、不创建授权。
6. 保存/编译草稿；使用原调试流程取得当前确切运行包的成功试用记录。「发布租户」显式勾选目标，执行预检，核对版本差异和运行条件，再确认发布。

## 必须区分的事实

- 工具已实现、平台发布开关、租户动作策略、员工版本、环境就绪和实际使用者授权不是同一件事。这里只管理前述目录/策略/员工版本，不以配置代替设备确认。
- `browser.run` 是既有云端网页读取；`browser.workspace` 与 `local.browser.workspace` 是不同执行路径。助手、进程状态/停止、项目预览和 MCP 使用既有 canonical 名称，不增加并行工具体系。
- Changeset：`workspace.export.create` 生成工件提案 → 网页精确批准 → 内部 `local.fs.changeset` 执行；内部动作不作为新的模型工具勾选。
- 后台将 `autonomous` 显示为不可用；编译继续拒绝它，并检查禁止能力、Skill 依赖、Bridge 禁用/只读与本地工具的冲突。
- 预检中的“平台未开放/策略禁止/执行目标未登记/还需环境与使用者授权”是可见的运行限制。按 canonical 工具检查所需 Bridge、Cloud Sandbox、Cloud MCP 目标的登记状态，登记不等于实时在线或执行许可。允许先发布静态配置，不会隐式开启执行；完整环境缺项矩阵和配置入口留在 PR-3/4。
- 发布更新所选工作区的员工分配，后续新 Run 读取新版本；运行中的 Run 保持冻结快照，会话已冻结的模型路由也不会被改写。
- 回滚影响该员工当前有效分配的全部工作区，不仅是页面上勾选的目标；必须确认范围与当前发布版本。不复活已经停用的历史分配，不覆盖历史版本或 Run。

## 接口与一致性

| 路径                                                          | 功能                                                                   |
| ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `GET/PUT /api/v1/admin/tenants/:organizationId/policy`        | 指定工作区策略读取、版本化保存、真实操作者与 before/after 审计         |
| `GET /api/v1/admin/platform-employees`                        | 现有员工目录附 canonical 工具元数据和平台开关状态                      |
| `GET /api/v1/admin/platform-skills/:skillId`                  | 已有 Skill 只读检查                                                    |
| `PUT /api/v1/admin/platform-employees/:employeeId`            | 保存并编译；必须提交所见草稿版本                                       |
| `POST /api/v1/admin/platform-employees/:employeeId/review`    | 只读一致性快照：版本差异、目标策略、运行条件、成功试用与 Provider 健康 |
| `POST /api/v1/admin/platform-employees/:employeeId/publish`   | 当前草稿、已发布指针、确切运行包 checksum、目标策略版本全部匹配后发布  |
| `POST /api/v1/admin/platform-employees/:employeeId/lifecycle` | 回滚提交预期发布版本与完整有效分配范围；审计随事务提交                 |

新的写入口使用平台管理员校验、同源校验及有大小上限的 JSON。策略写入和发布以同一工作区策略锁协调初次插入与后续版本检查。发布仍保留原有精确运行包试用、有效时间、Provider 健康及事务内复核门禁。

仅策略改变时重新预检即可，不要求重复模型试用；草稿或资源包改变才要求重新核对/试用。旧后台页面缺少版本字段会被拒绝，刷新页面加载新客户端后继续，不能靠自动重试重放发布。

## 验证层次

- `employee-administration.integration.test.ts`：5 项隔离 PostgreSQL 场景，覆盖 canonical 工具编译、禁止组合、策略并发与审计、越权/撤销、Skill 只读、发布前置条件、过期策略/草稿/发布指针、回滚范围及冻结历史。
- `tenant-administration.browser.test.ts`：在 PR-1 的 3 项基础上新增 2 项，真实 React → HTTP → 隔离 PostgreSQL。验证策略保存/刷新/冲突/跨域拒绝，以及工具/Skill 检查 → 预检 → 并发变化拒绝 → 重新确认 → 发布。
- 原 Worker manifest 契约测试增加后台目录一致性断言；错误响应测试增加策略变化指引。
- 原策略、受控 Bridge、确切 Skill 包发布/回滚测试继续回归。需要真实 VM/设备的跳过项不计为通过。
- GitHub CI 的租户管理任务显式运行新增数据库和浏览器测试；其他既有 CI 门禁继续保留。

上述模型试用回执由隔离测试夹具生成，**没有消费真实模型额度，不能代替 Snow member 或物理 Bridge 执行验收**。数据库夹具使用随机临时 schema，测试结束清理；浏览器连接的只是本机随机端口测试服务。
