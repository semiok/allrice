# MET166 PR3b：已保存项目的本地执行

`local_process_execute` 现在可以接受 `workspace.project` 返回的确切项目版本引用。平台校验私有源码对象、原始锁文件和当前 Worker 租约，再把完整源码交给 Bridge。沿用 DSH 原生参数校验、ToolBroker、执行账本，以及 PR8 已验证的 pnpm/uv 安装器和受管 VM。

模型只提供项目引用与有限的执行参数；源码字节、设备、架构、镜像、缓存身份及 Worker 来源由服务端填充。`project` 与宿主文件列表 `files` 必须二选一。保存的源码在私有 VM 工作副本中运行，不需要授权宿主文件夹，也不读取宿主源码或修改原项目。宿主文件、MCP 和其他目录操作仍检查各自的目录授权。

设备完成源码恢复、安装与物理取消探测后才报告该能力。平台复用现有受管运行授权，检查当前普通员工、发布版本、冻结工具、源码读取权限和确切 Worker attempt/token；创建、幂等重试、派发及运行心跳都复核。锁等待后再次检查租约时间，撤销后可以对账已发生的停止事实，不能继续执行。

回执必须匹配项目版本、恢复后的源码校验值、锁文件、缓存身份、架构、运行镜像和无宿主改动的结果。取消发生在恢复校验前时允许明确的空恢复证明，不得据此报告运行成功。公开工作记录只返回项目引用，不返回私有源码和内部 Worker 来源。

依赖缓存按组织、工作区、员工、项目、Linux 架构、固定镜像、安装器版本及锁文件隔离。宿主下载缓存最多 128 MB / 256 个文件；VM 项目缓存最多 512 MB / 8 个卷，每卷最多 128 MB。保留正在使用的缓存，清理闲置缓存；实际占用不足以容纳新任务时拒绝新准备。容器运行中及短任务结束时都检查缓存上限。

验证包括真实隔离 PostgreSQL 的普通账号授权、目录与受管授权隔离、Worker 重试和锁等待、撤销及回执对账，以及固定 DSH 子进程参数往返。Intel 和 M5 ARM 原生 VM 分别验证 pnpm/uv 冷准备、缓存复用、离线执行、同锁文件换源码、物理取消和短任务缓存超限。公开包启动和 Dev 普通账号完整链路的实际结果保存在交付记录，不能由本地测试代替。

本期支持有限 Node/Python 项目命令。云端执行属于 PR3c；编辑、构建、测试、修复及正式交付属于 PR4；持续预览属于 PR5。Windows Bridge 暂缓。
