# Codex 订阅历史未知用量：管理员预算例外

适用范围：普通订阅任务已失败或取消，拥有调用前冻结的订阅证明，但最终 Token 回执缺失。不是供应商周额度恢复，也不适用于 API 或助手根任务、子任务、悬挂预算。

1. 先核对原生回执、任务和执行进程；有真实完整回执时优先按账本核对流程处理。不得把未知写成 0 或伪造完整回执。
2. 仍无法核实且管理员明确接受风险时，在 Runtime Console 治理页选择具体租户和 Run，填写额外预留预算及依据，并勾选确认。未确认不得放行。
3. 同源 POST `/api/v1/admin/model-governance/usage-review` 仅允许真实平台管理员。租户由所选 RouteDecision 在服务端解析，不接受客户端伪造组织或完成状态。
4. 不可变审批保存原账本快照、批准人、理由、请求 ID 与预留数；原账本保持 `usage_complete=false`。预留按原账目所在月份计入组织内部月度 Token 预算，是额外预算占用，**不是实际用量、费用或用量上界**，不改写个人、供应商真实计数。
5. 只有所有未知项均得到有效的逐项批准，才可通过订阅组织预算准入；新未知项、回执变化、原任务重开都重新阻断。其他配额、供应商开关及助手悬挂检查照常生效。相同审批重放不重复预留，变更参数返回冲突。
6. 审批只恢复后续新请求，不自动重跑旧任务。新建独立测试会话完成一次真实订阅聊天，确认结果和完整回执，再请用户继续测试。

迁移 `0099_subscription_usage_budget_reviews.sql` 只增加审批表和不可变触发器；旧版本回滚仍会因原始未知用量而保守阻断，不删除审批或篡改旧账。Dev 与 Prod 分开部署，不以 Dev 验收代替 Prod 授权。
